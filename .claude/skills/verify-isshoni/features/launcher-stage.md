# 런처와 실행 화면

앱을 켜면 런처 창이 뜨고 이름, 레벨, 캐릭터 슬롯, 방 상태를 보여 준다. 런처에서 시작하기를 누르면 첫 창이 실행 화면으로 바뀌어 내 캐릭터와 상태칩이 보인다. 실행 화면 상태칩의 `메뉴 ▼`로 기능 창을 열고 맨 아래 « 런처로를 눌러 런처로 돌아간다. 이름표나 캐릭터 몸을 끌면 캐릭터가 화면 안 어디로든 옮겨 가고 그 자리를 기억한다. 누가 방에 들어오거나 나가도 내 캐릭터는 제자리에 있다. 기능 창은 작업 영역보다 크면 줄여서 열린다. 알림은 사용자가 방금 누른 창 위쪽에 뜨고 그런 창이 없으면 실행 화면에 뜬다. 서버 연결이 끊긴 지 5초가 지나면 상태칩 줄에 `연결 끊김` 칩이, 열린 창마다 위쪽에 띠가 생기고 다시 연결되면 `다시 연결됐어요.`가 뜬다. 이름표는 바쁨과 자리비움을 점 모양과 글로도 보여 준다. 기능 창 하나가 렌더 오류로 깨져도 실행 화면과 다른 창은 그대로이고 깨진 창에는 닫기 안내가 뜬다.

## Sub-features

- `launcher-show`는 런처가 이름, 캐릭터 슬롯, 혼자 모드 안내를 보여 주는 것이다. 맨 아래 `캐릭터 만들기`, `내 정보`, `설정` 버튼까지 잘리지 않고 보인다.
- `launcher-me`는 런처 이름 옆에 레벨이 보이고 아래 줄의 `내 정보` 버튼이 내 정보 화면을 여는 것이다 (SCR-03). 친구 코드와 복사 버튼은 [내 정보](./me.md)에 있다.
- `launcher-start`는 시작하기로 실행 화면을 여는 것이다.
- `stage-menu`는 `메뉴 ▼`가 기능 창 항목을 묶음별로 구분선을 넣어 보여 주고 방이 있어야 쓰는 항목은 혼자 모드에서 흐리게 보이는 것이다.
- `stage-back`은 « 런처로를 눌러 런처로 돌아가는 것이다 (CHR-04).
- `stage-fit`은 캐릭터가 있는 모니터의 작업 영역이 좁거나 낮으면 좌석이 들어갈 만큼 작아지고 `메뉴 ▼` 메뉴와 다른 사용자 메뉴가 작업 영역 높이 안에서 스크롤하는 것이다 (NFR-08). 낮은 작업 영역에서도 `메뉴 ▼` 메뉴가 다섯 줄 넘게 보이도록 좌석을 줄이고 스크롤 막대가 늘 보인다.
- `panel-fit`은 기능 창과 런처가 작업 영역보다 크면 작업 영역에 맞춰 줄어 열리고 확정 단추(촬영 시작, 저장, 보내기)가 창 안에 보이는 것이다. 기억한 자리가 없는 창은 캐릭터가 있는 모니터 가운데에 뜬다.
- `stage-drag`는 이름표나 상태칩 줄의 빈 곳을 6px 넘게 끌면 실행 화면이 고른 모니터의 작업 영역 안에서 따라 움직이고 짧게 누르면 메뉴가 열리는 것이다. 자리는 모니터마다 이 PC에 남고(고른 모니터는 다시 꽂아 id가 바뀌어도 고를 때의 id로 찾는다) 설정 화면 탭의 `위치 초기화`와 트레이 메뉴 `위치 초기화`가 아래 가운데로 되돌린다.
- `stage-body-drag`는 캐릭터 몸을 12px 넘게 끌면 이름표처럼 실행 화면이 옮겨지고 쓰다듬기 반응은 뜨지 않는 것이다. 세로로 더 많이 끌거나 0.2초 넘게 한쪽으로 끌면 끌기이고 그 전에 좌우로 빠르게 흔들면 흔들기다.
- `stage-steady`는 방에 누가 들어오거나 나가 좌석 수가 바뀌어도 실행 화면 왼쪽 끝이 그대로라 맨 왼쪽의 내 캐릭터가 옆으로 뛰지 않는 것이다. 메뉴를 열고 닫아도 그 자리다.
- `stage-offline`은 서버 연결이 끊긴 지 5초가 지나면 상태칩 줄 `메뉴 ▼` 옆에 `연결 끊김` 칩이 생기고 열린 창마다 위쪽에 `연결이 끊겼어요. 다시 연결하는 중이에요.` 띠가 생기며 다시 연결되면 둘 다 사라지고 `다시 연결됐어요.`가 한 번 뜨는 것이다. 끊긴 동안 쓰다듬기 같은 방 신호는 보내지 않고 같은 방 친구 좌석은 사라지지 않는다.
- `plate-state`는 다른 사람 이름표가 바쁨이면 가로 막대가 든 빨간 점과 `바쁨`, 자리비움이면 속이 빈 회색 고리와 `자리비움`을 이름 뒤에 보여 주는 것이다. 이름표의 접근 가능한 이름 끝에도 `, 바쁨`처럼 붙는다.
- `panel-guard`는 기능 창 하나가 렌더 오류로 깨지면 그 창에만 `이 창에 문제가 생겼어요. 닫고 다시 열어 주세요.`와 `닫기`가 보이고 실행 화면과 다른 창은 그대로인 것이다. 실행 화면이 깨지면 오류를 보고하고 스테이지를 다시 읽는다.
- `toast-where`는 알림이 방금 누르거나 키를 친 창(기능 창이나 런처) 위쪽에 뜨고 그 창이 바로 닫히면 런처 화면에서는 런처에 뜨고 실행 화면에서는 실행 화면에 뜨는 것이다. 한 번에 두 개까지 보인다.

## How to get to it (user POV)

- 앱을 켜면 런처가 뜬다.
- 런처의 `시작하기` 버튼을 누른다.
- 실행 화면 상태칩 줄의 `메뉴 ▼` 버튼을 누른다. 상태칩 줄에 항상 있는 것은 상태, 방 코드(방 안에서), `메뉴 ▼` 셋이고 💬와 🔔과 ✉는 알릴 것이 있을 때만, ♫는 재생 중일 때만 보인다. `메뉴 ▼`는 늘 첫째 줄 오른쪽 끝에 있고 상태칩이 바로 그 왼쪽에 있다. 연결이 끊긴 동안에는 `연결 끊김`이 그 자리에 오고 상태칩은 다음 칸으로 간다.
- 인터넷이 끊기면 5초 뒤 `연결 끊김` 칩이 생긴다. 누르면 무엇이 되는지 알림으로 알려 준다.
- `메뉴 ▼` 메뉴 맨 아래 `« 런처로`를 누른다.
- 내 이름표, 상태칩 사이 빈 곳, 캐릭터 몸을 누른 채로 끈다.

## Driving it with drive.ts

Preconditions:

- 새 `verify()` 세션이다.

- **런처 확인.** 런처 창은 이미 열려 있다. `await s.shot(s.launcher, 'launcher-show')`를 실행한다. ARIA에 `text: 이름 없음 Lv.1`, `button "시작하기"`, `text: 빈 캐릭터 (1/3)`, `text: 지금은 혼자 모드예요.`가 있다. 화면 맨 아래 세 버튼이 온전히 보이고 스크롤바가 없다.
- **내 정보.** 런처 아래 줄의 `button "내 정보"`를 누르면 런처 창 안이 내 정보 화면으로 바뀌고 `button "뒤로"`를 누르면 돌아온다. 화면 안의 조작은 [내 정보](./me.md)에 있다.
- **시작.** `await s.launcher.getByText('시작하기').click()` 다음에 `await s.stage.locator('button[title="메뉴"]').waitFor()`를 실행한다. 실행 화면 이름표에 `이름 없음`과 `Lv.1`이 보인다. 둘은 다른 요소라서 `s.stage.getByText('이름 없음')`처럼 따로 찾는다.
- **메뉴 열기.** `await s.stage.locator('button[title="메뉴"]').click()`을 실행한다. 버튼은 네 묶음이고 묶음 사이에 구분선 3개가 있다. 첫 묶음은 상태 고르기, 포커스 기록, 레벨 보상, 뽀모도로이고 둘째 묶음은 워킹룸, 친구, 대화하기, 이모티콘, 스티커 사진, 러시안룰렛이다. 셋째 묶음은 캐릭터 만들기, 가챠, 보관함, 꾸미기, 플레이리스트, 마이홈이고 마지막 묶음은 « 런처로와 설정이다. 춤추기는 열리면 러시안룰렛 뒤에 들어간다.
- **방 밖 항목.** 혼자 모드에서 대화하기, 이모티콘, 러시안룰렛, 가챠는 `aria-disabled="true"`로 흐리고 오른쪽에 `방에서만`이 보인다. `await s.stage.getByRole('button', { name: /^대화하기/ }).click({ force: true })`를 실행하면 창이 열리지 않고 실행 화면에 `방에 들어가면 쓸 수 있어요. 워킹룸에서 들어가요.`가 뜬다. `devdev` 방에 들어가면 흐림과 `방에서만`이 사라진다.
- **알림 위치.** 실행 화면에서 위 안내가 뜬 뒤 설정 창 화면 탭의 `위치 초기화`를 누르면 `위치를 처음으로 되돌렸어요.`가 설정 창 위쪽에 뜨고 `s.stage.getByText('위치를 처음으로 되돌렸어요.')`는 0개다. 런처에서 연 캐릭터 만들기 창의 `저장`을 누르면 창이 닫히고 `캐릭터를 저장했어요.`가 런처 창에 뜬다. 스테이지에서 `core.toast`를 세 번 부르면 `[class^="_toast_"]`는 2개다.
- **끌어 옮기기.** Playwright 마우스는 OS를 거치지 않아 창 이동과 클릭 통과를 증명하지 못한다. `node .claude/skills/verify-isshoni/osclick.ts`의 6번 항목이 이름표를 OS 이벤트로 150px 왼쪽, 120px 위로 끈다. 창 위치가 그만큼 바뀌고 메뉴는 열리지 않으며 옮긴 뒤에도 빈 자리는 아래 창으로 통과하고 캐릭터와 이름표는 눌린다. `device/stage-place.json`에 모니터 id마다 자리가 남고 `위치 초기화` 뒤 작업 영역 아래 가운데로 돌아온다. 7번 항목은 캐릭터 몸을 OS 이벤트로 오른쪽 120px, 위로 80px 끌어 창이 그만큼 옮겨지고 💗가 뜨지 않는 것을 본다. 2-1번 항목은 캐릭터 위에 머문 커서를 옆 빈 자리로 옮겨 20ms 뒤에 눌러도 아래 창이 받는 것을 본다.
- **좌석 수가 바뀔 때.** `devdev` 방에서 `const x = () => s.stage.evaluate(() => Math.round(window.screenX + document.querySelector('button[aria-label="내 메뉴"]')!.getBoundingClientRect().x))`로 내 이름표의 화면 x를 잰다. `devHub.writeMany`로 `rooms/DEVDEV/roster/qa5`와 `rooms/DEVDEV/members/qa5_dev`(가짜 친구 기록을 복제하고 이름만 바꾼 것)를 쓰면 좌석이 셋이 되고 x는 그대로다. 두 경로에 null을 쓰면 좌석이 둘로 돌아오고 x는 그대로다. 메뉴를 열고 닫아도 같다.
- **연결 끊김.** 방 `devdev`에 들어가고 설정 창을 열어 둔다. 사용자가 네트워크를 끊을 수 없으니 스테이지에서 `core.deps.server.goOffline({ abrupt: true })`를 실행하고 보고에 적는다. 4초 뒤에는 `button "연결 끊김"`이 없고 6초가 지나면 상태칩 줄 `메뉴 ▼` 왼쪽에 생긴다. 설정 창 위쪽에 `status`인 `연결이 끊겼어요. 다시 연결하는 중이에요.` 띠가 있다. 칩을 누르면 실행 화면에 `인터넷 연결이 끊겼어요. 다시 연결하는 중이에요. 그동안은 보내거나 저장할 수 없어요.`가 뜬다. `core.session.emit('play.pet', { to: 'devfriend_dev' }, 30)`이 false다. `core.deps.server.goOnline()`을 부르면 칩과 띠가 사라지고 방금 쓴 창(설정 창)에 `다시 연결됐어요.`가 뜬다.
- **이름표 상태.** 방 `devdev`에서 `devHub.write('rooms/DEVDEV/members/devfriend_dev/state', 'busy')`를 쓴다. 이름표 `button "가짜 친구 메뉴, 바쁨"`의 글이 `가짜 친구 바쁨`이고 점은 9px 빨간 점에 흰 가로 막대가 있다. `away`로 쓰면 `가짜 친구 메뉴, 자리비움`이고 점은 바탕이 투명하고 2px 회색 테두리다. 회사원 모드에서도 같다. `online`으로 되돌리면 이름 뒤 글이 사라진다.
- **창 렌더 오류.** 설정 창과 마이홈을 연다. 사용자가 만들 수 없는 오류라 스테이지에서 `core.windows.open.set(core.windows.open.get().map((w) => w.id === 'home.main' ? { ...w, Component: () => { throw new Error('패널 렌더 오류') } } : w))`를 실행한다. 마이홈 창에 `alert` `이 창에 문제가 생겼어요. 닫고 다시 열어 주세요.`와 `button "닫기"`가 있고 실행 화면 `button[title="메뉴"]`와 설정 창 글은 그대로다. `닫기`를 누르면 마이홈 창이 닫힌다. React가 이 오류를 `console.error`로 남기므로 `verify()`의 세 번째 인자에 `expectedErrors: [{ pattern: /^Error: 패널 렌더 오류/, count: 1 }]`를 준다.
- **실행 화면 렌더 오류.** 문서를 연 지 15초가 지난 뒤 스테이지에서 `core.allSeats = () => { throw new Error('스테이지 렌더 오류') }`와 `core.seatsDrawn.set((n) => n + 1)`을 실행한다. 스테이지가 다시 읽히고(`s.stage.waitForEvent('load')`) 런처가 다시 뜨며 시작하기 뒤 `button[title="메뉴"]`가 보인다. 메인 로그(`<userData>/logs/main-*.log`)에 `[renderer] renderer.stage: stage: 스테이지 렌더 오류`가 있다. 이 오류도 `console.error`로 남으므로 `expectedErrors: [{ pattern: /^Error: 스테이지 렌더 오류/, count: 1 }]`를 준다.
- **런처로.** `await menu(s, '« 런처로', 'Isshoni Hatarakou')`를 실행한다. 제목이 `Isshoni Hatarakou`인 런처 창이 다시 열린다.
- **작은 작업 영역.** 모니터를 바꿀 수 없으니 메인의 `screen`을 바꿔 작업 영역이 700x450인 모니터처럼 만들고 보고에 적는다. 방 `devdev`에 들어가고 `core.ctxs.get('core').ctx.seats.addLocal`로 로컬 좌석 4개를 더해 좌석 6개 줄(`window.innerWidth`가 976)을 만든 뒤 아래를 실행한다.
  ```ts
  await s.app.evaluate(({ screen }) => {
    const d = screen.getPrimaryDisplay();
    const f = { ...d, workArea: { x: d.workArea.x, y: d.workArea.y, width: 700, height: 450 } };
    screen.getPrimaryDisplay = () => f;
    screen.getAllDisplays = () => [f];
    screen.emit('display-metrics-changed');
  });
  ```
  0.5초쯤 뒤 `window.bridge.invoke('stage.workArea', {})`가 `{ width: 700, height: 450 }`이고 `window.innerWidth`가 700 이하가 되며 좌석 칸(`core.seatViews`의 `el.offsetWidth`)이 160에서 114로 준다. `가짜 친구 쓰다듬기`를 누르면 💗가 뜬다. `button[title="메뉴"]`를 누르면 `window.innerHeight`가 450 이하이고 `설정` 버튼의 부모(메뉴)는 `scrollHeight`가 `clientHeight`보다 크다. 메뉴를 끝까지 내려 `설정`을 누르면 설정 창이 열린다. `가짜 친구 메뉴`를 누르면 `menu "가짜 친구"`의 상자가 창 안에 있다. 바꾼 `screen` 함수를 되돌리고 다시 `display-metrics-changed`를 내면 너비와 좌석 칸이 원래대로 돌아온다.
- **창이 작업 영역에 맞는지.** 위와 같이 `screen`을 바꾸되 `workArea`를 `{ x: 0, y: 33, width: 853, height: 432 }`(1280x720 150%)로 두고 `getDisplayMatching`도 같은 모니터를 돌려주게 한다. `메뉴 ▼`를 누르면 메뉴의 `clientHeight`가 160 이상(다섯 줄)이고 `offsetWidth - clientWidth`가 6이라 스크롤 막대가 보인다. `스티커 사진`, `캐릭터 만들기`, `대화하기`(방 안), `설정`, « 런처로의 런처 창은 메인의 `getBounds()`가 작업 영역 안이고 `촬영 시작`, `저장`, `보내기` 단추 아래 끝이 그 창의 `innerHeight` 안이다.
- **증거.** 단계마다 `s.shot`으로 런처와 실행 화면을 남긴다.

## Gotchas

- 런처에도 `캐릭터 만들기`, `설정` 버튼이 있다. 메뉴 항목과 이름이 같으니 어느 창의 버튼을 누르는지 `s.launcher`와 `s.stage`로 구분한다. 방 창은 런처 버튼이 `방 만들기 / 참여하기`(방에 있으면 `방 정보`)이고 메뉴 항목과 창 제목은 `워킹룸`이다.
- 메뉴 칩의 접근 가능한 이름은 `메뉴 ▼`이다. 찾을 때는 `button[title="메뉴"]`를 쓴다. `내 메뉴` 버튼은 내 이름표이고 같은 메뉴를 연다. 내 캐릭터를 누르는 `내 캐릭터 쓰다듬기`는 메뉴를 열지 않는다.
- 흐린 메뉴 항목은 `aria-disabled`라서 Playwright `click()`이 누를 수 없다고 보고 기다리다 시간이 지난다. `menu()`도 같다. 혼자 모드에서 누를 때는 `click({ force: true })`를 쓰고 항목 이름 뒤에 `방에서만`이 붙으니 `/^대화하기/`처럼 찾는다.
- ARIA 스냅샷의 한 줄이 화면에서는 여러 요소일 수 있다. `getByText`가 못 찾으면 스냅샷 줄 전체 대신 요소 하나의 글자로 찾는다.
- 실행 화면은 `app.windows()`의 첫 창이다. 런처를 포함한 나머지 창은 제목으로 찾는다.
- 설정 창 화면 탭에서 회사원 모드를 켜면 메뉴 항목 수가 줄고 상태칩에 `숨기기` 칩이 더해진다. 상태칩 자리를 바꾸면 `메뉴 ▼`가 캐릭터 옆으로 간다. [설정 창](./settings.md)을 본다.
- 작업 영역을 바꾼 뒤 스테이지는 400ms 지나서 다시 놓이므로 `expect.poll`로 기다린다. 바꾼 `screen` 함수는 세션이 끝나면 앱과 함께 사라진다.
- 끊긴 동안에는 알림이 방금 쓴 창에 뜬다. `다시 연결됐어요.`도 설정 창을 눌렀으면 설정 창에서 찾는다.
- 창 렌더 오류를 일으킨 창이나 저장하지 않은 닉네임이 남은 창은 세션이 끝날 때 beforeunload를 낼 수 있다. 모든 창에 `page.on('dialog', (d) => void d.dismiss().catch(() => {}))`를 붙인다.
- 위쪽으로 끌어 둔 캐릭터의 메뉴를 열면 창이 작업 영역 안에 남도록 아래로 밀려 캐릭터가 메뉴를 닫을 때까지 내려간다.
- 방에 들어가 좌석이 늘면 실행 화면은 왼쪽 끝을 두고 오른쪽으로 넓어진다. 그래서 방 안에서는 실행 화면이 아래 가운데가 아닐 수 있다. 끌기, `위치 초기화`, 모니터 고르기가 이 자리를 지우고 앱을 다시 켜면 끌어 둔 자리나 아래 가운데에서 시작한다.
