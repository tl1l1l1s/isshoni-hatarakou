# 작업·장애 복구·재시작

작업 앱 등록부터 보상 사용까지 연결하고, 저장 실패 후 복구와 앱 재시작을 검증한다. 창 다시 열기와 앱 재시작은 별개로 확인한다. 반복 실행 경로는 `tests/e2e/recovery.spec.mts`에 있으며 `npx electron-vite build --mode e2e` 뒤 `npx playwright test tests/e2e/recovery.spec.mts`로 실행한다.

## Sub-features

- `work-reward`는 일반 문서 앱 등록 → 방 생성 → 작업 → 달성표·레벨과 뽑기 → 보관함 → 꾸미기 저장과 재열기다.
- `work-reward-save-failed`는 서버가 뽑기 기록을 거절해도 획득분이 유지되고 복구 뒤 한 번만 사용되는 것이다.
- `report-recovery`는 자동 진단 기록을 저장하지 못했을 때 pending을 보존하고 재연결 후 서버에 하나만 남기는 것이다.
- `restart-saved`는 저장 직후 앱을 다시 켜도 이름·캐릭터·플레이리스트가 유지되는 것이다.
- `pin-lifecycle`은 핀 고정 → 다른 창 활성화 → 축소 → 닫기 → 재열기 → 해제 → 화면 숨김/복원 → 재시작의 상태 전이다.
- `verify-error`는 패널 오류가 실제로 검증을 실패시키고 사전에 지정한 오류만 정해진 횟수로 허용되는 것이다.

## How to get to it (user POV)

- 설정의 집중 앱에서 일반 문서 앱을 등록하고 방 만들기 / 참여하기에서 내 방을 만든다. 방 설정에서 아이템을 넣고 작업한 다음 가챠·보관함·꾸미기를 연다.
- 설정에서 오류 자동 보고를 켠 상태로 네트워크 장애를 겪었다가 재연결한다.
- 설정에서 이름, 캐릭터 만들기에서 책상, 플레이리스트에서 곡을 저장하고 앱을 종료한 뒤 다시 켠다.
- 플레이리스트의 항상 위에 고정·작게 보기와 설정 화면 탭의 회사원 모드·숨기기를 사용한다.

## Driving it with drive.ts

Preconditions:

- 격리된 메모리 서버 빌드이며 운영 서버와 웹훅에는 연결하지 않는다.
- 문서 앱은 `fakePlatform.app = 'win:notepad.exe'`로 준비한다. 1시간은 실제 활동 샘플을 30초 간격으로 보내 가속한다. `focus.tick`이나 가챠·레벨 기록을 직접 넣지 않는다.
- 이미지 파일 선택은 시험 PNG를 반환하게 한다. 유튜브 iframe은 로컬 HTML 응답으로 대체한다. 이 검증은 영상·소리 출력이 아닌 앱의 재생 상태를 증명한다.

1. **작업과 보상.** 집중 앱 탭의 `직전에 쓴 앱 넣기`로 notepad를 등록한다. 내 방에 `별` 아이템을 넣고 포커스 기록의 달성표에서 하루 목표 1시간을 정한 뒤 작업 샘플을 보낸다. 달성표의 `1일 달성`을 확인한다. 레벨 보상 창의 `Lv.2`와 가챠 창의 `남은 뽑기 1회`를 확인한다.
2. **저장 장애.** 가챠 서버 transaction이 거절하도록 준비한 뒤 `1회 뽑기`를 누른다. 실패 안내와 유지된 1회를 찍는다. 실패 주입을 해제하고 다시 누르면 `NEW!`, 남은 0회, 보관함 `1/1종`이 보인다. 꾸미기에 붙여 저장한 뒤 다시 열어 외형에 스티커가 있는지 확인한다.
3. **진단 복구.** 자동 보고를 켠 설정 창을 연다. 서버 저장 실패를 주입하고 메인에 시험 오류를 보고한다. pending이 1개인 것을 확인한 뒤 저장 실패를 해제하고 메모리 서버 연결을 끊었다가 잇는다. pending은 0개, 서버 기록은 해당 내용 1개여야 한다. ack 실패 후 중복 방지는 `src/modules/report/recovery.test.ts`가 별도로 검증한다.
4. **핀과 창 숨김.** 곡을 등록하고 재생·핀을 켠다. 다른 창에 포커스를 준 뒤에도 BrowserWindow.isAlwaysOnTop()이 true인지 확인한다. 축소해도 유지되고 닫았다 열면 핀은 유지되지만 일시정지 상태다. 핀 해제를 확인한다. 다시 핀을 켜고 회사원 모드의 숨기기로 숨겼다 복원해도 일시정지 상태여야 한다.
5. **앱 재시작.** `await s.restart()`를 호출한다. `s.app`, `s.stage`, `s.launcher`는 새 참조다. 시작하기를 누르고 이름·외형을 다시 읽어 저장 전 값과 비교한다. 플레이리스트 곡은 남고 핀 버튼은 false, BrowserWindow.isAlwaysOnTop()도 false, 재생 버튼은 일시정지 상태다. 임의의 저장 대기 시간이나 내부 flush는 넣지 않는다.
6. **오류 판정.** 설정 패널에서 지정한 console.error를 발생시키면 기본 verify는 실패해야 한다. 새 세션에서 정확한 메시지와 count: 1을 지정하면 통과한다. 다른 오류나 누락·초과 발생은 통과하지 않는다.

각 단계의 버튼 조작 결과와 저장 후 다시 읽은 화면을 `s.shot`으로 남긴다. 오류 판정 시험의 의도한 실패도 별도 증거 폴더에 남는다.

## Gotchas

- 메모리 서버의 goOffline()만으로 쓰기 거절을 재현할 수 없다. 실패를 시험할 저장 함수에만 주입하고 복구 단계에서 반드시 해제한다.
- `s.restart()`는 디스크를 보존하지만 메모리 서버는 새로 만들어진다. 서버 기록의 재시작 내구성은 이 경로로 증명하지 않으며 에뮬레이터와 서버 계약 테스트가 담당한다.
- 직접 사용하는 OS 앱을 앞에 놓았을 때의 실제 창 순서와 독점 전체 화면은 Windows 체크리스트로 검증한다. isAlwaysOnTop() 값만으로 OS 합성 결과를 검증했다고 보고하지 않는다.
- `getByLabel`로 포털의 암묵적 label을 찾지 못하면 같은 접근 가능한 이름의 `getByRole('combobox'/'textbox')`를 쓴다. 개인정보 처리방침은 버튼이 아니라 summary이므로 텍스트로 펼친다.
- 오전 6시와 폰 4시간 경계는 `tests/sim/work-recovery.test.ts`, 뽑기 실패 중 기준 변경·방 이동은 `src/modules/gacha/sim.test.ts`에서 시간을 통제해 검증한다.
