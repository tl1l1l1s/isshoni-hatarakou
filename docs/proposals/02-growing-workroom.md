# 함께 키우는 작업실

작성일: 2026년 10월 10일 · 상태: 기획 초안, 미구현

## 경험과 목적

방에서 보낸 시간이 모두의 공간에 남도록 합니다. 처음에는 작은 창가와 화분뿐이지만, 함께 작업하면서 책장이 생기고 고양이가 찾아오고 옥상 정원이 열립니다. 친구가 며칠 뒤 돌아오면 “우리 작업실에 새것이 생겼네”를 느낍니다.

개인 레벨이나 가챠를 대체하지 않습니다. 같은 집중 시간이 개인 성장과 공동 공간의 진전에 각각 쓰이며, 가챠 횟수나 아이템을 건설 비용으로 빼지 않습니다.

## 현재 기능과 연결

- [rooms](../../src/modules/rooms/api.ts)의 지속되는 방을 공동 공간의 단위로 씁니다.
- [home](../../src/modules/home/logic.ts)의 개인 배경·스티커 꾸미기와 달리 방 사람들이 함께 소유하는 배치와 해금 상태를 둡니다.
- [focus](../../src/modules/focus/api.ts)의 실제 집중 시간만 기여량으로 인정합니다. 공동 세션에 참여하지 않고 작업해도 기여할 수 있습니다.
- 캐릭터를 띄운 투명 스테이지에는 작은 화분 같은 선택 소품만 보입니다. 전체 작업실은 별도 창에서 엽니다.

## 사용자 흐름과 화면

1. 방 주인이 `우리 작업실`을 열고 `밤의 도서관 / 창가 작업실 / 옥상 정원` 중 시작 테마를 고릅니다. 테마 변경으로 이미 얻은 물건은 사라지지 않습니다.
2. 사람들은 후보 프로젝트에 투표합니다. 후보에는 완성 모습, 필요한 공동 시간, 이미 모인 시간이 보입니다.
3. 방 주인이 프로젝트를 확정하면 그 뒤부터 기여하기를 켠 사람들의 실제 집중 시간이 쌓입니다.
4. 진행 중에는 싹이 돋거나 상자가 풀리는 등 단계별 변화가 보입니다.
5. 목표가 채워지면 소품이나 구역이 열립니다. 방에 없던 사람도 다음 접속 때 완성 소식을 한 번 볼 수 있습니다.
6. 가구 배치 화면에서 해금 물건과 직접 그린 소품을 놓습니다. 완성 장면을 앨범에 남길 수도 있습니다.

작업실 창에는 공간, 현재 프로젝트, `다음에 만들 것`, 꾸미기 메뉴를 둡니다. 기여 화면에는 공동 합계와 내 기여만 표시하고 타인의 시간 순위는 표시하지 않습니다.

## 성장 규칙 제안

| 항목 | 기본안 |
|---|---|
| 기여 방식 | 현재 들어가 있는 방에서 집중한 1분이 공동 시간 1분이 됨 |
| 참여 선택 | 방별로 기여를 켜고 끌 수 있음; 과거 시간을 소급하지 않음 |
| 동시 작업 | 3명이 각자 20분 집중하면 공동 60분 |
| 프로젝트 예시 | 작은 화분 5시간, 책장 20시간, 새 구역 60시간; 플레이 검토용 수치 |
| 비활동 기간 | 성장 정지; 시듦·퇴화·유지비 없음 |
| 프로젝트 교체 | 모아 둔 진전은 해당 프로젝트에 남고 새 프로젝트로 옮기지 않음 |
| 완료 시 초과분 | 방의 미배정 시간으로 보관하고 다음 확정 프로젝트에 적용 |
| 개인 보상 | 별도 기여 순위·독점 보상 없음; 해금 공간은 방 사람 모두 이용 |

활성 프로젝트는 하나입니다. 중단된 프로젝트를 다시 선택하면 이어서 진행합니다. 가득 찬 프로젝트에 마지막 기여가 동시에 들어와도 해금은 한 번만 일어나야 합니다.

## 투표와 편집 권한

- 투표는 다음 프로젝트를 고르는 의견 수렴입니다. 작업 시간을 많이 낸 사람에게 표를 더 주지 않습니다.
- 방에 있는 사람은 한 표를 내거나 바꾸고, 방 주인이 결과를 보고 확정합니다. 방에 없는 사람을 기다려야만 시작되는 정족수는 두지 않습니다.
- 방 주인은 꾸미기 권한을 `주인만 / 방 멤버`로 고릅니다. 직접 올린 그림의 작성자와 사용 범위를 저장합니다.
- 배치 변경은 되돌릴 수 있어야 합니다. 동시 편집에서 오래된 화면의 저장이 다른 사람의 새 배치를 통째로 덮어쓰지 않게 합니다.
- 내가 만든 소품을 회수하면 해당 그림은 작업실에서 제거하지만 공동 프로젝트의 달성 이력은 유지합니다.

## 데이터와 경계 상황

방에 테마, 프로젝트별 진행도, 미배정 시간, 해금 목록, 배치, 투표를 둡니다. 개인 기여 원장은 합계 중복 반영 방지에 필요하지만 다른 멤버에게 원장 전체를 공개하지 않습니다.

기여는 방 ID와 고유 기록 ID로 중복 반영을 막습니다. 현재 서버 함수가 없는 구조에서 클라이언트가 보내는 집중 시간의 완전한 진위를 보장한다고 가정하지 않습니다. 사용자 경험용 성장으로 다루며, 수정된 클라이언트를 막을 검증 수준은 별도로 정합니다.

연결이 끊긴 동안의 시간은 마지막으로 확인된 방·프로젝트에 묶어 로컬에 보관합니다. 재접속 때 방 존재와 권한을 확인해 반영하고, 방이 삭제되었거나 권한을 잃었으면 공동 기여는 반영하지 않습니다. 개인 집중 기록은 그대로 남습니다. 오프라인 허용 기간과 기여 상한은 구현 전에 정합니다.

방 삭제 시 공간이 사라진다는 사실과 내보내기 선택을 먼저 안내합니다. 앨범에 이미 게시한 완성 사진은 앨범의 별도 보관 규칙을 따릅니다. 탈퇴자의 과거 기여는 공동 합계에서 빼지 않고 표시 이름은 계정 삭제 정책에 맞춰 익명화합니다.

## 구현 연결 제안

`workroom` 모듈이 공동 성장과 배치를 소유하고 `focus.tick`에서 필요한 초와 기록 식별자만 받습니다. 앱 키는 서버로 보내지 않습니다. 기존 틱에는 공동 기여용 고유 ID가 없으므로 중복 방지 계약은 추가 설계가 필요합니다.

배경 전체를 스테이지에 항상 렌더링하지 않습니다. 작업실 창을 닫으면 공간 렌더링과 편집용 구독을 종료하고, 해금 알림에 필요한 상태만 유지합니다. 사용자가 올리는 이미지의 검증과 파일 크기 제한은 기존 파일 경로를 따르되 큰 배경 품질은 별도 검토합니다.

## 확인할 시나리오

- 같은 기여를 재전송하거나 기기를 바꿔도 공동 시간이 두 번 늘지 않는다.
- 방을 옮긴 시각 전후의 시간이 올바른 방에 들어간다.
- 두 사람이 마지막 기여를 동시에 보내도 해금과 초과분이 정확하다.
- 프로젝트 교체와 기여가 겹쳐도 시간이 사라지거나 두 프로젝트에 들어가지 않는다.
- 며칠 미접속 후에도 모든 성장과 물건이 유지된다.
- 소품 회수·방 삭제·동시 배치 편집에서 다른 사람의 데이터를 조용히 덮어쓰지 않는다.

## 검토할 선택

프로젝트별 필요 시간은 친구들의 실제 이용량을 보고 조정합니다. 많은 시간을 쓰도록 압박하기보다 공간이 주기적으로 달라지는 속도를 목표로 합니다. 테마별 그림과 해금 연출의 구체적인 아트 목록은 이 기획에 맞춰 별도 제작합니다.
