# 0009 M3 놀이 묶음의 스티커 사진과 올라타기, 동물탑, 벤치

날짜 2026년 10월 9일

COM-15는 `photo` 모듈이고 COM-16과 HOM-17과 AVT-21은 `seating` 모듈입니다. 좌석 계층에 고칠 곳이 있어서 코어도 조금 바꿨습니다.

## 정한 것

### 올라타기와 동물탑 (COM-16, HOM-17)

- 붙임 상태는 `seating` presence 필드로 보냅니다. `on`은 내가 올라탄 사람의 uid이고 `bench`는 같이 앉은 벤치 주인의 uid이며 `cap`은 내 책상이 벤치일 때 자리 수입니다. 같은 uid는 좌석 하나만 그리므로 좌석 key 대신 uid를 씁니다. key 두 개를 담으면 모듈 presence 상한 128바이트를 넘을 수 있습니다.
- 모든 PC가 멤버 기록만으로 같은 배치를 계산하고 바뀐 좌석만 `ctx.seats.attach`와 `ctx.seats.setBench`에 넣습니다. 그래서 방 사람 모두에게 같은 탑과 벤치가 보입니다.
- 남의 머리 위에는 다른 사용자 메뉴의 `머리 위에 올라타기`로 올라탑니다. 스테이지는 클릭 영역 밖으로 나간 마우스를 받지 못해서 끌어다 놓는 방식은 쓰지 않았습니다. 고른 사람 위에 이미 탑이 있으면 맨 위에 앉습니다.
- 동물 캐릭터만 올라탑니다. 사람 캐릭터에게는 메뉴 항목이 숨습니다. 이 확인은 보내는 PC만 하고 받는 PC는 presence를 그대로 그립니다.
- 내 위에 있는 사람에게는 올라타지 못하고 한 탑에는 3명까지 올라탑니다. 층마다 스테이지가 좌석 높이만큼 커지기 때문입니다.
- 올라타 있으면 상태칩 줄에 `내려오기`가 생깁니다. 다른 방으로 옮기거나 동물이 아닌 캐릭터로 바꾸면 저절로 내려옵니다.
- 아래 사람이 효과로 날아가거나 방을 나가면 위 사람이 한 칸 내려오는 규칙은 0007의 코어 좌석 계층이 처리합니다.
- 아래 사람이 올라타기를 거부하는 기능과 넓은 머리 파츠의 얹을 수 있음 속성은 넣지 않았습니다. 친구끼리 쓰고 2D 스티커에는 머리 파츠가 없습니다.

### 벤치 (AVT-21)

- 캐릭터 만들기 책상 목록에 `2인 벤치`와 `3인 벤치`를 더했습니다. 기본 책상으로 돌아갈 때도 같은 목록에서 고릅니다. 책상 인벤토리와 그 단축키는 따로 두지 않았습니다. 전역 단축키는 다른 앱에서 같은 키를 칠 때 가로채기 때문입니다.
- 벤치 책상을 쓰는 사람 옆에는 다른 사용자 메뉴의 `벤치에 같이 앉기`로 앉고 상태칩 줄의 `일어나기`로 돌아옵니다. 자리보다 많이 앉으면 먼저 들어온 사람부터 앉습니다. 남의 벤치에 앉은 사람은 벤치 주인이 되지 않습니다.
- 벤치 그림은 칸 끝까지 닿는 판이고 세로 테두리를 긋지 않습니다. 벤치에 앉은 좌석이 이 그림을 겹쳐 그려도 판 하나로 이어집니다.
- 책상마다 해금 레벨은 두지 않았습니다. 벤치 자리 수는 `@modules/wardrobe/api`의 `BENCH_SEATS`에 있습니다.

### 스티커 사진 (COM-15)

- 사진은 찍는 PC가 자기 화면에서 찍습니다. 같은 방 사람을 들어온 순서로 4명까지 나란히 놓고 컷마다 5초를 센 뒤 찍습니다. 방 밖에서는 나 혼자 찍습니다.
- 키(A, D, Q, E, W, S, Space)는 촬영 미리보기가 포커스를 가질 때만 받습니다. A와 D로 내 캐릭터를 옮기고 Q와 E로 돌고 Space로 뜁니다. W와 S는 거리(전신, 상반신, 얼굴)를 바꿉니다. 다른 사람은 지금 외형의 기본 자세로 서 있습니다. manifest 단축키는 모든 패널에 걸려서 채팅 입력의 글자까지 가로채므로 쓰지 않았습니다.
- 방향은 가로와 세로이고 컷 수는 가로 1, 2, 4컷과 세로 1, 4컷입니다. 결과 한 장은 가로 960x720이나 세로 720x960이고 검은 테두리 안에 컷을 놓습니다. 배경은 6색이고 필터는 없음, 뽀샤시, PS1, 흑백, 새벽, 빈티지입니다. 프레임은 코드로 그린 하트, 별, 필름과 내 프레임입니다. 내 프레임은 고른 PNG 하나를 모든 컷에 겹치고 서버에 올리지 않습니다.
- 꾸미기에는 스티커 12종, 펜 5종(기본, 무지개, 외곽선, 속 빈, 글로우), 굵기, 8색, 되돌리기와 앞으로, 전부 지우기가 있습니다. 스티커는 그림 파일 없이 OS 컬러 이모지 글꼴로 그립니다(0005의 이모티콘과 같은 방식).
- 저장하기는 패널 창의 내려받기 링크로 저장 창을 띄우고 서버에 올리지 않습니다.
- 방에 보내기를 두었습니다. 각 PC가 따로 찍으므로 함께 찍힌 사람도 결과를 갖도록 꾸민 사진을 `ctx.files.prepareImage`로 64KB 안으로 줄여 `files`에 올리고 방 이벤트 `photo.shared`에는 해시만 담습니다. 받은 사진은 알림과 함께 받은 사진 탭에 들어오고 이번 실행 동안 최근 10장만 남습니다.
- 촬영 자리 잡기, 진행자, 자세 정보 동기화, 하루 촬영 한도, 촬영 배경음악은 넣지 않았습니다. 친구 두세 명이면 서버 비용 때문에 횟수를 막을 이유가 적고 배경음악은 쓸 수 있는 소리 파일이 없습니다. 그래서 `photo` 모듈은 서버 컬렉션과 규칙이 없습니다.
- 채팅 도구 단추는 chat 모듈에 슬롯이 없어서 넣지 않았습니다. ▼ 메뉴의 `스티커 사진`으로 엽니다. 조용한 모드에서는 메뉴에서 숨고 명령도 막힙니다.

## 코어 변경

- 좌석 배치에서 bench id와 key가 같은 좌석이 있으면 그 좌석이 벤치 맨 앞에 앉습니다. 벤치에 붙은 좌석은 자기 책상과 바닥 대신 벤치 첫 좌석의 책상을 그립니다. 10.8.2의 책상 하나에 좌석 여러 개를 이렇게 그립니다.
- 좌석 줄을 아래 맞춤에서 위 맞춤으로 바꿨습니다. 상태칩 줄이 내 좌석에만 있어서 다른 사람 캐릭터가 그만큼 낮게 앉았고 벤치 판이 어긋났습니다. 이제 모든 캐릭터와 책상이 같은 높이에 앉고 이름표 아래 길이만 다릅니다.
- 남의 머리 위에 올라탄 좌석이 제자리에서도 자기 위에 탄 좌석을 한 번 더 그리던 문제를 고쳤습니다. 탑이 두 층 이상일 때 생겼습니다.
- 올라탄 캐릭터가 열린 메뉴를 덮어 메뉴 항목을 누를 수 없었습니다. 메뉴를 올라탄 캐릭터보다 위에 그립니다.
- 메모리 서버를 `globalThis.devHub`에 둡니다. 검증과 시험이 가짜 친구의 기록과 방 이벤트를 쓸 때 씁니다. 메모리 서버는 개발판과 시험판에만 있습니다.

## 알려진 한계

- 두 PC가 거의 같은 때 같은 사람에게 올라타면 둘 다 그 사람 머리 위에 겹쳐 앉습니다. 둘 가운데 하나가 다시 올라타면 맨 위로 갑니다.
- 사진에서 다른 사람 캐릭터는 움직이지 않습니다. 함께 움직이려면 자세 정보를 방에 보내야 해서 10.12 설계의 자리와 진행자가 필요합니다.
- 자세 그림은 긴 변 320px이라 큰 컷의 얼굴 구도에서는 조금 흐립니다.
- 방에 보낸 사진은 `files`에서 지우지 않습니다. 보낼 때마다 데이터베이스가 64KB까지 늘어납니다.
- 모듈을 내릴 때 그 모듈이 넣은 붙이기와 벤치가 코어에 남습니다. 모듈은 앱을 끌 때만 내려가서 고치지 않았습니다.
- Windows에서 이모지 스티커 모양과 저장 창은 확인하지 않았습니다. 실제 Firebase의 두 PC에서 올라타기, 벤치, 사진 보내기도 확인하지 않았고 메모리 서버와 가짜 친구로만 확인했습니다.
