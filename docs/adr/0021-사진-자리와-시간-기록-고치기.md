# 0021 스티커 사진 자리와 시간 기록 고치기

날짜 2026년 10월 9일

코드 검토에서 나온 스티커 사진(COM-15), 자리(COM-16, HOM-17, AVT-21), 뽀모도로(FOC-07), 달성표(GRW-06), 다가오는 일정(HOM-22), 휴지통(ACC-08) 문제를 고쳤습니다. 0019의 촬영 자리 규칙 일부를 이 문서가 바꿉니다. 코어는 바꾸지 않았습니다.

## 정한 것

### 스티커 사진

- 창을 열어 둔 동안 5분마다 내 자리의 `at`을 다시 씁니다. 0019에서는 자리를 잡을 때 한 번만 써서 창을 15분 넘게 열어 두면 새로 온 사람이 내 자리를 덮었습니다.
- 자리를 잡을 때 빈자리와 내 자리를 먼저 보고 15분 지난 남의 자리는 빈자리가 없을 때만 잡습니다.
- 내 자리가 사라지거나 남이 잡은 것을 보면 연결이 끊길 때 자리와 자세를 지우도록 한 예약을 거둡니다. 거두지 않으면 나중에 내 연결이 끊길 때 그 자리를 잡은 사람의 자리와 자세를 지웁니다.
- 규칙은 자리 `at`이 서버 시각보다 60초 넘게 앞서지 못하게 막습니다. 앞날 시각을 써서 자리를 오래 차지하지 못하게 하려는 것입니다. 검토 의견은 `at <= now`였지만 PC가 추정한 서버 시각이 실제보다 조금 앞설 수 있어서 60초를 봐줬습니다.
- 창을 닫을 때 자리와 자세를 먼저 지우고 그다음에 예약을 거둡니다. 마지막으로 나가는 사람은 설정과 컷까지 함께 지우는데 그사이 누가 자리를 잡으면 규칙이 이 쓰기를 거절합니다. 그때는 내 자리와 자세만 다시 지웁니다.
- 촬영 시작을 빠르게 두 번 눌러도 한 번만 시작하고 하루 한도도 한 번만 셉니다.
- 함께 찍자는 안내와 받은 사진 알림을 누르면 `photo.open` 명령으로 창을 엽니다. 회사원 모드에서는 창을 열지 않고 회사원 모드에서는 쓸 수 없다는 안내를 띄웁니다.
- 찍기 탭에 자세 단추 `왼쪽으로`, `오른쪽으로`, `돌아서기`, `점프`를 더했습니다. 펜으로 쓰는 사람이 키보드 없이 내 캐릭터를 움직입니다. 거리는 이미 있던 거리 단추로 바꿉니다. 키는 그대로 됩니다.
- 하루 한도 올리기와 촬영 시작 쓰기를 한 번의 쓰기로 묶지 않았습니다. 한도는 `mod/photo/g/quota`에 있고 시작은 `mod/photo/r/{방}/cfg`에 있어서 두 경로를 한 번에 쓰려면 방 범위와 전체 범위를 함께 쓰는 다중 경로 쓰기를 코어 `DocHandle`에 더해야 합니다. 한도는 transaction으로 올리므로 다중 경로 쓰기와 함께 쓸 수도 없습니다. tunable `photoDailyCap` 기본값이 0이라 지금은 한도를 세지 않습니다. 로그인한 계정이 촬영 없이 한도를 올려 다른 사람의 촬영을 막는 문제는 한도를 켤 때만 생깁니다.

### 자리

- 방 코드가 실제로 바뀔 때만 올라타기와 벤치를 풉니다. 절전에서 깨어나 다시 들어갈 때, 다른 기기에서 가져온 뒤 다시 들어갈 때, 자동 퇴장 뒤 같은 방에 다시 들어갈 때는 그대로 둡니다. 0009에서는 방에서 나가기만 해도 풀어서 절전 한 번에 올라탄 상태가 사라졌습니다.

### 뽀모도로

- 끝난 지 1분이 넘은 타이머는 알리지 않고 끝냅니다. 앱을 끈 사이나 절전 중에 끝난 타이머가 다음에 켤 때 알림을 띄우고 휴식을 시작했고 휴식 뒤 자동 시작을 켜 두면 집중과 휴식이 이어서 돌았습니다.
- 일시정지, 다시 시작, 건너뛰기는 창을 그린 때의 타이머가 아니라 저장된 지금 타이머를 바꿉니다. 그린 뒤 단계가 넘어가면 지난 단계로 되돌리던 문제입니다.

### 달성표

- 오늘 기록을 1분마다 쓰는 것에 더해 목표를 채웠는지가 바뀔 때와 절전, 종료 때도 씁니다. 다른 PC에서 달성표를 열 때 방금 채운 목표가 바로 보입니다.

### 다가오는 일정

- 오늘 일정 알림은 이 계정을 쓰는 기기(ACC-12)에서만 보냅니다. 다른 기기가 가져간 사이에 생긴 일정은 이 기기가 다시 가져온 뒤 다음 확인 때 알립니다.

### 휴지통

- 이전 모습 목록은 키 순서의 마지막 50개를 읽습니다. 키가 `<mtime>_<칸>`이라 마지막 50개가 최근 50개입니다. 예전에는 처음 50개를 읽어서 50개를 넘으면 오래된 모습만 보였습니다. `DocHandle.list`에는 끝에서 읽는 선택이 없어서 `watchList`의 `last`로 한 번 읽고 바로 구독을 끊습니다.

## 알려진 한계

- 자리 시각 고치기, 빈자리 먼저 잡기, 잃은 자리의 예약 거두기는 메모리 서버 시뮬레이터로 확인했습니다. 메모리 서버는 규칙을 검사하지 않아서 창을 닫을 때 설정 지우기가 거절되는 경우는 시뮬레이터로 만들지 못했습니다. 그 거절은 에뮬레이터 규칙 시험에 이미 있습니다.
- 방을 나갔다가 같은 방에 다시 들어가면 올라탄 상태가 남습니다. 올라탔던 사람이 방에 없으면 제자리에 앉습니다.
- 달성표를 종료 때 쓰는 것은 앱이 끝나기 전에 쓰기가 서버에 닿는다는 보장이 없습니다. 실제 Firebase로 확인하지 않았습니다.
- 오늘 일정 알림은 기기마다 보낸 목록을 따로 기억해서 두 기기를 번갈아 쓰면 같은 일정 알림이 기기마다 한 번씩 올 수 있습니다.
- 실제 Firebase의 PC 두 대와 Windows의 절전, 펜 입력으로는 확인하지 않았습니다.
