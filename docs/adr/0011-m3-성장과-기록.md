# 0011 M3 성장과 기록 묶음

날짜 2026년 10월 9일

GRW-02, GRW-04, GRW-06, GRW-07, GCH-04, GCH-05, FOC-04, FOC-07, FOC-08, FOC-09를 넣었습니다. 새 모듈은 goals(달성표), pomodoro(뽀모도로), phone(폰 연결)입니다.

## 코어 변경

10.3의 11번에 따라 기능 이름이 없는 범용 기능 두 가지를 더했습니다.

- `ctx.self.activeDevice()`와 `ctx.self.onActiveDevice(fn)`은 이 PC가 지금 이 계정을 쓰는 기기인지 알려 주고 값이 바뀌면 fn을 부릅니다. 값은 0007의 한 계정 한 기기 상태를 그대로 읽습니다. 다른 기기가 가져가면 false가 되고 여기서 계속 쓰기를 누르면 true로 돌아옵니다. 한 계정 한 기기를 끈 시뮬레이터에서는 늘 true입니다. 0007의 알려진 한계였던 문제는 focus 모듈이 이 값으로 고칩니다. 다른 기기에서 쓰는 중인 PC는 이제 포커스 시간을 세지 않습니다.
- `ctx.gates.list()`는 선언된 gate마다 id, 이름, 조건 모듈, 함수 이름, 지금 조건 값, 열렸는지를 돌려줍니다. 조건 값이 tunable이면 gate를 선언한 모듈의 지금 값을 읽습니다. 레벨 보상 표처럼 여러 모듈의 gate를 모아 보여 주는 화면이 씁니다.

## 정한 것

- 레벨 보상 표(GRW-02)는 보상을 growth 안에 따로 적지 않습니다. 다른 모듈이 growth의 `level`에 선언한 gate를 모아 레벨 순서로 보여 줍니다. 보상 레벨은 그 gate나 tunable 한 곳에서 바꿉니다. 놀이 묶음이 춤, 폭탄, 채팅 날리기 글자 색 gate를 이렇게 선언하면 표에 저절로 나옵니다. 동물 캐릭터도 표에 나오도록 wardrobe manifest에 같은 해금 레벨을 gate로 적었습니다. 실제 해금은 지금처럼 wardrobe의 해금 기록이 정합니다. 새 보상이 열리면 스테이지 알림을 띄우고 켤 때 이미 열려 있던 보상은 알리지 않습니다. 레벨 5마다 뽑기 1회는 9.3 OUR-02에 따라 넣지 않았습니다.
- growth의 `level()`은 회차와 상관없는 평생 레벨로 그대로 둡니다. 보상과 gate는 이 값을 봅니다.
- 회차(GRW-04)는 999레벨분을 채울 때마다 넘어가고 화면 레벨은 1부터 다시 올라갑니다. 2회차부터 이름표의 Lv.을 ☆로 바꾸고 회차 수는 이름표에 마우스를 올리면 보입니다. 100회차에서 멈춥니다. 방 멤버 기록의 `m.growth.lv`는 이제 이번 회차의 레벨이고 회차 `rd`를 더했습니다. 공개 프로필의 `level`은 평생 레벨입니다. 별 색 고르기는 무채색 디자인과 맞지 않아 넣지 않았습니다.
- 레벨 티어(GRW-07)는 무채색 디자인에 맞춰 색 대신 모양으로 나눕니다. 티어가 오를 때마다 경험치 바 굵기, 테두리, 반전, 빛, 광택, 바 빛이 차례로 더해져 모두 일곱 단계입니다. 티어가 오르는 레벨은 tunable `tierLevels`이고 기본값은 50, 100, 150, 200, 300, 500입니다. 친구 작업량을 보고 서버에서 바꿉니다.
- 달성표(GRW-06)는 보상 없이 하루 집중 목표 하나와 이번 주 요일별 표시만 둡니다. 목표는 등록 앱 하나가 아니라 오늘 전체 집중 시간이고 1시간부터 12시간까지 고릅니다. 목표를 바꾸면 오늘부터 적용하고 지난날은 그날 적어 둔 목표로 판정합니다. 목표와 날마다 기록은 서버 `mod/goals`에 두어서 다른 PC에서 열어도 같은 표가 보입니다. 오늘 목표를 채우는 순간 한 번 알립니다.
- 기록 미니 창(FOC-04)은 지금 이어서 작업한 시간과 오늘 합계 두 줄입니다. 위치는 다른 패널 창처럼 기억하고 항상 위에 띄우지는 않습니다.
- 포커스 기록 창 아래에 슬롯 `focus.drawer`를 열었습니다. 뽀모도로와 달성표가 이 슬롯에 자기 창을 여는 단추를 넣습니다.
- 뽀모도로(FOC-07)는 포커스 기록과 따로 돕니다. 프리셋은 25 / 5와 50 / 10이고 직접 고를 수도 있습니다. 진행 중인 타이머는 끝나는 시각으로 기기 범위 로컬 데이터에 남기므로 앱을 껐다 켜도 이어집니다. 단계가 끝나면 OS 알림과 스테이지 알림을 띄우고 소리는 소리 파일 없이 Web Audio로 짧게 냅니다. 돌고 있는 동안 남은 분을 presence로 보내고 머리 위 말풍선이 오늘 집중 시간 대신 남은 시간을 보입니다.
- 기기 간 공유(FOC-08)는 기기마다 자기 기록만 쓰는 지금 방식을 그대로 씁니다. 쓰는 기기가 아닌 PC는 시간을 세지 않습니다. 다른 기기가 가져가면 그때까지 센 기록을 바로 올리고 다시 쓰는 기기가 되면 다른 기기 기록을 다시 읽습니다. 오늘 집중 시간에는 같은 날 다른 기기의 오늘 기록을 더합니다. 그래서 낮에 노트북에서 작업하고 저녁에 데스크톱으로 옮겨도 오늘 시간과 레벨이 이어집니다. 앱을 끄거나 절전에 들어갈 때도 기록을 올립니다.
- 폰 연동(FOC-09)은 phone 모듈이 focus 공개 API `addSource`로 출처를 더하는 방식입니다. 출처가 켜져 있으면 focus는 등록 앱과 입력을 보지 않고 세며 샘플마다 한 번만 더하므로 PC와 폰을 함께 써도 겹쳐 세지 않습니다. tick의 `source`는 이제 pc이거나 출처 id입니다.
- 연결 키는 32자 무작위 문자열이고 `mod/phone/u/{uid}/key`에 두어 본인만 읽습니다. 폰 자동화 앱은 로그인 없이 `mod/phone/u/{uid}/sig.json`에 REST PUT으로 h, open, app, at을 씁니다. 규칙은 keyedWrite 템플릿을 쓰고 h가 저장한 키와 같고 PC 앱이 켜져 있을 때만 받습니다. at은 서버 시각이어야 합니다. 규칙이 해시를 계산하지 못하므로 키 문자열을 그대로 비교합니다. 열림 신호 하나는 4시간까지만 세고 앱 이름은 40자까지 머리 위에 보입니다. 키를 새로 만들면 예전 키로 보낸 신호는 무시합니다.
- 설정 창 폰 연결 탭의 QR은 안내 페이지 주소 뒤 # 에 uid와 키를 붙인 링크입니다. # 뒤의 값은 서버로 가지 않습니다. QR 인코더는 바이트 모드, 오류 정정 L, 버전 1부터 5까지만 만드는 짧은 코드로 모듈 안에 두었고 macOS 이미지 인식으로 읽히는지 확인했습니다. 106바이트를 넘는 링크는 QR 대신 링크 복사를 안내합니다.
- 안내 페이지는 저장소의 `hosting/phone/index.html` 정적 파일 하나입니다. Firebase Hosting에 올리면 `/__/firebase/init.json`에서 데이터베이스 주소를 읽고 다른 곳에 올리면 `?db=` 주소를 받습니다. 페이지 주소는 phone 모듈의 tunable `pageUrl`이고 기본값이 비어 있어서 선물하는 사람이 Hosting에 올린 뒤 정합니다. firebase.json에 hosting 설정을 더했습니다.
- 기간 한정 아이템(GCH-04)은 아이템마다 시작 날과 끝 날을 둡니다. 날짜는 오전 6시에 바뀌는 하루로 받고 끝 날은 그날 하루를 포함합니다. 기간 밖 아이템은 확률 계산에서 빠지고 가챠 창에 기간과 함께 따로 보입니다. 규칙도 서버 시각으로 기간을 확인해서 기간 밖 아이템은 보관함에 들어가지 않습니다. 기간은 아이템을 넣을 때 정하고 넣은 뒤에 바꾸는 화면은 두지 않았습니다.
- 색 해금(GCH-05)은 같은 아이템을 tunable `hueUnlockCount`(기본 4)개 모으면 꾸미기에서 그 스티커의 색조와 채도를 바꾸게 합니다. 1로 두면 처음부터 바꿀 수 있습니다. 10.9 예시처럼 해금 표시 hueOpen을 저장하지 않고 보관함 개수로 그때그때 계산해서 migration이 없습니다. 보관함은 진행도를 색 2/4처럼 보입니다. 내 그림으로 넣은 소품과 이미 바꾼 색은 막지 않습니다. 꾸미기 창(stickers 모듈)에 이 확인 몇 줄을 더했습니다.

## 알려진 한계

- 폰 신호는 계정 접속 기록의 online으로 PC 실행 중을 확인합니다. 오프라인으로 보이기(FRD-05)가 online을 쓰지 않게 되면 폰 신호도 거부되므로 그때 실행 중 표시를 따로 두어야 합니다.
- 폰 신호가 켜져 있어도 자동 자리비움(CHR-06)은 PC 입력만 봅니다. 10.9 메모처럼 폰 신호를 활동으로 세려면 status 모듈이 출처 상태를 읽어야 합니다.
- 단축어와 MacroDroid의 메뉴 이름과 순서는 실제 폰에서 확인하지 않았습니다. 실제 Firebase의 REST 쓰기와 안내 페이지의 교차 출처 요청도 확인하지 않았고 에뮬레이터 규칙 시험으로 로그인하지 않은 쓰기만 확인했습니다.
- 달성표 하루 기록은 1분마다 쓰므로 PC를 바꾼 직후 마지막 1분이 늦게 보일 수 있습니다.
- 쓰는 기기를 바꾸는 흐름은 메모리 서버와 시험에서만 확인했고 Firebase에서 두 PC로 확인하지 않았습니다.
- 뽀모도로가 앱을 껐다 켜도 이어지는지는 검증 하네스가 실행마다 데이터 폴더를 지워서 앱에서 확인하지 않았습니다.
