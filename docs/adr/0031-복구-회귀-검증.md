# 0031 저장 복구와 재시작 회귀 검증

날짜 2026년 10월 11일

정상 경로 외에 저장 실패, 앱 재시작, 여러 기능의 연결을 검증하도록 테스트와 verify 스킬을 확장했습니다.

## 추가한 검증

- `src/modules/gacha/sim.test.ts`: 저장이 실패하는 동안 기준이 바뀌고 작업이 추가되어도 당시 획득분을 보존합니다. 저장 응답 전에 다른 방으로 이동해도 새 방의 화면이나 기록을 덮지 않습니다.
- `src/modules/report/recovery.test.ts`: 서버 저장 실패 후 재연결, 저장 성공 후 ack 실패와 주기 재시도, 동시에 들어오는 알림을 검증합니다. appendOnly 쓰기를 흉내 내서 덮어쓰기로 중복 문제가 가려지지 않게 합니다.
- `tests/sim/work-recovery.test.ts`: 실제 phone·focus·status 모듈을 연결해 만료·키 교체·연결 해제와 수동 상태·잠금 우선순위를 확인합니다. 오전 6시를 가로지르는 활동 샘플로 focus·growth·goals·gacha를 함께 검증합니다.
- `tests/verification/errors.test.ts`: 예상하지 않은 오류, 기대 오류의 누락·초과, 정확한 횟수만 발생한 경우를 구분합니다.
- `tests/e2e/recovery.spec.mts`: 문서 앱 등록 → 작업 → 달성표·레벨·뽑기 → 저장 실패와 복구 → 보관함 → 꾸미기, 저장 후 정상 종료·재시작, 플레이리스트 핀과 숨김, 진단 저장 복구, 패널 오류 판정을 실제 Electron UI로 검증합니다. `drive.ts`의 ES 모듈을 재사용하므로 파일 확장자는 `.mts`입니다.

## 테스트로 확인하고 고친 문제

- 진단 보고는 매번 새 시각을 키로 사용해서 서버 저장 후 ack가 실패하면 재시도 때 중복 기록이 생길 수 있었습니다. `auto_<보고 ID>`를 키로 삼고 기존 기록의 내용을 확인한 뒤 ack합니다. 동시에 두 sync가 실행되지 않으며 온라인 복귀와 1분 주기로 다시 시도합니다. 웹훅 전송 재시도 정책은 바꾸지 않았습니다.
- 달성표는 오늘 합계만 조회해서 6시를 넘기는 마지막 전날 작업 구간을 저장하지 못했습니다. 기존 코드에서 회귀 테스트를 실행해 전날 기록이 null인 실패를 확인했습니다. focus가 날짜별로 나눈 tick을 받아 마지막 전날 합계를 저장하고 종료 시에도 같은 분 안의 추가 초를 보존합니다.

## verify 스킬

- 모든 창에 오류 수집기를 붙이고 예상하지 않은 오류는 자동 실패시킵니다. 의도한 오류는 `expectedErrors`에 정규식과 정확한 횟수를 사전에 지정합니다. 오류 주입 시험도 증거에 원문을 남깁니다.
- `s.restart()`는 같은 임시 데이터 폴더로 정상 종료하고 다시 실행합니다. 새 app·stage·launcher 참조를 돌려받고 세션 마지막에만 폴더를 정리합니다. 메모리 서버는 재시작마다 초기화됩니다.
- 성능 측정은 정상 정원 5좌석을 사용하고 유휴 1201초에 실제 `awake=false`를 확인한 뒤 잠든 상태를 측정합니다.
- 기능 지도에 복구 흐름을 연결하고 기본 뽑기·보관함·이모티콘을 미작성으로 적었던 목록을 정리했습니다. Windows의 실제 창 순서는 별도 체크리스트에 핀·모니터 분리·재시작 순서로 추가했습니다.

## 검증 범위

2026년 10월 11일 검증 결과:

- `npm run check`: 타입·lint·규칙 생성 일치 검사 통과, 일반 테스트 613개 통과(117개 제외). 에뮬레이터 전용 검사는 아래 실행으로 별도 확인했습니다.
- `npm run test:emulator`: 19개 파일, 165개 테스트 통과.
- E2E 빌드 후 `npx playwright test tests/e2e/recovery.spec.mts`: 4개 통과. 마지막 화면 테스트 수정 뒤 타입과 lint도 다시 통과했습니다.
- `measure.ts --soak 60`: 정상 종료. 5좌석 awake/잠듦 전이를 확인했고 패널 반복 개폐 뒤 구독은 28개로 복귀했습니다. 60초 실행의 0초·30초 표본 사이 GC 후 힙은 9.2MB로 같았습니다. 짧은 측정이므로 장시간 누수 검증을 대신하지 않습니다.
- 화면 증거: `work-reward-recovery-hRAx4X`, `restart-playlist-F8imlZ`, `report-recovery-xHHL62`; 측정 증거: `measure-BLJcui`. 현재 macOS 임시 폴더의 `isshoni-verify` 아래 보관됩니다.

가짜 플랫폼·메모리 서버·로컬 유튜브 대체 페이지를 사용한 E2E는 앱의 상태와 저장을 증명합니다. 실제 폰 자동화, Windows 창 합성 순서, 실제 유튜브 음성, 운영 Firebase·디스코드 전송을 증명하지 않습니다. 에뮬레이터 규칙 검증은 별도로 실행합니다. 공식 스킬 검사 스크립트는 환경에 PyYAML이 없어 실행하지 못했으며, 설치된 YAML 파서로 frontmatter와 참조 파일을 확인했습니다.
