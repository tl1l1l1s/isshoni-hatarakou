# 0004 M2b를 위한 코어 확장

날짜 2026년 10월 9일

10.3의 11번에 따라 채팅, 친구, 마이홈, 사운드 모듈이 함께 쓰는 범용 기능만 코어에 더했습니다.

## 정한 것

- `DocHandle.watchList(key, { limit, last }, fn)`를 더했습니다. key 아래 자식을 키 순서로 앞에서 limit개나 뒤에서 limit개만 구독하고 처음 한 번과 바뀔 때마다 부릅니다. 채팅 최근 100개처럼 계속 쌓이는 목록도 필요한 만큼만 내려받습니다. Firebase 구현은 `orderByKey`에 `limitToFirst`나 `limitToLast`를 붙인 질의를 쓰고 메모리 구현은 같은 순서로 잘라서 줍니다.
- `ctx.seats.refresh()`는 스테이지만 다시 그립니다. 좌석 목록은 바뀌지 않으므로 `ctx.room.onMembers`와 `ctx.seats.onChange`를 부르지 않습니다. 그래서 모듈이 이 구독 안에서 refresh를 불러도 호출이 되풀이되지 않습니다.
- `ctx.notify`는 메인 프로세스가 Electron `Notification`으로 띄웁니다. 렌더러가 알림마다 id를 붙여 `notify.show`로 보내고 사용자가 알림을 누르면 메인이 `notify.click`으로 같은 id를 돌려줍니다. 누를 때 부를 함수는 최근 50개만 기억합니다. Windows에서는 알림이 뜨도록 설치 프로그램과 같은 앱 ID를 `app.setAppUserModelId`로 정합니다.
- `keepAlive` 패널은 사용자가 창을 닫아도 메인 프로세스가 숨기기만 합니다. React portal이 남아 있어 재생이 이어지고 다시 열면 같은 창이 보입니다(SND-04 메모). `ctx.ui.close`와 ESC도 숨기기만 하고 모듈을 내리거나 앱을 끝낼 때만 실제로 닫습니다. 렌더러가 부르는 `window.close()`는 메인의 close 이벤트를 거치지 않고 바로 닫히는 것을 확인했습니다.
- 스테이지가 다시 읽히거나 다시 만들어지면 메인 프로세스가 열린 패널을 모두 닫습니다. 패널을 남겨 두면 다시 읽은 스테이지가 같은 이름으로 `window.open`을 부를 때 새 창 대신 숨은 옛 창을 돌려받습니다.
- `externalOrigins`는 `https://host[:port]` 형식만 받습니다. 렌더러가 부팅 첫 단계에서 모든 모듈의 출처를 모아 메인이 쓰는 목록과 비교하고 다르면 메인이 `device/csp.json`에 저장한 뒤 스테이지를 다시 읽습니다. 메인은 저장한 목록이 실제로 바뀔 때만 다시 읽으므로 같은 목록으로는 되풀이되지 않습니다. 목록이 비어 있으면 `frame-src`는 none입니다. about:blank 패널은 스테이지의 정책을 물려받아서 허용한 출처의 iframe만 열리는 것을 확인했습니다.
- 다른 사람 좌석을 누르면 그 좌석 위에 다른 사용자 메뉴(ROM-11)가 열리고 다시 누르면 닫힙니다. 항목은 `seat.menu` 슬롯에서 받고 명령은 args로 `{ uid, name }`을 받습니다. 메뉴가 열려 있는 동안 스테이지 창이 메뉴 높이만큼 커집니다. 메뉴는 내 좌석처럼 왼쪽 클릭으로 엽니다.
- rooms 모듈이 지금 있는 방 코드를 계정 접속 기록(`accountPresence`의 `code`)에 쓰고 방에서 나오면 지웁니다. 규칙상 친구만 읽으므로 친구 목록에서 방을 보고 따라 들어갈 수 있습니다.
- `win.prepare`의 `keepAlive`는 선택 인자로 더해서 `BRIDGE_VERSION`을 올리지 않았습니다.

## 확인하지 않은 것

- Windows에서 알림이 뜨는지와 누르면 `notify.click`이 오는지는 실제 기기에서 확인하지 않았습니다.
- 숨긴 `keepAlive` 패널 안의 YouTube 플레이어가 계속 재생되는지는 사운드 모듈이 들어온 뒤에 확인합니다.
