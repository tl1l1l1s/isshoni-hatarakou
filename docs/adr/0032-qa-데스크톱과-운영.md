# 0032 QA 데스크톱과 운영

날짜 2026년 10월 11일

QA 검토에서 코어 몫으로 나온 지적 가운데 데스크톱 연동, PC 데이터 보존, 운영 지적을 고쳤습니다. 고친 곳은 `src/main`, `src/preload/api.ts`, `src/shared/constants.ts`, `src/renderer/core`(`boot.tsx`, `main.tsx`, `bridge.ts`, `persist.ts`, `scope.ts`, `host.ts`, `runtime.ts`의 로그와 오류 경로, `types.ts`의 `ctx.net`, `ui/windows.ts`, `ui/Stage.tsx`의 몸 끌기와 메뉴 높이, `coreSettings.ts`와 `coreModule.tsx`의 화면 탭 항목), `scripts/ops.ts`, `scripts/set-min-protocol.ts`, `.github/workflows/release.yml`, `tests/e2e/upgrade.spec.ts`와 그 고정값, 검증 하네스(`measure.ts`, `osclick.ts`, `click.swift`, `SKILL.md`, 지도), 명세 몇 줄, Windows 점검표입니다.

## 패널 창이 앞 앱을 바꾸지 않음

- 패널을 `show: true`로 만들면 포커스를 받지 않는 창도 Mac에서 앱을 앞으로 가져와 작업 앱이 키 입력을 잃었습니다. 친구 신청, 6시간 자리비움 안내, 업데이트 소식, 캐릭터 맞추기처럼 모듈이 저절로 여는 창도 같았습니다.
- 이제 패널은 숨긴 채 만들고 `did-create-window`에서 `showInactive`와 `moveTop`으로 맨 위에 보이기만 합니다. 사용자가 연 창이고 포커스를 받는 창일 때만 `focus()`를 부릅니다. 이미 열린 창을 다시 열 때(`win.show`)도 같은 규칙입니다.
- 사용자가 열었는지는 렌더러 코어가 정합니다. 실행 화면을 누른 것과 OS 알림을 누른 것은 `touch('')`가 시각을 남기고 그 뒤 5초 안에 여는 창은 사용자가 연 창입니다. 패널 안에서 누르거나 키를 친 것은 패널 문서의 `navigator.userActivation.isActive`로 봅니다. 모듈은 바꿀 것이 없습니다. 메뉴, 칩, 버튼마다 표시를 넘기는 방법은 명령 실행 경로 전체를 고쳐야 해서 쓰지 않았습니다.
- 설정 코드 창은 앱을 처음 켠 사람이 바로 코드를 붙여 넣도록 늘 포커스를 받습니다. 런처는 켤 때 저절로 열리므로 포커스를 받지 않고 맨 위에만 뜹니다. 로그인할 때 자동 실행으로 켜져도 하던 일의 키보드를 뺏지 않습니다.
- ponytail: 사용자 입력 뒤 5초 안에 저절로 열린 창은 사용자가 연 창으로 봅니다. 드문 일이라 그대로 둡니다.
- 시작하기로 런처가 닫힌 뒤 Mac에서 앱이 키 창 없이 앞에 남는 것은 고치지 않았습니다. Electron에는 앱을 비활성으로 돌리는 API가 없고 `app.hide()`는 실행 화면까지 숨깁니다.

## 패널이 작업 영역에 맞음

- 메인의 `setWindowOpenHandler`가 기억한 자리가 있으면 그 자리의 모니터, 없으면 캐릭터 모니터의 작업 영역을 읽습니다. 폭은 작업 영역 폭까지, 높이는 작업 영역 높이에서 제목 표시줄 32를 뺀 만큼까지로 줄이고 자리를 `clampIn`으로 작업 영역 안에 맞춥니다. 기억한 자리가 없으면 `center: true` 대신 캐릭터 모니터 가운데에 둡니다. `body.panel`이 창 높이이고 스크롤하므로 줄어든 창은 안에서 스크롤합니다.
- 렌더러에서 `screen.availHeight`로 줄이는 방법(사진 창 제안)은 쓰지 않았습니다. 메인 한 곳에서 모든 창을 맞추는 쪽이 짧고 기억한 자리까지 함께 맞춥니다.
- 작업 영역 853x432(1280x720 150%)에서 `▼` 메뉴가 세 줄만 보이던 것은 두 가지로 고쳤습니다. 메뉴가 다섯 줄은 보이도록 좌석 배율을 고를 때 작업 영역 높이에서 그만큼을 빼고 메뉴에 `::-webkit-scrollbar`를 주어 Mac에서도 스크롤 막대가 늘 보입니다. 1366x768 100%와 그보다 큰 화면에서는 배율이 바뀌지 않습니다.

## 클릭 통과, 끌기, 좌석 수 변화

- 캐릭터 위에 머물던 커서나 펜을 옆 빈 자리로 옮겨 바로 누르면 다음 50ms 확인까지 실행 화면이 그 클릭을 받았습니다(desktop-click-eaten). 확인 주기를 고정 `setInterval`에서 `setTimeout`으로 바꾸고 커서가 스테이지에서 40픽셀 안이면 8ms, 멀면 50ms 뒤에 다시 봅니다. 상수는 `CURSOR_POLL_NEAR_MS`입니다. 렌더러의 pointermove로 바로 알리는 방법은 IPC와 렌더러 코드가 더 들어서 쓰지 않았습니다. 같은 이벤트 안의 경쟁은 그대로 남습니다.
- 캐릭터 몸을 끌면 이름표처럼 실행 화면이 옮겨집니다(F8). 흔들기와 나누려고 누른 곳에서 12px 넘게 움직였고 방향을 바꾼 적이 없을 때 세로로 더 많이 움직였거나 누른 지 0.2초가 지났으면 끌기로 봅니다. 끌기로 본 뒤에는 흔들기를 세지 않고 짧게 누른 것으로도 보지 않습니다. `useDrag`에 시작 조건 함수를 더해 같은 처리를 씁니다. `.hit`에 `touch-action: none`을 주어 Windows 펜 끌기가 스크롤 몸짓으로 빠지지 않습니다.
- 좌석이 늘거나 줄어 실행 화면 폭만 바뀌면 왼쪽 끝을 그대로 둡니다(social-join-jump). 아래 가운데에 다시 맞추면 맨 왼쪽의 내 캐릭터가 누가 들어오고 나갈 때마다 80px씩 뛰었습니다. 그 자리는 이번 실행 동안만 메모리에 두고 끌어 둔 자리 파일에는 쓰지 않습니다. 파일에 쓰면 방에 한 번 들어간 것만으로 다음 실행의 자리가 바뀌기 때문입니다. 끌기, 위치 초기화, 모니터 고르기가 이 자리를 지웁니다. 새 좌석의 나타남 효과는 다른 코어 묶음과 같은 CSS를 고치게 되어 넣지 않았습니다.
- 끌어 둔 자리의 키를 고른 모니터의 고를 때 id로 바꿨습니다(desktop-place-display-id). Windows가 다시 꽂은 모니터에 새 id를 주어도 `pickDisplay`가 지문으로 찾은 모니터의 자리를 그대로 씁니다. 고른 모니터가 아닌 모니터는 지금처럼 그 모니터 id입니다. 순수 함수 `placeKey`와 시험이 `display.ts`에 있습니다.

## 전체 화면 앱 위에서 숨기기 (D1)

- 화면 탭에 `전체 화면 앱 위에서 숨기기`를 더했고 기본값은 켜짐입니다(`coreSettings.coverHide`, 새 채널 `stage.coverHide`).
- 500ms 활동 샘플이 `get-windows`의 앞 창 영역을 함께 넘깁니다. Windows는 물리 픽셀이라 `screen.screenToDipRect`로 바꾸고 Mac은 그대로 씁니다. 렌더러에는 보내지 않습니다.
- 메인은 앞 창 영역이 캐릭터 모니터 영역과 1px 안에서 같고 앞 앱이 그림 앱이 아니고 이 앱이 아닐 때 스테이지만 숨깁니다. 덮는지가 아니라 같은지를 보는 것은 최대화한 창이 테두리만큼 모니터보다 커서 작업 표시줄을 자동으로 숨긴 PC에서도 덮는 창으로 잡히기 때문입니다. 패널은 숨기지 않습니다.
- 사용자가 숨긴 값(`hidden`)과 따로 둡니다. 실제로 보이는지는 두 값과 설정으로 정하고 바뀌면 `stage.visibility`를 보냅니다. 렌더러는 지금처럼 표시 모드 `hidden`이 되어 그리기를 멈추고 새 효과를 열지 않습니다. 숨은 동안 사용자가 보이기(트레이, `Ctrl+Alt+H`, 다시 실행, 위치 초기화)를 하면 그 전체 화면이 끝날 때까지 보입니다. 사용자가 숨긴 화면은 전체 화면이 끝나도 숨은 채입니다.
- ponytail: 앞 창은 입력이 2초 넘게 없으면 5초마다만 읽으므로 입력 없이 앞 창이 바뀌면 5초까지 늦게 압니다(`lessForeground`). 전용 전체 화면 게임에서 이 영역이 모니터와 같은지는 Windows 점검표로 봅니다.

## Mac

- Mac 실행 화면을 누르면 앱이 앞으로 와서 작업 앱이 키 입력을 잃습니다(desktop-mac-click-activates). `type: 'panel'`과 `focusable: false`로는 막히지 않는 것을 Electron 44.4.5와 macOS 26에서 다시 확인했습니다. 막으려면 창 핸들로 `NSWindowStyleMaskNonactivatingPanel`을 주는 네이티브 도우미가 필요한데 이번에는 의존성을 더할 수 없어 넣지 않았습니다. NFR-03과 10.8.1에 알려진 문제로 적고 Mac은 개발판으로 둡니다.
- `osclick.ts`의 앞 앱 확인은 가짜 플랫폼의 보통 창을 눌러 앞 앱이 이미 이 앱일 때 통과하던 거짓 통과였습니다. 이제 실제 Mac 오버레이 옵션의 창을 띄우고 Finder를 앞에 둔 채 누른 뒤 1초 동안 `lsappinfo front`를 보고 그 창이 클릭을 받았는지도 확인합니다. 지금은 실패로 적히는 참고 항목입니다.
- Mac 그림 앱 기본 목록을 넣었습니다. 클립 스튜디오(`jp.co.celsys.CLIPSTUDIOPAINT`), 포토샵, 일러스트레이터, 크리타, 파이어알파카, Aseprite, 블렌더의 번들 ID이고 공개된 앱 정보로 확인한 것만 넣었습니다. 설치한 Mac에서 직접 읽어 보지는 않았습니다.
- NFR-01에 지원하는 가장 낮은 버전을 적었습니다. Windows 10 x64와 macOS 13입니다.

## 잠금과 절전

- 잠금과 절전이 같은 상태 출처 `core.sleep`을 써서 잠근 채 절전했다 깨어나면 잠금 화면에 있는 동안 접속 중으로 보였습니다. 잠금은 `core.lock`, 절전은 `core.sleep`으로 나눴습니다.

## OS 알림 소리 (F3, D5)

- OS 알림을 모두 `silent: true`로 만듭니다. 소리는 앱의 알림음이 채팅 알림음 설정과 회사원 모드를 따라 냅니다. 회사원 모드에서 OS 알림을 띄우지 않는 것(D4)과 채팅 알림 횟수(D5)는 다른 코어 묶음이 맡습니다.

## PC 데이터

- JSON은 맞지만 모양이 다른 설정 파일(예를 들어 `{}`, `modules: null`)로 켜면 `시작하지 못했습니다`에서 멈췄습니다(RES-5). `JsonFile.load`가 검사 함수를 받고 맞지 않으면 메인에 새 채널 `store.quarantine`으로 그 파일을 `.bak`으로 옮기게 한 뒤 처음 값으로 시작합니다. 깨진 JSON을 옮기는 `readJson`과 같은 이름입니다. `settings.json`, `accounts/<uid>/settings.json`은 `isSettingsFile`, `device/core.json`은 `deviceId`가 문자열인지로 봅니다.
- 모듈 로컬 파일이 검사에 실패하면 알림에 zod 오류 글을 붙이던 것을 고쳤습니다(RES-6). 알림은 `<모듈 이름> 데이터를 읽지 못해 처음 상태로 시작해요.`이고 자세한 이유는 메인 로그에 `local <scope>:` 줄로 남깁니다.
- 앱보다 새 버전이 쓴 모듈 파일은 덮지 않습니다(OPS-10). `readLocal`이 `tooNew`를 돌려주면 그 파일은 `readOnly` `JsonFile`로 만들어 이번 실행에서 바꾼 것을 쓰지 않고 `.bak.json`도 만들지 않습니다. 알림은 `<모듈 이름> 데이터는 새 버전 앱이 저장한 거라 읽지 못했어요. 업데이트할 때까지 바꾼 내용은 저장하지 않아요.`입니다. 그래서 출시판을 되돌린 뒤 고친 판이 오면 새 형식 파일을 그대로 읽습니다. `.bak.json`에서 되살리는 길은 넣지 않았습니다. 이제 새 형식 파일은 덮이지 않고 남은 `.bak.json`은 검사에 실패한 값이라 되살릴 것이 없습니다.
- 출시 규칙(README의 출시 절차에 넣을 문장)입니다. manifest의 local, settings, server 버전 번호가 지난 출시보다 낮은 판은 내지 않고 되돌릴 때는 코드만 되돌리고 버전 번호와 migration은 남깁니다. README는 이번에 고치지 않아 여기 적어 둡니다.
- 메인의 쓰기 모으기를 파일마다 정합니다(RES-7, perf-3). 설정과 작은 파일은 0.2초, 1초마다 바뀌는 `accounts/*/modules/focus.json`만 15초입니다. 종료, 절전, 로그오프의 동기 flush는 그대로라 그때는 바로 씁니다. 바꾼 설정을 잃는 틈이 1초에서 0.2초로 줄고 집중 시간을 쓰는 동안 디스크 쓰기는 1분에 56번에서 4번으로 줄었습니다. 갑자기 꺼지면 집중 시간은 15초까지 잃습니다.

## 로그, 자동 오류 보고, 성능

- 메인 로그가 평소에 비어 있어 비정상 종료 보고에 붙는 로그 끝이 비었습니다(OPS-1). 상태가 바뀔 때만 한 줄씩 남깁니다. 켤 때 버전과 OS, 끌 때, 부팅이 끝나고 서버 종류와 꺼진 모듈, 서버 연결과 끊김, 방에 들어가고 나온 것과 까닭, 패널 창을 연 것입니다. 방과 연결 줄은 다른 코어 묶음이 고치는 `runtime.ts` 대신 `boot.tsx`에서 구독합니다.
- 부팅이 실패하면 `main.tsx`가 `reportError(getBridge(), 'renderer.boot', e)`를 부릅니다(OPS-2). preload가 없을 때 메인이 따로 알아채는 일은 넣지 않았습니다.
- 모듈 이벤트 처리 오류는 Bus가 `renderer.event` 보고로, 모듈을 내릴 때의 정리 오류는 Scope가 `renderer.dispose` 보고로 보냅니다(OPS-4). `Scope`는 생성자에서 오류 처리 함수를 받고 `ModuleHost`가 모듈 id를 붙여 넘깁니다.
- 한도 때문에 보내지 않은 보고를 종류마다 `device/crash.json`의 `skipped`에 세고 다음에 보내는 보고의 셋째 줄에 `그동안 생략한 보고 <종류> x<수>`로 붙인 뒤 비웁니다(OPS-8). 같은 줄이 진단 요약에도 들어갑니다. 5분 간격을 서명마다 두는 것은 넣지 않았습니다.
- 진단 요약에 프로세스별 메모리와 CPU 시간 줄을 넣었습니다. 30분마다 프로세스별 메모리와 그동안의 평균 CPU(코어 하나 기준, `cumulativeCPUUsage` 차이)를 로그에 한 줄 남기고 평균 CPU가 20%를 넘거나 렌더러 메모리가 500MB를 넘으면 `perf` 보고를 냅니다. 보고 첫 줄이 같아 한 실행에 한 번만 갑니다.
- 업데이트 받기 실패가 처리하지 않은 거절이 되어 첫 보고 자리를 차지하던 것을 고쳤습니다(OPS-9). `checkForUpdates`가 돌려준 `downloadPromise`에도 `catch`를 붙입니다. 실패 내용은 `error` 이벤트가 진단 요약과 로그에 남깁니다.

## 기기 버전 기록 (OPS-7)

- 앱이 켤 때와 업데이트 상태가 바뀔 때 `users/{uid}/private/devices/{deviceId}`에 `{ ver, proto, upd, at }`를 씁니다. `private`은 본인만 읽고 쓰는 자리라 규칙은 바꾸지 않았습니다. 업데이트 상태는 `update.state`의 새 `status`와 새 이벤트 `update.status`로 받습니다.
- `node scripts/ops.ts versions`가 사람마다 기기 기록을 한 줄씩 보여 줍니다. `scripts/set-min-protocol.ts`는 바꾸기 전에 같은 목록을 보여 주고 낮은 프로토콜의 기기가 있으면 `--force` 없이는 바꾸지 않습니다. 친구 몇 명 규모라 `users`를 한 번에 읽습니다.

## 출시 검사와 업그레이드 시험 (OPS-5)

- release는 첫 단계에서 같은 커밋의 `ci` 실행이 성공했는지 `gh run list --commit`으로 확인하고 진행 중이면 1시간까지 기다립니다. 실패했거나 없으면 멈춥니다. lint, 규칙 빌드 확인, 에뮬레이터 규칙 시험, Windows e2e를 release에 다시 적는 것보다 짧고 Java 준비도 필요 없습니다. `actions: read` 권한을 더했습니다.
- `tests/e2e/upgrade.spec.ts`는 `tests/e2e/fixtures/userdata-v0.1.0`의 데이터 폴더로 앱을 켭니다. 아직 출시한 판이 없어서 지금 형식(v0.1.0)으로 사용자가 이름, 테마, 상태칩 자리, 집중 앱, 캐릭터, 플레이리스트를 바꾼 데이터 폴더의 JSON만 담았습니다. 알림은 4초 뒤 사라지므로 `.bak` 파일과 메인 로그의 읽기 오류 줄이 없는지로 보고 설정, 이름, 집중 앱, 캐릭터, 플레이리스트가 그대로인지 봅니다. 날짜가 바뀌면 달라지는 오늘 기록은 보지 않습니다. 형식을 바꾸는 출시마다 고정값 폴더를 하나씩 더합니다.

## 새 코어 계약

- `ctx.net.get(url): Promise<{ ok: boolean; status: number; json: unknown }>`는 메인이 허락한 주소에서만 JSON을 읽습니다. 지금은 `https://www.youtube.com/oembed?url=<영상 주소>&format=json`뿐이고 다른 주소, 10초 넘김, 64KB 넘김, 다른 곳으로 넘기는 응답은 예외입니다. 렌더러 CSP는 그대로입니다. 플레이리스트 곡 제목에 쓰도록 마이홈과 소리 묶음이 요청한 계약입니다.
- 브리지 채널은 `store.quarantine`, `net.get`, `stage.coverHide`, 이벤트 `update.status`를 더했고 `win.prepare`와 `win.show`에 `user?`, `update.state` 결과에 `status?`를 더했습니다. 기존 모양은 그대로라 `BRIDGE_VERSION`은 바꾸지 않았습니다.

## 측정 도구와 하네스

- `measure.ts`의 잠듦 상태는 유휴 600초여서 집중 시간 규칙(20분)에 걸리지 않은 내 좌석이 깨어 있었습니다(perf-2). 유휴를 20분 넘게 두도록 바꿨습니다. 같은 문제를 먼저 고친 0031과 합치면서 유휴 1201초로 두고 내 좌석이 잠든 것을 확인한 뒤 잽니다. 깨어 있는 친구 좌석이 레벨 티어 5라 배지가 광택을 낼 때의 상태를 더했습니다(perf-1). 이 Mac에서 친구 4명이 광택을 내면 CPU가 36.6%였고 광택 없이 1%였습니다. 배지 광택은 다른 묶음이 고칩니다.
- 방 정원이 5명이 된 뒤(ADR 0026) `measure.ts`의 10좌석 상태는 정원을 넘겨 내 앱이 방에서 나와 멈췄습니다. 정원까지 채운 5좌석으로 바꿨습니다.
- `osclick.ts`에 캐릭터에서 옆 빈 자리로 옮겨 20ms 뒤 누르기, 몸 끌기, 위의 Mac 활성화 확인을 더했습니다. 6번 앞에서 3번에서 연 상태 고르기 창을 닫아 옮긴 뒤 빈 자리 클릭을 덮지 않게 했습니다. 방에 들어가면 실행 화면이 아래 가운데가 아니므로 위치 초기화는 작업 영역 아래 가운데와 비교합니다. `click.swift`는 옮긴 뒤 기다릴 밀리초를 받습니다.

## 날짜 칸의 한국어 형식

- 영어 macOS에서 날짜 칸이 mm/dd/yyyy로 보였습니다(ux gacha-validation의 코어 몫). 앱 글이 한국어뿐이라 메인이 ready 전에 `app.commandLine.appendSwitch('lang', 'ko')`를 겁니다. 이 Mac에서 날짜 칸이 `2026. 10. 31.`로 보이고 `navigator.language`가 `ko`입니다. Windows에서도 같은 스위치로 렌더러 언어가 정해지는 것으로 알고 있고 확인하지 않았습니다.

## 앱을 쓰는 사람 수 문구

- 두 친구나 두 사람이 쓰는 앱처럼 적힌 문장을 실제 모델로 바꿨습니다. 선물하는 사람이 설정 코드로 계정을 발급한 친구 몇 명이 쓰고 방에는 2명부터 5명까지 들어갑니다. ADR 0009, 0010, 0013, 0015, 0019의 까닭 문장, 9장 9.2의 1행과 정원 줄, 10장의 정원 줄과 사진 한도 줄, photo 모듈 주석입니다. ADR의 결정은 바꾸지 않았습니다.

## 확인한 것

- 검증 하네스에서 확인했습니다. 메뉴로 연 창만 포커스를 받고 저절로 연 창은 앞 앱을 바꾸지 않는 것, 전체 화면 숨기기와 그림 앱, 최대화 창, 보이기, 사용자 숨김, 설정 끄기, 작업 영역 853x432에서 창 다섯 개와 메뉴, 좌석 수가 바뀌어도 내 이름표 화면 x가 같은 것, 다른 id로 다시 꽂은 모니터의 끌어 둔 자리, 잠금과 절전 상태, OS 알림의 `silent`, 모양이 다른 설정 파일과 검사에 실패한 파일과 새 버전 파일, 부팅 실패와 이벤트 오류 보고, 생략 수와 진단 줄, 상태 로그, 기기 버전 기록, `net.get`, 날짜 칸, 설정을 바꾸고 0.3초 뒤 kill -9 해도 남는 것, 1분 동안 `focus.json` 쓰기 4번입니다.
- `osclick.ts`로 옆 빈 자리 20ms 클릭 통과 5번 가운데 5번(머리 위와 몸 옆), 몸 끌기 이동과 쓰다듬지 않음, 이름표 끌기와 위치 초기화를 확인했습니다. 업데이트 받기 실패는 같은 `NsisUpdater`를 개발판 메인에서 옛 호출 모양과 새 모양으로 돌려 옛 모양만 처리하지 않은 거절을 남기는 것을 확인했습니다.

## 확인하지 않은 것

- Windows에서 전체 화면 영상, 테두리 없는 게임, 전용 전체 화면 게임, 클립 스튜디오 전체 화면, 작업 표시줄 자동 숨기기의 최대화 창, 펜을 들어 옆 캔버스에 내리는 첫 점, 펜으로 몸 끌기, 저절로 열린 창과 키 입력, 150% 작은 화면, OS 알림 소리, 잠근 채 절전, 다시 꽂은 모니터, 업데이트 받기 실패와 기기 기록, 날짜 칸 형식은 `docs/checklists/windows-m0.md`에 더한 항목으로 봅니다.
- release의 ci 확인 단계는 실제 태그로 돌려 보지 않았습니다. `scripts/ops.ts versions`와 `set-min-protocol.ts`의 목록은 에뮬레이터로만 돌렸습니다.
- 30분 자원 줄과 `perf` 보고는 시간이 걸려 앱에서 기다려 보지 않았습니다.
