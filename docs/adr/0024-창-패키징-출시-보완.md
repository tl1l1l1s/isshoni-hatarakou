# 0024 창, 패키징, 출시 보완

날짜 2026년 10월 9일

Windows와 Mac 점검(O1부터 O16), 리뷰의 M9, M10, M11, M13, Codex 검토 4번에서 나온 메인 프로세스, 창, 패키징, 출시 문제를 고쳤습니다. 기능 명세는 바꾸지 않았습니다. 고친 곳은 `src/main`, `src/preload/api.ts`의 주석, `src/renderer/core/ui/windows.ts`, `electron-builder.yml`, `package.json`, `.github/workflows/release.yml`입니다.

## 정한 것

- 출시 (O1, O14). release.yml은 electron-builder를 `--publish never`로 돌려 파일만 만들고 `gh release create` 한 번으로 exe, blockmap, latest.yml을 함께 올립니다. v0.1.1에서는 electron-builder가 파일을 나눠 올리다가 같은 태그의 릴리스가 둘 생겼습니다. electron-builder.yml의 publish 설정은 남겨 둡니다. 설치 파일 안의 app-update.yml이 이 설정으로 만들어집니다. 빌드 앞에는 저장소 변수 `VITE_FIREBASE_DATABASE_URL`이 비어 있으면 실패하는 단계를 두었습니다. 코드에서 실제 서버 없는 출시 빌드를 막는 검사(리뷰 M15)는 렌더러 쪽 일이라 이 작업에 넣지 않았습니다.
- 이름 고정 (O3). `nsis.guid`를 `75a0e9d7-a3e3-5c7d-830a-621e2290b363`으로 고정했습니다. electron-builder가 지금 appId `app.isshoni-hatarakou.gift`에서 만드는 UUID v5 값입니다. 내려받은 v0.1.1 설치 파일의 NSIS 헤더를 풀어서 제거 정보 레지스트리 키에 같은 값이 들어 있는 것을 확인했습니다. 데이터 폴더도 `app.setPath('userData', ...)`로 지금 폴더 이름 `isshoni-hatarakou`에 고정했습니다. 앞으로 productName이나 appId를 바꿔도 같은 앱으로 덮어 설치되고 설정, 저장 파일, Firebase 로그인이 남습니다. 단일 실행 잠금이 이 폴더에 생기므로 잠금보다 먼저 정합니다. 시험처럼 `--user-data-dir`로 켜면 고정하지 않습니다.
- 패널 다시 열기 (O2, O10, M9). 이미 열린 패널을 다시 열면 렌더러는 `win.show`로 메인에 맡기고 메인은 `showInactive`와 `moveTop`으로 창을 맨 위에 올립니다. 포커스를 받는 패널은 이어서 `focus`를 부릅니다. 화면 숨기기에서 돌아올 때 함께 숨겼던 패널도 같은 방법으로 올립니다. Windows에서 포커스를 받지 않는 창은 렌더러의 `focus()`로 앞에 오지 않아서 그림 앱 뒤에 남았습니다. 숨긴 keepAlive 패널을 다시 열 때 창 위치가 지금 모니터 작업 영역 밖이면 가운데로 옮깁니다. 같은 창을 빠르게 두 번 열면 첫 호출이 끝날 때까지 두 번째 호출은 아무것도 하지 않습니다.
- 모니터 배율 (O4). 스테이지와 효과 창의 위치를 정한 뒤 다시 읽어서 다르면 한 번 더 정합니다. 배율이 다른 모니터로 옮길 때 Windows의 DPI 변경 처리가 크기를 바꾸는 경우를 위한 것입니다.
- 전역 ESC (O6, M10). 등록과 해제를 메인의 `pickEscape` 하나로 모았습니다. 등록한 ESC는 10초 뒤 스스로 풀리고 스테이지가 다시 읽히거나 충돌 뒤 다시 만들어질 때도 풀립니다.
- 자동 실행 (O7). Windows에서는 `getLoginItemSettings`의 `executableWillLaunchAtLogin`을 읽습니다. 사용자가 Windows 설정이나 작업 관리자의 시작 앱에서 끈 것까지 반영합니다. 설정 창은 시작할 때 이 값을 읽어 체크 상자를 맞춥니다.
- 의존성 (O8). firebase, react, react-dom을 devDependencies로 옮겼습니다. e2e 빌드의 `out/main/index.js`는 electron, electron-log, electron-updater, zod, get-windows만 부르고 `out/preload/bridge.js`는 electron만 부릅니다. 세 패키지는 Vite가 렌더러에 묶으므로 설치 파일의 node_modules에 따로 넣을 필요가 없습니다. 잠금 파일은 `npm install --package-lock-only --ignore-scripts`로 고쳤고 dev 표시만 바뀌었습니다.
- 트레이 (O9). Windows에서 트레이 아이콘을 왼쪽 클릭하면 보이기와 숨기기를 바꿉니다. 저장소에 아이콘 그림 파일이 없어서 지금의 원을 16, 24, 32px 세 크기로 그려 넣고 배율마다 맞는 크기를 쓰게 했습니다. 가장자리 픽셀은 원이 덮은 만큼만 칠합니다.
- Mac (O11, O12, O13). 숨기기 단축키는 두 OS 모두 Control+Alt+H입니다. Mac의 Cmd+Option+H는 다른 앱 가리기라서 겹쳤습니다. Windows에서는 전과 같은 Ctrl+Alt+H입니다. 일부 유럽 자판에서는 AltGr이 Ctrl+Alt로 들어가 AltGr+H와 겹치지만 친구들이 쓰는 한국어 자판에는 AltGr이 없어서 그대로 둡니다. Mac 메뉴는 앱 메뉴와 편집 메뉴만 둡니다. 기본 메뉴의 Cmd+R이 about:blank 패널을 다시 읽어서 비웠습니다. 편집 메뉴는 입력란의 복사와 붙여넣기 단축키에 필요합니다. 트레이 앱이라 Dock 아이콘을 숨기고 Finder로 다시 열면 숨긴 스테이지를 보입니다. dmg는 Intel과 Apple 실리콘에서 모두 켜지는 universal 하나로 만듭니다. get-windows의 Mac 보조 실행 파일은 이미 두 아키텍처를 함께 담고 있습니다.
- 앞에 있는 앱 조회 (O13, Codex 4번). 활동 샘플은 전처럼 0.5초마다 만들고 유휴 시간도 매번 읽습니다. 앞에 있는 앱은 입력이 2초 넘게 없으면 5초마다만 다시 묻고 그 사이에는 앞 결과를 씁니다. 앞에 있는 앱은 거의 언제나 입력이 있어야 바뀌므로 입력이 있는 동안은 전처럼 매번 묻습니다. Mac은 물을 때마다 보조 프로세스를 띄우므로 1.5초에 한 번까지만 묻습니다. 숨긴 스테이지는 커서 위치를 읽지 않습니다. 집중 시간 계산과 그림 앱 판정 코드는 바꾸지 않았습니다. 시험용 가짜 플랫폼에는 이 줄이기를 넣지 않아서 시험이 바꾼 앞 앱이 바로 보입니다.
- 하드웨어 가속 (O16). 데이터 폴더에 `no-gpu` 파일이 있거나 환경 변수 `ISSHONI_NO_GPU=1`이 있으면 시작할 때 하드웨어 가속을 끕니다. 진단 요약에 하드웨어 가속 꺼짐 줄이 들어갑니다. 설정 창의 체크 상자는 렌더러 코어를 고쳐야 해서 넣지 않았습니다.
- 로그오프 저장 (M11). Windows는 `session-end` 처리기가 끝나면 언제든 프로세스를 끝내므로 그 안에서 렌더러의 IPC를 기다릴 수 없습니다. 그래서 앞서 오는 `query-session-end`에서 트레이의 종료와 같은 길로 끝내기 시작합니다. 렌더러가 1초 지연 쓰기를 메인으로 보내고 앱을 끝냅니다. 그 전에 `session-end`가 오면 메인이 받아 둔 쓰기를 동기로 쓰고 바로 끝냅니다.
- 권한 (M13). 모든 웹 권한 요청을 거절합니다. 앱이 쓰는 웹 권한은 없습니다. 알림과 클립보드는 메인이 Electron API로 직접 합니다. 유튜브 iframe의 encrypted-media 요청도 거절되지만 Electron에는 Widevine이 없어서 원래 쓸 수 없습니다.

## 로그오프 저장 다시 (Codex 검토 6번)

M11의 고침은 `query-session-end`가 렌더러의 1초 지연 쓰기를 받아 오기를 기대했습니다. Windows는 그 뒤 언제든 `session-end`를 보내고 처리기가 끝나면 프로세스를 끝내므로 1초 안에 바꾼 설정은 그래도 사라질 수 있었습니다.

- 렌더러의 `JsonFile`은 1초 지연을 없애고 같은 틱의 변경만 모아 바로 메인에 보냅니다. 슬라이더처럼 초당 수십 번 바뀌는 값도 이벤트마다 한 번만 보냅니다. 그리기는 저장 단추를 눌러야 로컬 파일에 쓰므로 그대로입니다.
- 메인의 `store`는 전처럼 파일마다 마지막 값을 들고 있다가 1초 뒤에 원자적으로 쓰고 `will-quit`, `session-end`, 절전과 종료의 lifecycle 처리기에서 동기로 다 씁니다. 디스크 쓰기 횟수는 전과 같고 메인이 값을 드는 시점만 1초 앞당겨졌습니다.
- `query-session-end`는 전처럼 트레이 종료와 같은 길로 끝내기 시작합니다. 모듈이 shutdown에 저장하는 값을 받기 위해서입니다. `session-end`는 들고 있는 값을 쓰고 바로 끝냅니다.
- IPC 계약은 바뀌지 않아 `BRIDGE_VERSION`은 그대로입니다. `src/renderer/core/persist.test.ts`가 같은 틱의 변경이 한 번에 바로 가는 것을 확인합니다.
- 이 Mac에서 테마를 바꾸고 바로 메인에서 `query-session-end`를 내면 0.3초 안에 끝나고 settings.json에 바꾼 테마가 있습니다. 확인 단계 없이 `session-end`만 내도 0.1초 안에 끝나고 같은 값이 있습니다. 전에는 두 번째 경우에 테마가 사라졌습니다.

## 작은 화면 맞춤, 미리보기 배율, 집중 기록 저장 (Codex 검토 3, 5, 6, 7번)

- 작업 영역 맞춤 (3번). 1080p 150%(1280x720 DIP)에서는 항목 13개짜리 ▼ 메뉴를 연 스테이지가 900 DIP 가까이 되고 좌석 10개 줄은 1616 DIP라 화면 밖으로 나갔습니다. 메인은 `stage.workArea` 호출에 캐릭터가 있는 모니터의 작업 영역 크기를 돌려주고 `place`에서 그 크기가 마지막으로 알린 것과 다르면 같은 이름의 이벤트로 알립니다. 두 채널은 더한 것이라 `BRIDGE_VERSION`은 그대로입니다. 스테이지는 좌석 줄을 설정한 배율로 잰 뒤 작업 영역보다 넓거나 높으면 들어갈 배율로 줄여 다시 잽니다 (`src/renderer/core/seats.ts`의 `fitScale`). 좌석을 두 줄로 나누는 대신 배율을 줄인 이유는 클릭 영역, anchor, 효과 좌표가 모두 배율 하나에서 나와서 따로 고칠 것이 없기 때문입니다. ▼ 메뉴와 다른 사용자 메뉴는 작업 영역에 남는 높이까지만 커지고 넘치는 항목은 메뉴 안에서 스크롤합니다. 작업 영역을 아직 받지 못한 첫 그리기는 전처럼 설정한 배율로 잽니다.
- 미리보기 배율 (5번). canvas2d 뷰는 전역 `devicePixelRatio` 대신 캔버스가 붙는 창(`container.ownerDocument.defaultView`)의 배율과 `matchMedia`를 씁니다. 패널 창은 스테이지와 같은 JS 문맥에서 그리므로 전역 값은 스테이지가 있는 모니터의 배율이었습니다. 그림을 줄일 때 부드럽게 그리는 판정도 그 창의 배율을 쓰고 `renderScene`은 출력 배율을 씁니다. 도트 그림은 전처럼 창 배율로 판정합니다.
- 집중 기록 저장 (6번). 집중 시간은 30초마다가 아니라 시간이 쌓인 활동 샘플마다 바뀐 누적을 바로 로컬 파일에 씁니다. 샘플은 0.5초마다 오고 `JsonFile`이 같은 틱의 변경을 모아 메인에 보내므로 IPC는 초당 2번 이하이고 디스크 쓰기는 전처럼 메인이 1초마다 모읍니다. 켤 때 읽는 다른 기기 기록도 읽자마자 씁니다. 절전과 종료 때 한 번 더 쓰는 것은 그대로입니다. `src/modules/focus/focus.test.ts`가 시간이 쌓인 샘플마다 바로 쓰는 것을 확인합니다.
- 펜 탭 (7번). 코드는 바꾸지 않았습니다. 클릭 통과는 50ms마다 커서 위치로 정하므로 펜을 들었다가 캐릭터 위에 바로 내리면 첫 접촉이 아래 그림 앱으로 갈 수 있습니다. 재현되는지 `docs/checklists/windows-m0.md`의 화면과 입력 항목으로 친구 PC에서 확인하고 재현되면 판정을 펜 접촉 단위로 바꿉니다.
- 이 Mac의 e2e 빌드로 확인했습니다. 메인의 `screen`을 바꿔 작업 영역을 700x450으로 만들면 좌석 6개 줄이 976px에서 700px로 줄고 좌석 칸이 160px에서 114px이 되며 클릭 영역도 그에 맞아 친구를 누르면 💗가 뜹니다. 항목 16개짜리 ▼ 메뉴를 열어도 창 높이가 450이고 메뉴 안에서 스크롤해 맨 아래 설정을 누를 수 있으며 다른 사용자 메뉴도 창 안에 있습니다. 모니터를 되돌리면 원래 크기로 돌아옵니다. 런처 창의 배율을 CDP로 3배로 흉내 내면 미리보기 캔버스가 320px에서 480px로 다시 그려지고 스테이지 배율은 2 그대로입니다. 집중 시간이 2.5초 쌓인 순간 메인이 든 값은 같은 2.5초이고 디스크 파일은 1초 안에 따라옵니다. 실제 Windows의 150% 모니터, 배율이 다른 두 모니터, 펜 태블릿은 확인하지 못했습니다.

## 확인한 것

- `npm run typecheck`, `npm run lint`, `npx vitest run`, `npm run rules:build -- --check`, e2e 두 개(boot, m3-core)가 통과했습니다. 앞 앱 조회 줄이기는 `src/main/activity.test.ts`에 시험이 있습니다.
- e2e 빌드로 Mac arm64 폴더 패키지를 만들어 봤습니다. app.asar는 18.6MB이고(v0.1.1 Windows 설치판은 149.9MB) firebase와 react가 들어 있지 않으며 패키지를 켜면 런처와 실행 화면이 뜹니다. Windows 설치 파일 크기는 재지 않았습니다.
- 이 Mac에서 e2e 빌드를 켜고 확인했습니다. 열린 패널을 메뉴로 다시 열면 메인이 창을 올리고 포커스를 받는 패널에만 `focus`를 부릅니다. 같은 창을 동시에 두 번 열면 `window.open`은 한 번만 불립니다. 화면 밖으로 옮긴 숨긴 플레이리스트 창은 다시 열 때 작업 영역 안으로 옵니다. 숨긴 스테이지는 커서 위치를 읽지 않고 다시 보이면 읽습니다. 대상 고르기 중 스테이지 렌더러가 죽으면 ESC 등록이 풀리고 렌더러가 풀지 않은 ESC는 10초 뒤에 풀립니다. 테마를 바꾸고 1초가 지나기 전에 창에 `query-session-end`를 내면 바꾼 테마가 settings.json에 저장되고 앱이 끝납니다. 알림 권한 요청은 거절됩니다. Mac 메뉴에는 앱 메뉴와 편집 메뉴만 있고 Dock에는 아이콘이 없으며 Control+Alt+H가 등록됩니다. `ISSHONI_NO_GPU=1`로 켜면 GPU 합성이 꺼지고 캐릭터가 그대로 그려집니다.

## 확인하지 않은 것과 한계

- 실제 Windows PC에서만 확인할 수 있는 항목은 `docs/checklists/windows-m0.md`에 적었습니다. 패널이 그림 앱 위로 올라오는지, 포커스를 받는 패널이 다시 열 때 입력을 받는지, 배율이 다른 모니터에서 두 번 놓기가 필요한지, 시작 앱에서 끈 값, 로그오프 저장, 트레이 왼쪽 클릭과 아이콘 선명도, v0.1.1 위에 덮어 설치, 출시 워크플로입니다. 출시 워크플로는 실행하지 않았습니다.
