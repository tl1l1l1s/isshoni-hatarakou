# 0040 출시 전 점검

날짜 2026년 10월 12일

GitHub에 올리고 운영 규칙을 배포하기 전에 규칙, Electron 설정, 공급망, 개인정보와 용량, 출시 준비를 나눠 검토했습니다. 지적마다 검증 담당이 에뮬레이터와 코드로 다시 확인했습니다. 초대한 친구 몇 명이 쓰는 지금 범위에서는 출시를 막는 보안 문제가 나오지 않았습니다. 이 문서는 바로 고친 것과 선물하는 사람이 정할 일을 적습니다. 0020에서 roster 확인, 방 주인 확인, 친구 확인은 로그인만 본다고 정한 항목을 이 문서가 바꿉니다.

## 정한 것

- `IN_ROSTER`, `ROOM_OWNER`, `IS_FRIEND`도 발급 확인(`ISSUED`)을 합니다. 0020은 friendCode를 지우면 그 계정이 막힌다고 적었습니다. 실제로는 이 세 확인이 로그인만 봐서 friendCode를 지운 계정도 이미 들어간 방의 채팅과 멤버 기록을 읽고 썼고 친구 범위 기록도 읽었습니다. 이제 friendCode를 지우면 이 경로가 모두 막히고 열려 있던 구독도 바로 끊깁니다(에뮬레이터 확인).
- 발급을 거두는 절차를 07장 ACC-04 아래에 적었습니다. Firebase 콘솔에서 `users/{uid}/public/friendCode`, `codes/{친구 코드}`, `users/{uid}/presence`를 지웁니다. 거둔 계정은 앱을 끌 때 접속 상태를 쓰지 못합니다. 에뮬레이터에서는 그 계정의 앱을 끈 뒤에도 접속 상태가 남아 친구 목록에 계속 접속 중으로 보여서 접속 상태도 지웁니다.
- 방 설정 `mod/rooms/r/{room}/cfg`는 `cap`과 `v`만 받고 `v`는 1이어야 합니다. chat, gacha, photo의 cfg처럼 정하지 않은 칸은 `$other`로 거부합니다. 예전에는 방 주인이 큰 칸을 더하면 방에 들어오는 사람이 모두 내려받았습니다. 앱은 방을 만들 때와 정원을 바꿀 때 `{ cap, v: 1 }`만 쓰고 0.1.0 코드도 같습니다.
- `npm run rules:deploy`는 origin/main의 `database.rules.json`만 배포합니다. 내 PC의 파일이 origin/main과 다르면 배포하지 않습니다. 올리지 않은 규칙은 CI의 에뮬레이터 시험을 거치지 않았기 때문입니다. 덮어쓰기 전의 운영 규칙은 저장소 밖 `~/isshoni-hatarakou-backups/rules`에 남기고 되돌릴 때는 그 파일 내용을 콘솔의 규칙 편집기에 붙여 넣습니다. `FIREBASE_DATABASE_EMULATOR_HOST`가 남아 있으면 관리 SDK가 운영 대신 에뮬레이터에 배포하므로 완료 줄에 실제 대상을 적습니다.
- `.gitattributes`로 `database.rules.json`을 LF로 받게 했습니다. Windows의 Git은 기본으로 CRLF로 받는데 `rules:build --check`가 글자 그대로 비교해서 Windows에서는 `rules:deploy`가 배포 전에 멈췄습니다.
- 메인 로그에서 방 코드를 뺐습니다. 방에 들어갈 때 남기는 줄과 가챠 보관함 정리가 실패할 때 남기는 줄에 방 코드가 있었습니다. 자동 오류 보고는 로그 끝 줄을 디스코드로 보내고 발급 계정은 방 코드만 알면 그 방에 들어가 예전 채팅을 읽습니다. 구독이 끊길 때 Firebase가 내는 경고에도 경로와 방 코드가 있지만 콘솔에만 나오고 메인 로그로 가지 않습니다.
- Electron을 44.4.5에서 44.7.0으로 올렸습니다. 44.5.1과 44.7.0에 ANGLE, Chromium, V8, Skia 보안 수정이 들어 있고 앱은 다른 계정이 올린 그림을 누르지 않아도 디코딩합니다. 44.7.0은 나온 지 5일이라 2주 넘은 안정판을 쓴다는 0001의 규칙에 맞지 않습니다. 보안 수정이 들어간 Electron 패치는 이 규칙의 예외로 둡니다. 44.5.0부터 44.7.0까지의 변경 가운데 이 앱이 쓰는 API를 바꾸는 것은 없었습니다.

## 출시 순서

1. main을 올리고 Windows CI가 통과하는지 봅니다.
2. CI가 만든 설치 파일로 실제 Windows PC에서 `docs/checklists/windows-m0.md`를 확인합니다.
3. 운영 데이터베이스를 백업하고 `npm run rules:deploy`를 실행합니다. 규칙이 태그보다 먼저입니다. 1933f6e의 규칙은 새 앱의 옷장 `active` 쓰기와 가챠 `earned` 쓰기를 거부했습니다(에뮬레이터 확인).
4. 콘솔에서 이메일 로그인이 켜져 있는지 봅니다. 시험 계정 두 개와 PC 두 대로 로그인, 방, 채팅, 친구 신청, 가챠, 버그 제보를 한 번씩 씁니다.
5. 저장소 설정에서 immutable releases를 켜고 태그를 올립니다.
6. 버전을 올린 태그를 하나 더 만들어 자동 업데이트를 한 번 실행해 봅니다.

## 정하지 않은 것

선물하는 사람이 정할 일이라 바꾸지 않았습니다.

- 서명. 설치 파일과 업데이트에 서명이 없어서 electron-updater가 서명 검사를 건너뜁니다. GitHub 계정이나 이 저장소에 쓰는 토큰을 가진 사람은 모든 설치본에 코드를 보낼 수 있습니다. 서명하지 않는다면 첫 태그 전에 immutable releases를 켜고 계정의 2단계 인증을 확인하는 것이 가장 싼 대책입니다.
- Spark 한도. 설치 파일이 공개라서 계정이 없어도 동시 연결 100개를 채울 수 있습니다. 발급 계정 하나는 파일과 본인 기록으로 저장과 내려받기 한도를 채울 수 있고 한도를 넘으면 Firebase가 프로젝트를 끕니다. 막으려면 Blaze 전환과 사용자별 쓰기 한도 규칙이 필요합니다.
- 모르는 사람에게 넓힐 때. 발급 계정은 방 코드만 알면 정원과 상관없이 들어와 예전 채팅을 읽고 아무도 그 사람을 내보낼 수 없습니다(0033 D3). 계정 삭제 도구가 없고 개인정보 안내는 설정 안에 있으며 자동 오류 보고는 기본으로 켜져 있습니다.
- 디스코드 웹훅 주소는 0039의 세 선택지에서 아직 고르지 않았습니다.

## 확인한 것

- 규칙 시험 2개를 더했습니다. friendCode를 지운 멤버는 방 기록, 멤버 기록, 친구 범위 기록을 읽고 쓰지 못하고 friendCode를 지운 방 주인은 방 설정을 쓰지 못합니다. 방 설정은 `v`가 1이 아니거나 다른 칸이 있으면 거부됩니다. chat과 rooms 규칙 시험의 사용자에게 friendCode를 넣었습니다. 에뮬레이터 시험 전체(19개 파일, 180개)가 통과합니다. 규칙 파일은 69KB로 Realtime Database 한도 256KB의 4분의 1쯤입니다.
- 에뮬레이터를 가리키는 앱 두 개로 발급 계정 둘을 동시에 썼습니다. 설정 코드 로그인, 방 만들기와 참여, 방 설정에서 정원 바꾸기, 양쪽 채팅, 친구 신청과 수락, 방 주인의 가챠 설정 바꾸기가 모두 됐고 멤버 창에 바로 반영됐습니다. 방 설정은 `{ cap: 4, v: 1 }`과 `{ cap: 3, v: 1 }`로 저장됐습니다.
- 그 뒤 관리자로 한쪽의 friendCode와 codes 항목을 지우자 그 계정의 구독 35개가 0.1초 안에 모두 끊겼고 상대가 보낸 새 채팅을 받지 못했습니다. 그 계정이 보낸 채팅은 거부됐고 앱은 멈추거나 오류 화면을 띄우지 않았습니다. 상대 앱은 그대로 동작했습니다. 거둔 계정의 앱은 아무 설명 없이 마지막으로 받은 화면을 보이고 끊긴 구독을 계속 다시 겁니다. 친구 몇 명이 쓰는 지금 범위에서는 고치지 않았습니다.
- Electron 44.7.0에서 e2e 26개가 통과했습니다. 검증 세션에서 시작하기, 방 참여, 채팅 보내기, 설정 탭 일곱 개, 친구 창을 열었고 오류는 없었습니다. 메인 로그의 방 줄은 `[room] 들어감`으로 끝났습니다.
- macOS에서 OS 클릭 검사(`osclick.ts`)를 44.7.0으로 여섯 번 실행했습니다. 네 번은 필수 항목이 모두 통과했고 두 번은 창이 줄어든 뒤 이름표 클릭, 몸 끌기, 이름표 끌기 가운데 매번 다른 항목이 한두 개씩 실패했습니다. 44.4.5로 바꿔 실행한 세 번은 모두 통과했습니다. 실패한 항목이 매번 달라서 Electron 회귀보다 OS 이벤트 타이밍 문제로 봅니다. 펜과 끌기는 Windows 체크리스트에서 실제 기기로 확인합니다. 참고 항목 두 개(Mac 오버레이 창 클릭, 멀리서 바로 찍기)는 예전처럼 실패했습니다.
- `npm run typecheck`, `npm run lint`, `npx vitest run`(662개 통과, 에뮬레이터 시험 129개 건너뜀), `npm run rules:build -- --check`가 통과했습니다.
