# 0033 QA 연결과 화면

날짜 2026년 10월 11일

QA 검토(복원력, 여러 사람, 화면, 상호작용, 피드백, 오류와 보안, 운영)에서 코어 몫으로 나온 지적 가운데 절반을 고쳤습니다. 연결 모델과 오프라인 동작, 서버 오류 처리, 좌석과 말풍선과 이름표, 회사원 모드 알림, 한 좌석에 겹치는 효과, 대비와 색만으로 나누던 상태, 오류 경계, 버전 차이, 방에서 나갈 때의 roster, 계정입니다. 다른 묶음이 이어서 쓸 코어 계약도 더했습니다. 고친 곳은 `src/renderer/core`, `src/renderer/server`, `src/renderer/render/canvas2d/placeholder.ts`, account 모듈, `rules/core.ts`와 규칙 시험, 시험과 검증 지도, 명세 줄입니다. 지적이 고칠 곳으로 짚은 rooms 모듈 자동 재입장 한 곳과 status 모듈 칩 순서 한 줄도 고쳤습니다.

## 오프라인 쓰기 정책

Realtime Database SDK는 연결이 끊긴 동안의 쓰기를 메모리에 모아 두고 이 PC 화면에는 바로 반영합니다. 쓰기 Promise는 다시 연결될 때까지 끝나지 않습니다. 그래서 끊긴 채로 보낸 채팅과 저장한 닉네임, 더한 D-day 카드, 쓰다듬기가 성공한 것처럼 보였고 다시 연결되기 전에 앱을 끄면 아무 안내 없이 사라졌습니다. 이번에 정한 정책은 이렇습니다.

- 사용자가 시작한 쓰기(보내기, 저장, 지우기, 방 이벤트)는 `ctx.connection.online()`이 false면 시작하지 않고 `OFFLINE`(`연결이 끊겨서 보내지 못했어요. 연결되면 다시 해 주세요.`)이나 그 일에 맞는 같은 뜻의 글을 띄웁니다. 사용자가 적은 글은 지우지 않습니다. 코어는 닉네임 저장, 방 지우기, 방 이벤트에 이 정책을 적용했고 채팅, D-day, 스케줄러, 북마크 같은 모듈 쓰기는 각 묶음이 같은 계약으로 바꿉니다.
- 사용자가 누르지 않은 백그라운드 쓰기(계정 접속 상태, 멤버 기록의 `seenAt`과 batch 필드, 집중 합계, 상태, 레벨, 캐릭터 동기화)는 전처럼 모았다가 다시 연결되면 올립니다. 멤버 기록만은 끊긴 동안 쓰지 않고 이 PC 사본에 합쳐 두었다가 다시 연결될 때 사본 전체를 씁니다(RES-1).
- 방 이벤트는 끊긴 동안 보내지 않으므로 이 PC에서만 재생되지 않습니다. 끊긴 줄 모르고 보낸 이벤트는 받는 앱이 버립니다. push 키 앞 8글자는 보낸 앱이 어림한 서버 시각이라 서버 시각 `at`이 그보다 60초 넘게 늦으면 버립니다. 규칙과 기록 형식은 바꾸지 않았습니다.
- 끊긴 지 5초가 지나면 코어가 실행 화면 칩과 모든 창 위쪽 띠로 끊김을 보입니다. 모듈은 따로 보이지 않아도 되고 필요하면 `ctx.connection`으로 읽습니다.
- 방 입장(`ctx.room.join`, `create`)은 이 정책에서 뺐습니다. SDK 읽기가 연결될 때까지 기다리므로 입장은 끝나지 않은 채로 기다리고 성공한 것처럼 보이지 않습니다. 연결되면 들어갑니다. 절전 뒤 다시 들어가기와 앱을 켤 때 자동 재입장이 이 기다림을 씁니다.

고르지 않은 방법도 적어 둡니다.

- 모든 DocHandle 쓰기를 기본으로 막고 백그라운드 쓰기에만 표시를 다는 방법은 모든 모듈의 백그라운드 쓰기를 찾아 바꿔야 합니다. 하나라도 빠뜨리면 집중 합계 같은 기록이 끊긴 동안 사라집니다.
- 몇 초 안에 서버가 받지 않으면 실패로 보는 방법은 실패로 알린 쓰기가 나중에 올라가 같은 글이 두 번 생길 수 있습니다.
- 끝낼 때 올라가지 못한 쓰기를 세어 경고하는 방법은 사용자 쓰기를 막으면 남는 것이 백그라운드 쓰기뿐이라 뺐습니다.

## 연결 표시

- `CoreRuntime.offline`은 서버 연결이 끊긴 지 5초가 지나면 켜집니다. 잠깐 끊겼다 이어지는 일로 깜빡이지 않게 기다립니다.
- 실행 화면 상태칩 줄의 `메뉴 ▼` 옆에 `연결 끊김` 칩이 생깁니다. 펜으로는 title을 보기 어려워서 누르면 `인터넷 연결이 끊겼어요. 다시 연결하는 중이에요. 그동안은 보내거나 저장할 수 없어요.`를 알립니다. 회사원 모드에서도 보입니다.
- 열린 창마다 위쪽에 `연결이 끊겼어요. 다시 연결하는 중이에요.` 띠(`role="status"`)가 붙고 내용을 스크롤해도 위에 남습니다. 런처 화면에서는 런처 창에 보입니다.
- 다시 연결되면 칩과 띠가 사라지고 `다시 연결됐어요.`를 한 번 띄웁니다. 띄울 창은 알림 계약(0028)대로 방금 쓴 창입니다.
- 끊긴 동안 RoomSession은 150초 거름을 미루고 다시 연결되면 다시 거릅니다. 끊긴 동안 친구가 안내 없이 사라지던 일이 없어집니다. 남의 오래된 기록을 지우는 쓰기도 그동안 보내지 않습니다.
- 절전 뒤 끊긴 채로 깨어나면 다시 들어가기가 연결을 기다리는 동안 `연결 끊김` 칩이 보입니다. 지적은 `방에 다시 들어가는 중` 표시를 따로 두자고 했지만 두 표시가 늘 같은 때에 뜨므로 칩 하나로 두었습니다.
- 앱을 켤 때 자동 재입장이 실패하면 rooms 모듈이 다음에 연결될 때 한 번 더 들어갑니다(RES-3). 사용자가 직접 들어가면 다시 시도하지 않습니다.

## 코어 계약

모듈 묶음이 쓸 새 계약과 바뀐 계약입니다.

- `ctx.connection: { online(): boolean; onChange(fn: (online: boolean) => void): Dispose }`. 사용자 쓰기 앞에서 `online()`을 보고 React 화면은 `useSyncExternalStore((f) => ctx.connection.onChange(f), () => ctx.connection.online())`로 읽습니다. `onChange`는 lifecycle의 `online`, `offline`과 같은 때에 옵니다.
- `OFFLINE`(`@core/types`)은 끊겨서 시작하지 않은 쓰기를 알리는 글입니다.
- `ctx.room.emit`은 끊긴 동안 false입니다. 분당 한도와 나누려면 `ctx.connection.online()`을 봅니다.
- `RoomEventMsg`에 `key: string`을 더했습니다. 모든 PC에서 같고 보낸 순서로 정렬되는 push 키입니다. 같은 때에 온 두 이벤트(쓰다듬기와 흔들기)를 PC마다 같은 순서로 정하려면 `key`를 문자열로 비교합니다. `at`은 그대로 서버가 받은 시각이고 보낸 PC가 먼저 받는 자기 이벤트에는 어림한 값이 들어 있어 순서 비교에 쓰지 않습니다. `uid`도 그대로 있습니다.
- `ctx.self.setName(name): Promise<void>`. 서버 프로필에 쓰고 서버가 받은 뒤에 이 PC의 이름을 바꿉니다. 끊겼거나 서버가 거부하면 이름은 그대로 두고 그 까닭으로 reject합니다.
- `ctx.ui.ask(windowId, q: AskQuestion): Promise<boolean>`과 `AskQuestion { text: string; ok: string; cancel?: string }`. 지우기 확인처럼 그 창 안에 묻습니다. ok 단추면 true, cancel 단추와 ESC는 false이고 기본 포커스는 cancel입니다. cancel을 빼면 `취소`입니다. 창이 닫혀 있거나 숨겨져 있으면 묻지 않고 false입니다.
- `ctx.ui.confirmLeave(windowId, q?: Partial<AskQuestion>): Promise<boolean>`. guard 물음이 있을 때만 묻는 것은 같고 q로 글과 단추 이름을 바꿉니다. 캐릭터 슬롯을 바꿀 때 `{ text: '캐릭터를 저장하지 않았어요. 바꿀까요?', ok: '바꾸기' }`처럼 씁니다. 빼면 전처럼 guard 글과 `닫기`, `계속하기`입니다.
- `SettingField.hint?: string`. 설정 창 일반 탭이 항목 바로 아래에 `p`로 그립니다. 피규어 모드 설명 글은 그리기 묶음이 넣습니다.
- `AccountApi.pickPhoto(): Promise<boolean>`. 그림 파일을 골라 256px 안으로 줄여 올리고 프로필 사진으로 둡니다. 바꿨으면 true, 고르지 않았으면 false이고 끊겼거나 올리지 못하면 사용자에게 보일 글로 reject합니다. 계정 탭의 `사진 넣기`도 같은 함수를 씁니다.
- 읽지 않은 수 배지는 `<span data-unread>3</span>`입니다. 모양은 `theme.css`가 주고(높이 16px, 11px 굵은 글자, `--danger` 바탕에 흰 글자, 대비 4.54:1) 상태칩 단추 안에 두면 코어가 단추 오른쪽 위에 붙입니다. 💬, ✉, 🔔 배지는 각 묶음이 이 배지로 바꿉니다.
- `ctx.room.leave()`는 roster에서도 빠집니다(아래 절). `ctx.notify`는 회사원 모드에서 아무것도 하지 않습니다.
- 서버 쓰기가 실패하면 `e.message`는 사용자에게 보일 한국어 글이고 원래 오류는 `e.cause`, 오류 코드는 `e.code`에 있습니다.

## 방에서 나가면 roster에서 빠진다

사용자 결정 D3에 따라 내보내기와 차단은 만들지 않았습니다. 스스로 나가면 본인 roster 칸을 지워서 그 방 기록을 더 읽지 못하게만 했습니다.

- 규칙은 `rooms/$room/roster/$uid` 쓰기를 `본인 && (지우기 || (없을 때 && meta가 있고 && 지우지 않은 방))`으로 바꿨습니다. 남의 칸은 주인도 지우지 못합니다. 코드로 다시 들어오면 `ensureRoster`가 칸을 다시 만듭니다.
- `RoomTransport.removeRoster(code, uid)`를 두 구현에 더하고 `RoomSession.leave(forget)`이 forget일 때 나간 뒤 부릅니다. 끊긴 동안이면 다시 연결될 때 지워지고 그 전에 앱을 끄면 남습니다.
- forget은 모듈이 부르는 `ctx.room.leave()`에만 켭니다. 방 창의 `방에서 나가기`, 정원을 넘은 늦은 입장자의 스스로 나가기, 자동 퇴장이 여기에 들어갑니다. 자동 퇴장은 돌아올 때 다시 들어가며 칸을 다시 만듭니다. 앱 끝내기, 다른 기기로 넘기기, 절전, 다른 방으로 옮기기는 칸을 남깁니다. 다른 기기로 넘길 때 칸을 지우면 같은 계정으로 막 들어온 새 기기가 그 방을 읽지 못합니다.
- 방 주인도 스스로 나가면 칸이 빠지고 방을 지우려면 다시 들어갑니다. 지우기는 방 안에서만 할 수 있어 바뀌는 흐름은 없습니다.
- 나간 방의 가챠 아이템 목록과 삭제 표시는 보관함에서 읽지 못해 없는 것으로 봅니다. 보관함 항목은 지우지 않고 남깁니다.

## 서버 오류 글과 구독 다시 걸기

- Firebase 구현이 쓰기(문서 set, update, remove, transaction, 방 만들기와 지우기 표시, 파일 올리기, 프로필, 개인 기록)의 실패를 한국어 글로 바꿉니다. 거부는 `권한이 없어 저장하지 못했어요. 방이 지워졌거나 계정 설정이 바뀌었을 수 있어요.`, 그 밖의 실패는 `저장하지 못했어요. 인터넷 연결을 확인하고 다시 해 주세요.`입니다. 모듈은 `e.message`를 그대로 띄우므로 30곳쯤의 `PERMISSION_DENIED: Permission denied` 알림이 한 번에 바뀝니다. 메모리 서버의 거부도 같은 글과 코드를 던집니다.
- 읽기를 거부당해 SDK가 끊은 구독(문서 watch, watchList, 멤버, 방 이벤트, 개인 기록)은 5초, 15초, 1분 뒤에 다시 걸고 그 뒤로는 5분마다 겁니다. 다시 연결되면 기다리지 않고 바로 겁니다. 계정 접속 상태 구독은 전처럼 친구가 아니면 online과 lastSeen만 다시 구독합니다.

## 방 이벤트 순서

같은 때에 쓰다듬기와 흔들기가 오면 보낸 PC는 자기 이벤트를 먼저 받아 PC마다 결과가 달랐습니다. 지적은 서버 시각을 실어 순서를 정하자고 했지만 보낸 PC가 먼저 받는 자기 이벤트의 `at`은 어림한 값이라 PC마다 같지 않습니다. 그래서 모든 PC에서 같은 push 키를 `RoomEventMsg.key`로 주었습니다. 키 앞부분이 보낸 앱이 어림한 서버 시각이라 서버 시각 순서와 거의 같고 같은 밀리초도 겹치지 않습니다. 놀이 모듈이 이 키로 머리 위 반응을 정하는 일은 함께 묶음이 합니다.

## 한 좌석의 효과

`runtime.playEffect`가 좌석마다 지금 도는 detach 효과(춤, 날아가기, 때리기)를 하나만 둡니다. 같은 좌석에 새 detach 효과가 오면 앞의 효과를 스스로 끝난 것처럼 끝내고 모듈의 정리 목록에서도 뺍니다. 춤 중에 때리면 캐릭터 그림이 둘로 겹치던 것과 1초 안에 폭탄 10개가 오면 같은 캐릭터 10개가 날던 것이 한 번에 고쳐집니다. 날아가는 모양은 마지막 효과를 따릅니다. 폭탄 공처럼 detach가 아닌 효과는 전처럼 겹칩니다.

## 오류 경계

- 패널 창마다 렌더 오류 경계를 둡니다. 깨진 창에는 `이 창에 문제가 생겼어요. 닫고 다시 열어 주세요.`와 `닫기`가 보이고 실행 화면과 다른 창은 그대로입니다. 오류는 `renderer.window`로 보고하고 메시지 앞에 창 id를 붙입니다. 닫았다 다시 열면 새로 그립니다.
- 실행 화면도 경계로 감싸 `renderer.stage`로 보고하고 스테이지를 다시 읽습니다. 문서를 연 지 15초 안에 깨지면 다시 읽어도 같은 오류일 가능성이 높아 되풀이하지 않고 보고만 합니다.
- 슬롯 조각의 `Guard`를 type, fallback, onError를 받게 넓혀 세 곳이 같이 씁니다.

## 버전 차이

방에 있는 동안 `config/minProtocol`이 올라가면 규칙이 옛 앱의 `seenAt` 쓰기를 막습니다. 전에는 1분마다 다시 쓰다 실패하며 자기만 보이지 않는 방에 남았습니다. 이제 쓰기 실패 뒤의 recover가 최소 프로토콜을 다시 읽고 높으면 `앱을 새 버전으로 업데이트해야 방에 들어갈 수 있어요.`와 함께 방에서 나옵니다.

## 회사원 모드 알림

사용자 결정 D4에 따라 회사원 모드에서는 OS 알림을 하나도 띄우지 않습니다. `ctx.notify` 한 곳에서 막아서 채팅, 마이홈, 일정, 친구, 뽀모도로, 스티커 사진이 함께 조용해집니다. 앱 안 알림(토스트)과 소리 규칙은 그대로입니다.

## 화면

- 이름표는 바쁨을 흰 가로 막대가 든 빨간 점, 자리비움을 속이 빈 회색 고리로 그리고 이름 뒤에 `바쁨`, `자리비움`을 붙입니다. 점은 7px에서 9px로 키웠습니다. 이름표의 접근 가능한 이름 끝에도 `, 바쁨`처럼 붙어 `가짜 친구 메뉴`로 찾는 시험은 그대로 됩니다. 긴 이름은 상태 글에 자리를 내주고 줄임표로 줄어듭니다.
- 올라탄 캐릭터는 몸 오른쪽 가운데에 이름이 붙습니다(11px, 어두운 유리, 80px 넘으면 줄임표). 이름표를 제자리에 두는 0007의 결정은 그대로라 탑의 누가 누구인지를 몸에서 읽습니다. 클래스 이름에 rider를 넣지 않아 `[class*="rider"]`로 탑 층을 세는 시험과 지도가 그대로 됩니다.
- 벤치에 겹쳐 앉은 좌석(겹친 좌석과 그 바로 앞 좌석)은 말풍선 최대 폭을 좌석 간격에서 6px 뺀 값(크기 100%에서 90px)으로 줄입니다. 말풍선은 배율로 커지므로 좌석 칸이 CSS 변수 `--bubble-max`로 배율을 나눈 값을 줍니다.
- 기본 캐릭터의 잠든 z를 머리 오른쪽 옆으로 내리고 흰 테두리를 먼저 그립니다. 머리 위 말풍선과 겹치지 않고 검은 바탕에서도 읽힙니다.
- 밝은 테마의 `--fg-muted`를 `#636366`, `--fg-subtle`을 `--gray-600`으로 진하게 했습니다. 선택하지 않은 탭 글자는 탭 줄 바탕 위에서 4.21:1에서 4.98:1이 됐습니다. 어두운 테마는 그대로입니다.
- `aria-pressed`가 있는 단추(탭, 스케줄러 달력 칸, 백색소음 단추)는 바탕과 글자색을 한 번에 바꿉니다. 둘이 반대로 함께 바뀌면 중간 프레임에서 같은 회색이 되어 글자가 사라졌습니다. 모듈 CSS를 고치지 않고 `theme.css` 한 줄로 고쳤습니다.
- 설정 창 탭 줄은 줄을 바꾸지 않고 한 줄에 둡니다. 글자가 넓은 글꼴에서는 긴 탭 이름이 단추 안에서 두 줄로 접힙니다. 줄을 바꾸면 Windows 글꼴처럼 넓은 글꼴에서 `자리 추가` 하나만 둘째 줄로 내려갔습니다. 창을 넓히는 방법은 글꼴마다 넓힐 폭을 알 수 없어 고르지 않았습니다.
- 일반 탭의 그림 앱을 시스템 묶음에서 꺼내 자기 묶음(`그림 앱`)으로 시스템 앞에 두었습니다. 기본으로 든 그림 앱, 그림 앱이 하는 일, 집중 앱과의 차이를 세 줄로 적고 더한 앱이 있을 때만 목록을 그립니다. 단추는 `다른 그림 앱 넣기 (직전에 쓴 앱)`이고 이미 든 앱을 다시 넣으면 `이미 들어 있는 앱이에요.`를 띄웁니다. macOS 기본 목록은 다른 코어 작업이 채웁니다. main에 먼저 들어간 0030이 이 목록을 펜 입력 보호 앱으로 부르기로 해서 합칠 때 묶음 이름, 단추, 안내 글은 0030의 글을 따랐습니다.
- 상태칩은 order를 -1로 두어 방 안팎 어디서나 `메뉴 ▼` 바로 옆에 있습니다. 방 코드, 💬, ✉가 늘어도 내 상태칩 자리가 바뀌지 않습니다.

## 계정

- 닉네임 저장은 `setName`의 Promise를 기다립니다. 그동안 `저장하는 중이에요.`이고 서버가 받으면 `저장했어요`, 끊겼으면 코어의 끊김 안내, 서버가 거부하면 `닉네임을 저장하지 못했어요. 잠시 뒤 다시 해 주세요.`입니다. 실패하면 적은 이름이 칸에 남아 떠나기 전 물음이 그대로 뜹니다. 이 PC에만 새 이름이 남고 서버와 친구 화면은 옛 이름이던 일(RES-4)과 끊긴 채 저장한 이름이 앱을 끄면 사라지던 일(RES-2의 닉네임)이 없어집니다.
- 코드 복사 단추는 `코드 복사`, 알림은 `친구 코드를 복사했어요.`, 실패는 `복사하지 못했어요. 코드를 직접 알려 주세요.`로 방 창과 친구 창에 맞췄습니다.
- 친구 코드가 아직 없으면 내 정보와 계정 탭 모두 `연결되면 친구 코드가 보여요.`를 보입니다. 계정 탭의 `개발용 계정이라 친구 코드가 없어요`는 오프라인으로 켠 실제 계정에도 떴습니다.
- 내 정보 머리의 이름에 title로 전체 이름을 둡니다.

## 확인한 것

- 시험을 더했습니다. 규칙 시험은 본인 roster만 지우고 지우면 방 멤버, 방 이벤트, roomMember 컬렉션을 읽지 못하며 다시 만들면 읽는 것입니다. 계약 시험은 거부 글, 끊긴 동안 seenAt만 있는 기록이 생기지 않는 것(이 수정을 빼면 에뮬레이터에서 uid 없는 기록이 생겨 실패합니다), roster 지우기, 잠깐 거부당한 구독을 다시 거는 것입니다. RoomSession 시험은 끊긴 동안의 방 이벤트, 150초 거름, seenAt만 있는 기록, 늦게 닿은 이벤트, forget입니다. 시뮬레이터는 방에 있는 동안 최소 프로토콜이 오를 때 나오는 것을 봅니다. runtime 시험은 ask와 confirmLeave의 글, 회사원 모드 알림, 5초 뒤 끊김 표시와 다시 연결 알림, 한 좌석 detach 효과 하나입니다. 계정 시험은 끊겼거나 거부된 닉네임이 이 PC 이름을 바꾸지 않는 것입니다.
- verify-isshoni로 고치기 전에 재현하고 고친 뒤 다시 봤습니다. 회사원 모드의 바쁨 이름표 점만 보이던 것, 회사원 모드 OS 알림, 끊긴 실행 화면이 전과 같던 것, 끊긴 채 보낸 방 이벤트, 끊긴 채 저장한 닉네임, 창 하나의 렌더 오류로 실행 화면까지 사라지던 것, 넓은 글꼴의 탭 줄, 그림 앱 중복 넣기, 동물탑 이름, 벤치 말풍선 겹침, 방 지우기 알림 두 개입니다. 춤 중 때리기와 폭탄 10개는 고친 코드를 잠시 빼고 다시 빌드해 캔버스 2개와 10개를 본 뒤 고친 빌드에서 1개와 1개를 봤습니다. 실행 화면 렌더 오류는 15초 뒤에 일으켜 스테이지가 다시 읽히고 메인 로그에 `renderer.stage`가 남는 것을 봤습니다. 눌림 단추는 스케줄러 칸과 백색소음 단추를 밝게와 어둡게에서 누르고 300ms 동안 프레임마다 잰 대비가 쉬는 상태 값(13.97, 12.42) 아래로 내려가지 않았습니다. 사진 넣기(계정 탭과 `pickPhoto`), 코드 복사, 20자 이름의 title, 설명 줄, 공용 배지, 나가면 roster가 빠지는 것도 봤습니다.
- `npm run typecheck`, `npm run lint`, `npx vitest run`, `npm run rules:build -- --check`, 에뮬레이터 시험 전체(19개 파일, 9640번대 포트), e2e 세 개(boot, m3-core, windows-smoke), `osclick.ts`가 통과했습니다. `osclick.ts`의 참고 항목(멀리서 바로 찍기)은 전처럼 실패합니다.

## 한계

- SDK가 끊김을 알아채기 전(조용히 끊긴 네트워크에서 길게는 1분쯤)에 한 쓰기는 전처럼 쌓였다가 다시 연결될 때 올라갑니다. 그 사이 보낸 방 이벤트는 이 PC에서만 재생될 수 있고 친구 앱은 늦게 닿았다고 버립니다.
- 늦은 이벤트 거름은 보낸 앱의 서버 시각 어림(push 키)에 기댑니다. 연결된 앱만 보내므로 어림이 틀릴 일은 드물지만 서버 시각 차이를 받기 전에 보낸 이벤트는 PC 시계가 1분 넘게 늦으면 버려질 수 있습니다.
- 실행 화면이 켜자마자 깨지면 다시 읽지 않고 보고만 하므로 화면이 빈 채로 남습니다. 트레이 메뉴로 끝내고 다시 켜야 합니다.
- 다른 기기로 넘기기 같은 forget 없는 나가기 뒤에도 roster는 남으므로 그 방을 다시 읽을 수 있습니다. D3가 다루는 것은 스스로 나가기뿐입니다.
- 오프라인 띠는 창 위쪽에 자리를 차지해 창 높이에 맞춘 화면(대화하기)은 끊긴 동안 조금 스크롤합니다.
- Windows에서는 연결 표시, 넓은 글꼴의 탭 줄, 이름표 상태 글을 보지 않았습니다. 탭 줄은 Courier New로 넓은 글꼴을 흉내 내어 확인했습니다.
