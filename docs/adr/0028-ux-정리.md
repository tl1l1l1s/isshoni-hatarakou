# 0028 UX 정리

날짜 2026년 10월 10일

처음 쓰는 사람의 눈으로 창을 하나씩 연 검토(ux 18개)와 긴 글이 칸을 넘치는지 본 검토(wrap 15개)에서 코어 몫으로 나온 지적을 고쳤습니다. 다른 묶음이 이어서 쓸 수 있게 코어 계약 여섯 가지를 더하거나 바꿨습니다. 알림이 뜨는 창, 떠나기 전 묻기, 패널 문서 표준 모드, 공통 상태칩 모양, 스테이지 끌어 옮기기, 메뉴 묶음과 방 밖 항목입니다. 고친 곳은 `src/main`, `src/preload/api.ts`, `src/renderer/core`, launcher와 account 모듈, 메뉴 순서와 방 표시를 바꾼 모듈 `index.ts` 열네 개, 칩 규칙을 지운 모듈 CSS 일곱 개, 확정 버튼에 `type="submit"`을 붙인 모듈 화면 다섯 파일, 집중 앱 이름 칸 폭(`focus/ui/AppsTab.tsx`)과 지운 칩 클래스를 뺀 플레이리스트 칩(`sound/ui/Chip.tsx`), 검증 하네스와 지도입니다.

## 알림이 뜨는 창 (`ctx.ui.toast`)

- 코어가 창마다 마지막으로 누르거나 키를 치거나 포커스를 받은 시각을 기억합니다. 실행 화면은 빈 id로 세고 OS 알림을 누른 것도 실행 화면을 쓴 것으로 봅니다.
- 알림을 띄울 때 30초 안에 쓴 열린 창 가운데 가장 나중 창을 고릅니다. 실행 화면을 그보다 나중에 썼거나 고를 창이 없으면 실행 화면에 그립니다. 창에 그릴 때는 그 창 위쪽 가운데에 실행 화면 알림과 같은 유리 판으로 그립니다.
- 런처 화면에서는 실행 화면이 360x120의 작은 알림 창이라 열린 창 가운데 가장 나중에 쓴 창(대개 런처)에 그립니다.
- 고른 창이 1초 안에 닫히면(저장하고 닫는 창) 런처 화면에서는 런처로 옮기고 실행 화면에서는 실행 화면으로 옮깁니다. 1초 넘게 보인 뒤 닫히면 창과 함께 사라집니다.
- 한 번에 두 개까지 보이고 새 알림이 오면 가장 오래된 것을 뺍니다. 4초 뒤 사라지는 것은 그대로입니다.
- 모듈은 바꿀 것이 없습니다. 런처의 저장과 복사 알림, 집중 앱 탭, 마이홈 양식, 위치 초기화에서 피드백이 보이지 않던 지적은 이 계약으로 함께 고쳤습니다.

## 떠나기 전 묻기 (`ctx.ui.guard`, `ctx.ui.confirmLeave`)

- `guard(windowId, check): Dispose`의 check는 물을 글이나 null을 돌려줍니다. 코어는 ESC, 창 닫기 단추(제목 표시줄 ×), 설정 창 탭 바꾸기에서 check를 부르고 글이 있으면 그 창 안에 글과 `닫기`, `계속하기`를 띄웁니다. 사용자가 `닫기`를 눌러야 창을 떠납니다. 기본 포커스는 `계속하기`이고 묻는 중에 누른 ESC도 계속하기로 봅니다.
- 모듈이 `ctx.ui.close`로 닫을 때와 앱을 끝낼 때는 묻지 않습니다. 모듈이 이미 처리한 ESC(`defaultPrevented`)는 전처럼 건드리지 않습니다.
- `confirmLeave(windowId): Promise<boolean>`은 모듈이 창 안의 탭이나 뒤로처럼 제 화면을 바꿀 때 같은 물음을 띄웁니다. 물을 글이 없거나 사용자가 `닫기`를 누르면 true를 돌려줍니다.
- 슬롯 조각은 어느 창에 그려졌는지 알아야 guard를 걸 수 있어서 `SlotProps`에 `windowId`를 더했습니다. 패널 portal이 React context로 넘기고 실행 화면에 그린 조각에는 없습니다. 설정 창 탭은 `core.settings`를 받습니다.
- 제목 표시줄 ×는 패널 문서의 `beforeunload`에서 막습니다. Electron 44에서 `BrowserWindow.close()`(× 단추를 누른 것과 같은 동작)로 확인하니 window.open으로 연 패널에도 스테이지 렌더러가 붙인 `beforeunload`가 불리고 `preventDefault`를 부르면 대화상자 없이 닫기가 멈춥니다. 그때 코어가 창 안에 묻고 `닫기`를 누르면 `window.close()`로 닫습니다. 코어가 닫는 창은 미리 표시해 두어 다시 막지 않습니다. 앱을 끝낼 때는 메인이 `will-prevent-unload`에서 막기를 무시합니다. 메인 `close` 이벤트에서 렌더러에 물었다가 다시 닫는 방법은 같은 일에 IPC 왕복을 더하는 것이라 쓰지 않았습니다.
- keepAlive 창(플레이리스트)은 메인이 닫기를 숨기기로 바꾸므로 묻지 않고 내용도 남습니다.
- 첫 사용처는 계정 탭(설정 창과 런처의 내 정보)의 저장하지 않은 닉네임입니다. 런처 ◀와 내 정보의 탭도 `confirmLeave`를 거칩니다. 캐릭터 만들기의 저장하지 않은 그림은 모듈이 전부터 ESC에서 따로 묻고 있어 이번에는 두었습니다. 그 물음을 이 계약으로 옮기면 × 단추에서도 묻게 됩니다.

## 패널 문서 표준 모드

- `window.open('')`으로 연 about:blank 문서는 doctype이 없어 quirks 모드였습니다. 표가 글자 크기를 물려받지 않아 16px로 커졌고 body 높이 계산도 실행 화면과 달랐습니다.
- 패널, 설정 코드 창, 효과 창을 연 바로 뒤에 `standardsMode`가 doctype을 넣어 문서를 다시 씁니다. 다시 쓰면 문서의 리스너가 지워지므로 리스너보다 먼저 부릅니다.
- 표준 모드에서는 body가 창 높이를 채우지 않아 `body.panel`에 `height: 100vh`를 주고 body가 스크롤합니다. 패널 글은 어절 단위로 줄을 바꾸고(`word-break: keep-all`) 칸보다 긴 낱말만 글자 단위로 바꿉니다.

## 공통 상태칩 모양

- 코어가 `.chipBox` 바로 아래 `button`에 높이 28px, 반지름 14px, 12px 글자의 어두운 유리 모양을 줍니다. `:where`로 우선순위를 낮춰 모듈 클래스가 덮을 수 있습니다. 모듈 CSS 일곱 곳에 복사돼 있던 칩 규칙은 지우고 배지 자리, 방 코드 글꼴, 상태 글 줄임처럼 내용에 필요한 것만 남겼습니다.
- 이름표도 28px입니다. 이름표 한 줄과 칩 두 줄 높이인 `NAMEPLATE_H`를 76에서 100으로 올렸습니다. 재생, 안 읽은 글, 우편, 내려오기가 함께 있어 칩이 세 줄이 되어도 창 위쪽 여유 안에 그려지고 열린 메뉴는 잘리지 않습니다. 칩 줄에 단추를 더해 확인했습니다.
- 메뉴 칩 글자는 `메뉴 ▼`이고 title은 그대로 `메뉴`입니다. 회사원 모드의 숨기기 칩 글자는 `숨기기`입니다. 칩 줄을 오른쪽부터 채워 메뉴 칩이 늘 첫째 줄 오른쪽 끝에 있습니다.
- 다른 사람 이름표 끝에 ▾를 붙이고 마우스를 올리면 테두리를 밝게 그립니다.

## 스테이지 끌어 옮기기

- 이름표나 칩 줄의 빈 곳을 6px 넘게 끌면 렌더러가 pointerdown 자리에서 움직인 거리를 새 채널 `stage.drag`(start, move, end)로 보내고 메인이 창을 옮깁니다. 6px 안에서 떼면 전처럼 누른 것으로 보고 메뉴를 엽니다.
- 메인은 고른 모니터의 작업 영역 밖으로 나가지 않게 맞추고 창 아래 가운데 점을 작업 영역 안의 비율로 `device/stage-place.json`에 모니터 id마다 남깁니다. 비율이라 배율과 해상도가 바뀌어도 같은 쪽에 남고 모니터 구성이 바뀌면 다시 놓으면서 작업 영역 안으로 맞춥니다.
- 끄는 동안(마지막 move 뒤 2초까지) 메인이 클릭 통과를 멈춥니다. 커서가 창보다 빨리 움직여도 끌기가 이어지고 끝나면 커서 확인으로 돌아갑니다.
- 설정 화면 탭의 `위치 초기화`가 끌어 둔 자리와 기억한 창 자리를 지우고 설정 창에 `위치를 처음으로 되돌렸어요`를 띄웁니다. 트레이 메뉴와 같은 낱말입니다.
- 메뉴는 전처럼 작업 영역 높이까지 커집니다. 위쪽에 끌어 둔 캐릭터의 메뉴를 열면 창이 작업 영역 안에 남도록 아래로 내려갑니다.
- 브리지 채널을 하나 더했지만 기존 채널은 그대로라 `BRIDGE_VERSION`은 바꾸지 않았습니다.

## 메뉴 묶음과 방 밖 항목

- order의 십의 자리가 같은 항목끼리 한 묶음이고 묶음 사이에 구분선을 넣습니다. 10번대는 내 자리(상태 고르기, 포커스 기록, 레벨 보상), 20번대는 함께(방 만들기 / 참여하기, 친구, 대화하기, 이모티콘, 스티커 사진, 러시안룰렛, 춤추기), 40번대는 꾸미기(캐릭터 만들기, 가챠, 보관함, 꾸미기, 플레이리스트, 마이홈)이고 마지막 묶음은 « 런처로와 설정입니다. 설정 앞에 따로 두던 구분선은 지웠습니다.
- `ContributionDecl.needsRoom`이 켜진 메뉴 항목은 방 밖에서 흐리게(`aria-disabled`) 그리고 오른쪽에 `방에서만`을 붙입니다. 누르면 코어가 명령 대신 `NOT_IN_ROOM`을 알립니다. 글은 `방에 들어가면 쓸 수 있어요. 방 만들기 / 참여하기에서 들어가요.`이고 `@core/types`에서 내보내 모듈도 같은 글을 쓸 수 있습니다. 대화하기, 이모티콘, 가챠, 러시안룰렛, 춤추기에 켰습니다.

## 확인한 것

- `runtime.test.ts`가 ESC와 묻기, 저장하면 묻지 않기, 알림이 뜨는 창과 옮기기, 두 개 한도를 확인합니다. `display.test.ts`가 자리 비율과 작업 영역 안으로 맞추기를 확인합니다.
- `osclick.ts`에 끌기 항목을 더했습니다. OS 이벤트로 이름표를 150px 왼쪽과 120px 위로 끌면 창이 그만큼 옮겨지고 메뉴는 열리지 않습니다. 옮긴 뒤에도 빈 자리는 아래 창으로 통과하고 캐릭터와 이름표는 눌리며 자리가 `device/stage-place.json`에 남고 `위치 초기화`로 돌아옵니다. 기존 항목도 모두 통과했고 참고 항목(멀리서 바로 찍기)은 전처럼 실패합니다.
- 검증 하네스로 패널 25개를 모두 열어 밝게와 어둡게로 찍었습니다. 모두 `CSS1Compat`이고 가로로 넘치지 않으며 errors.json이 비어 있습니다. 설정 코드 창은 가짜 Firebase 설정 빌드로 열어 표준 모드와 형식 오류, 닫으면 다시 열림을 확인했습니다.
- 같은 하네스로 런처 복사 알림이 런처에만 뜨는 것, 런처 화면에서 저장하고 닫힌 캐릭터 만들기의 알림이 런처에 뜨는 것, 위치 초기화와 마이홈 북마크 알림이 그 창에 뜨는 것을 확인했습니다. 닉네임 물음이 ◀, 탭, ESC, `BrowserWindow.close()`에서 뜨고 저장 뒤에는 묻지 않는 것, 이미지 찍기를 버리는 ESC가 창을 닫지 않는 것, 20자 이름과 긴 상태 글과 긴 채팅과 그림 말풍선, 회사원 모드와 칩을 옆에 세운 모습도 확인했습니다.

## 한계

- Windows에서 끌기, 클릭 통과, 펜으로 끌기는 확인하지 않았습니다. 펜 입력이 스크롤로 바뀌지 않게 이름표와 칩 줄에 `touch-action: none`을 두었습니다.
- 모니터 id가 바뀌면 기억한 자리를 잃고 아래 가운데로 돌아갑니다.
- Chromium은 사용자가 한 번도 누르거나 입력하지 않은 문서의 `beforeunload` 막기를 무시합니다. 저장하지 않은 일은 사용자 입력으로만 생기므로 실제로는 막힙니다.
- 알림은 30초 안에 쓴 창을 기준으로 고르므로 사용자가 다른 앱을 쓰는 동안 서버에서 온 알림은 실행 화면에 뜹니다.
- Playwright로 창 닫기를 막으면 CDP가 beforeunload 대화상자를 알리고 Playwright가 대신 닫으려다 예외를 냅니다. 검증 스크립트는 그 창에 dialog 리스너를 붙입니다.
- 코어 방 세션의 실패 안내(없는 방 코드입니다 같은 글)는 rooms 모듈 시험과 지도가 그 글로 찾아서 이번에는 합니다체로 두었습니다.
