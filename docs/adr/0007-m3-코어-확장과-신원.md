# 0007 M3를 위한 코어 확장과 코어 신원 기능

날짜 2026년 10월 9일

10.3의 11번에 따라 M3 묶음 여러 모듈이 함께 쓰는 범용 기능을 코어에 더했습니다. 10.7.2의 코어 신원 기능인 연결 해제(ACC-05)와 한 계정 한 기기(ACC-12, SCR-08)도 함께 넣었습니다. 기능 이름은 코어에 들어가지 않습니다.

## 정한 것

- 효과는 manifest `effects`에 id와 `run(surface, args)`를 적고 `ctx.render.playEffect(seatKey, effectId, { toSeatKey, seed })`로 실행합니다. 효과 창은 효과가 하나라도 있는 동안만 열리고 마지막 효과가 끝나면 닫힙니다. 캐릭터가 있는 모니터 전체 크기이고 투명하며 클릭을 언제나 아래로 넘기고 포커스를 받지 않습니다. DOM은 패널처럼 스테이지 렌더러가 그립니다. 창 이름은 열 때마다 새 번호를 붙여서 닫히는 중인 창을 다시 받지 않습니다.
- 효과 좌표는 효과 창 기준 CSS 픽셀입니다. Mac은 화면 전체 창을 메뉴 막대 아래로 내리므로 렌더러는 요청한 영역 대신 메인이 알려 주는 실제 창 영역으로 좌표를 계산합니다.
- 방 사람 모두가 같은 효과를 보려면 모듈이 시드를 담은 방 이벤트를 보내고 받는 곳에서 `playEffect`를 부릅니다. 내가 보낸 이벤트도 나에게 오므로 보낸 PC도 같은 곳에서 실행합니다. 효과는 `args.rand`로 시드에서 같은 수열을 받습니다.
- 캐릭터가 자리를 떠나는 효과(`detach`)는 좌석의 몸만 숨기고 책상과 바닥은 남깁니다. 효과에는 책상과 바닥을 뺀 캐릭터 그림을 함께 줍니다. 그래서 `CharacterView.detach()`는 이제 캔버스 전체를 숨기지 않고 몸 층만 그리지 않습니다.
- 표시 모드가 `normal`이 아니거나 좌석이 그려져 있지 않으면 효과를 건너뜁니다.
- 대상 고르기 `ctx.ui.pickTarget`은 효과 창이 아니라 스테이지에서 합니다. 다른 사람 좌석의 클릭 영역은 이미 클릭을 받으므로 강조만 더하고 클릭 통과 규칙은 바꾸지 않았습니다. 고르는 몇 초 동안 메인이 ESC를 전역 단축키로 받고 취소 버튼과 시간 제한도 둡니다.
- gate는 manifest `gates`에 조건을 데이터로 적습니다. 코어는 gate를 선언한 모듈의 requires에 있는 모듈의 공개 API 함수만 불러 숫자를 비교합니다. 5초마다 다시 확인하고 바뀌면 슬롯을 다시 그립니다. `sticky` gate는 처음 열릴 때 `users/{uid}/private/gates/{gateId}`에 시각을 남겨 다른 PC에서도 열려 있습니다. 데이터베이스 키에 점을 쓸 수 없어서 gate id의 점은 쌍점으로 바꿔 저장합니다. 명령과 슬롯 항목은 `gate` 한 줄로 잠금을 따릅니다.
- 표시 모드 `ctx.mode`는 `normal`, `quiet`, `hidden`입니다. `quiet`은 PC마다 코어 설정에 기억하고 `hidden`은 이번 실행에만 둡니다. 앱을 켤 때 화면이 보이지 않으면 앱이 켜지지 않은 것처럼 보이기 때문입니다. 트레이나 단축키로 숨기고 보이면 표시 모드도 따라 바뀝니다.
- 좌석에는 로컬 좌석(4개까지), 올라타기, 순서 힌트, 벤치를 더했습니다. 올라탄 좌석은 몸만 아래 좌석 머리 위에 그리고 책상과 이름표와 상태칩은 제자리에 남깁니다. 내 캐릭터가 남의 머리에 올라타도 내 ▼ 메뉴를 그대로 누를 수 있습니다. 아래 좌석이 효과로 자리를 떠나거나 방을 나가면 한 칸 아래 좌석에 앉고 아래에 아무도 없으면 제자리로 돌아옵니다. 붙임 상태는 이 PC에만 적용하고 모듈이 presence 필드로 나눕니다.
- 규칙 템플릿 `dailyQuota`는 날짜 키 경로 대신 기록 하나 `{ d: 날 번호, n: 횟수 }`를 씁니다. 규칙 언어에는 날짜 문자열을 만드는 함수가 없어서 규칙이 `now`로 날 번호를 계산해 `d`와 비교합니다. 날 번호는 `dayKey`와 같은 오전 6시 경계를 쓰고 날이 바뀌면 1부터 다시 셉니다. 지난 날짜 기록이 쌓이지 않고 내일 몫을 미리 쓰는 쓰기도 막힙니다.
- 규칙 템플릿 `keyedWrite`는 로그인하지 않은 쓰기를 받습니다. 쓰는 값의 `h`가 본인이 저장한 해시 문자열과 같고 그 사람의 계정 접속 기록 `online`이 true일 때만 받습니다. 규칙은 해시를 계산하지 못하므로 폰이 해시 값을 그대로 보냅니다. PC 실행 중 표시는 코어가 이미 연결이 끊길 때 false로 바꾸는 `online`을 그대로 씁니다.
- 한 계정 한 기기는 켤 때 `users/{uid}/private/activeDevice`에 이 기기 id를 쓰고 구독합니다. 다른 기기가 이 값을 바꾸면 먼저 쓰던 기기는 방에서 나오고 방 입장을 막으며 스테이지에 다른 기기에서 쓰는 중이라는 안내와 여기서 계속 쓰기 버튼을 띄웁니다. 버튼을 누르면 다시 이 기기 id를 쓰고 나왔던 방에 들어갑니다. 캐릭터와 기록은 지우지 않습니다. 시뮬레이터는 같은 계정의 PC 두 대를 함께 돌리므로 이 동작은 `boot`가 켭니다.
- 연결 해제는 설정의 일반 탭에서 한 번 더 확인한 뒤 모듈에 종료를 알리고 저장한 다음 로그인만 지우고 스테이지를 다시 읽습니다. 이 PC의 파일은 남고 신원 단계가 설정 코드 창을 다시 띄웁니다.
- 브리지에 `stage.setVisible`, `stage.reload`, `effects.prepare`, `effects.bounds`, `pick.escape` 채널과 `pick.cancel` 이벤트를 더했습니다. 기존 채널은 바꾸지 않아서 `BRIDGE_VERSION`은 그대로입니다. `ServerPort`에는 본인만 읽고 쓰는 `users/{uid}/private`의 `userPrivate`를 더했고 규칙은 이미 본인에게 열려 있어 바꾸지 않았습니다.

## 알려진 한계

- 효과 창은 Windows에서 확인하지 않았습니다. 화면 전체를 덮는 투명 창이 영상 위에서 검어지거나 깜빡이는지(NFR-04)는 친구 PC에서 봐야 합니다.
- 전역 ESC 등록이 Windows에서 되는지 확인하지 않았습니다. 등록이 실패해도 취소 버튼과 시간 제한으로 끝납니다.
- 다른 기기에서 쓰는 중인 PC도 포커스 시간을 계속 셉니다. 모듈에 활성 기기 여부를 알려 주는 계약은 아직 없습니다.
- 한 계정 한 기기는 Firebase에서 두 PC로 확인하지 않았고 메모리 서버와 시험에서만 확인했습니다.
- 올라탄 층마다 스테이지 높이를 좌석 높이만큼 늘려서 조금 넉넉합니다.
