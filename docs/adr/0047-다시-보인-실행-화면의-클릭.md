# 0047 다시 보인 실행 화면의 클릭

날짜 2026년 10월 20일

Windows 10 PC에서 숨겼던 실행 화면이 다시 보이면 캐릭터, 이름표, `메뉴 ▼`, 상태칩이 왼쪽 클릭과 끌기를 받지 않았습니다(이슈 #6). 영상을 전체 화면으로 봤다 끄면 캐릭터가 안 움직이고 메뉴도 안 켜진다는 사용자 리뷰도 이 문제를 말합니다. 이 문서는 원인과 앱에 넣은 우회를 적습니다. Electron이 고치면 우회를 지웁니다.

## 원인

Electron v44.7.0과 그 판이 쓰는 Chromium 152.0.7977.130의 소스에서 확인했습니다.

- 스테이지는 `backgroundThrottling: false`입니다. 이때 Electron은 렌더 위젯이 숨김 상태가 되지 않게 막습니다(`disable_hidden.patch`).
- 창을 숨기면 Chromium이 입력을 받는 자식 창 `Chrome_RenderWidgetHostHWND`를 `SW_HIDE`로 숨깁니다. 이 부분은 Electron 패치가 막지 않습니다.
- 다시 보일 때 자식 창을 다시 보이는 코드는 렌더 위젯이 숨김 상태였을 때만 실행됩니다. 위젯은 숨김 상태가 된 적이 없어서 자식 창이 숨은 채로 남습니다. 그 밖에 자식 창을 다시 보이는 경우는 창 크기가 바뀔 때뿐입니다. 그래서 메뉴를 열거나 좌석 수가 바뀌면 실행 화면이 왼쪽 클릭을 다시 받았지만 다시 숨겼다 보여서는 받지 못했습니다.
- 자식 창이 숨으면 마우스 버튼을 누른 메시지가 포커스를 받지 않는 최상위 창으로 바로 전달됩니다. Chromium은 활성화할 수 없는 창의 `WM_MOUSEACTIVATE`에 `MA_NOACTIVATEANDEAT`를 돌려주고 Windows는 그 메시지를 버립니다. 마우스를 움직이거나 버튼을 뗀 메시지는 그대로 전달되어 툴팁이 떴고 버튼을 뗄 때 열리는 오른쪽 클릭 메뉴는 열렸습니다.
- 화면을 잠그거나 모니터가 꺼지면 Chromium의 Windows 창 가림 계산(`CalculateNativeWinOcclusion`)이 모든 창을 가려진 창으로 보고 같은 코드로 자식 창을 숨깁니다. 그래서 앱이 스테이지를 숨기지 않아도 잠금을 풀면 같은 문제가 생겼습니다.
- Electron 저장소에 같은 원인의 이슈(electron/electron#54694)가 열려 있습니다. 고치는 PR(#54695)은 아직 병합되지 않았고 v44.9.0과 main에도 같은 코드가 있습니다.

## 정한 것

- 숨겼던 스테이지가 다시 보이면 창 폭을 1px 줄였다가 바로 되돌립니다. 창 크기가 바뀌면 Chromium이 자식 창을 다시 보입니다. 같은 틱에 `setBounds`를 두 번 불러도 자식 창을 다시 보이는 코드가 끝까지 동기로 실행되는 것을 소스로 확인했습니다. 늘리지 않고 줄이는 것은 작업 영역 끝에 붙은 스테이지가 옆 모니터로 1px 넘어가지 않게 하려는 것입니다.
- 배율 125%나 150%에서는 DIP와 픽셀을 바꿀 때의 반올림 때문에 크기를 되돌려도 창이 1px쯤 어긋날 수 있습니다. 그래서 바로 뒤에 `place()`로 스테이지를 원래 자리에 다시 놓습니다. 100%에서는 자리가 같아서 아무것도 하지 않습니다.
- 크기 바꾸기는 Windows 어댑터의 `overlay.afterShow`에 둡니다. Mac은 아무것도 하지 않고 시험용 가짜 플랫폼은 불린 횟수를 `reshown`에 셉니다. `applyStage`가 숨김에서 보임으로 바꿀 때와 OS가 최소화한 스테이지를 되돌릴 때(`restore`) 부릅니다.
- Windows에서는 앱을 켤 때 `--disable-features`에 `CalculateNativeWinOcclusion`을 더합니다. 화면 잠금, 모니터 꺼짐, 다른 창이 다 덮었을 때 자식 창이 숨지 않습니다. 모든 창이 `backgroundThrottling: false`라 가림 계산으로 아끼던 것이 없습니다. `appendSwitch`는 앞서 넣은 값을 덮어써서 이미 있는 목록(Playwright 시험이 넣는 목록)에 이어 붙입니다.
- 다시 보일 때마다 스테이지 크기 바뀜 이벤트가 두 번 더 나고 렌더러가 클릭 영역을 다시 보냅니다.
- 고르지 않은 방법
  - 숨기는 동안만 배경 제한을 켜는 방법은 숨긴 동안 타이머가 느려져서 접속 상태와 서버 시각 일정이 늦어집니다.
  - `hide()` 대신 불투명도 0으로 숨기면 전체 화면 영상 위에 보이지 않는 맨 위 창이 남습니다. NFR-04가 숨기려는 경우와 맞지 않습니다.
  - 스테이지를 포커스를 받는 창으로 바꾸면 클릭은 들어가지만 누를 때마다 작업 중인 앱이 키보드를 잃습니다(ADR 0041).

## 확인한 것

- 원인은 Electron v44.7.0 태그와 Chromium 152.0.7977.130 태그의 소스를 두 번 따로 받아 읽어 확인했습니다.
- 이 Mac의 e2e 빌드에서 숨겼다 보이면 `overlay.afterShow`가 한 번 불리고 보이는 동안 `stage.setVisible`로 다시 보이기를 불러도 불리지 않습니다(`tests/e2e/m3-core.spec.ts`). 하네스에서는 스테이지를 최소화했다 되돌릴 때도 한 번 불리고 다시 보인 뒤 캐릭터와 `메뉴 ▼`를 눌러 반응을 확인했습니다. Mac은 원래 이 문제가 없어서 이 확인은 처리가 불리는지만 보여 줍니다.

## 한계

- Windows에서 실행 화면이 왼쪽 클릭을 다시 받는지와 플래그가 화면 잠금과 모니터 꺼짐 때 자식 창이 숨는 것을 막는지는 아직 확인하지 않았습니다. Windows PC 확인 순서는 PR에 적었습니다.
- 플래그를 넣어도 잠금을 푼 뒤 실행 화면이 왼쪽 클릭을 받지 않으면 잠금을 풀고 1초쯤 뒤에 같은 크기 바꾸기를 부르는 방법이 남아 있습니다.
- 숨겼다 보인 기능 창은 포커스를 받는 창이라 클릭은 들어갑니다. 정밀 터치패드 스크롤이 안 될 수 있는데(electron/electron#54694의 증상) 확인하지 않았습니다.
- 지금 Windows 점검표의 숨기기와 잠금 항목은 다시 보이는지만 봐서 이 문제를 잡지 못했습니다. 다시 보인 뒤 왼쪽 클릭을 확인하는 단계를 점검표에 더해야 합니다.
- Electron을 #54695가 들어간 판으로 올리면 이 우회와 플래그를 지우고 다시 확인합니다.
