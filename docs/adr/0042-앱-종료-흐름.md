# 0042 앱 종료 흐름

날짜 2026년 10월 16일

종료 흐름을 검토해 보니 앱을 끄는 곳은 트레이 메뉴뿐이었습니다. 런처 창을 닫아도 앱이 꺼지지 않고 실행 화면으로 넘어갔습니다. 트레이에서 종료하면 저장하지 않은 편집도 묻지 않고 버렸습니다(0028). 이 문서는 앱을 끄는 곳을 늘리고 끌 때 묻도록 바꾼 이유와 확인한 것을 적습니다. 0028의 규칙 가운데 앱을 끝낼 때는 묻지 않는다는 부분을 이 문서가 바꿉니다.

## 정한 것

- ▼ 메뉴 맨 아래 [설정] 다음에 [종료]를 둡니다. 이미 있던 `core.quit` 명령을 부릅니다.
- 런처 창을 닫으면 앱을 끕니다. 제목 표시줄 ×, Alt+F4, 작업 표시줄의 창 닫기가 모두 해당합니다. 런처는 앱을 켜면 처음 뜨는 창이어서 닫으면 앱이 꺼진다고 기대할 것으로 봤습니다. 다만 ESC를 누르다가 실수로 꺼질 수 있어서 런처만 ESC로 닫지 않습니다(`WindowDecl.closeOnEsc`).
- 앱을 끌 때 저장하지 않은 편집이 있는 창이 있으면 그 창마다 묻습니다. 캐릭터 만들기, 마이홈 편집, 꾸미기, 닉네임이 해당합니다.
  - 화면을 숨겼으면 다시 띄운 뒤에 묻습니다.
  - 모듈은 저장하지 않은 것을 알리는 글(예: 캐릭터를 저장하지 않았어요.)만 돌려주고 코어가 뒤에 물음을 붙입니다. ×로 닫을 때는 나갈까요?와 [나가기] [계속하기]이고 앱을 끌 때는 종료할까요?와 [종료] [계속하기]입니다. ×로 닫을 때 보이는 글은 전과 같습니다.
  - [계속하기]를 누르면 앱을 끄지 않습니다. 런처를 닫다가 누르면 런처를 다시 엽니다.
- 트레이 종료와 Mac Cmd+Q를 누르면 메인이 렌더러에 `quit.request`를 보냅니다.
  - 렌더러가 묻기 시작하면 메인에 `app.quitWait`를 보내고 메인은 사용자가 고를 때까지 기다립니다.
  - 렌더러가 1.5초 안에 묻기 시작하거나 저장을 끝내지 않으면 메인이 앱을 끝냅니다. 렌더러가 멈춰서 앱을 끄지 못하는 일은 없습니다.
- 업데이트 알림의 [다시 시작]은 누를 때 먼저 묻습니다. 설치 프로그램을 띄운 뒤에는 묻지 않습니다. 설치 프로그램이 뜬 뒤에 종료를 멈추면 설치가 어떻게 되는지 확인하지 못했기 때문입니다.
- Windows 로그오프와 Mac에서 OS를 끌 때는 기다릴 수 없어서 묻지 않습니다. 0002에서 정한 저장 순서는 그대로입니다. 모듈에 shutdown을 알리고 저장한 뒤 방에서 나옵니다.
- 끄기로 정한 뒤에는 남은 창이 닫힐 때 다시 묻지 않습니다.
- 연결 해제는 설정 창에서 따로 묻기 때문에 바꾸지 않았습니다. 연결 해제할 때 다른 창에 저장하지 않은 편집이 있으면 지금처럼 묻지 않고 버립니다.

## 확인한 것

- 이 Mac에서 e2e 빌드를 켜고 확인했습니다.
- 트레이 종료 확인
  - 설정 창 계정 탭에 저장하지 않은 닉네임을 두고 화면을 숨겼습니다. 이어서 트레이 종료와 같은 `app.quit()`을 불렀습니다.
  - 설정 창이 다시 떠서 물었고 2.5초가 지나도 앱이 꺼지지 않았습니다.
  - [계속하기]를 누르자 닉네임 칸에 쓴 글이 그대로 남았습니다.
- ▼ 메뉴의 [종료]를 누르면 다시 묻습니다. 여기서 [종료]를 누르자 0.2초 만에 꺼졌습니다.
- 런처 확인
  - 런처에서 ESC를 눌러도 런처가 그대로 남았습니다.
  - 메인의 `close()`로 런처 창을 닫자 설정 창에서 물었습니다. [계속하기]를 누르자 런처가 다시 열렸습니다.
  - 닉네임을 저장한 뒤 런처를 닫으면 묻지 않고 0.2초 만에 꺼졌습니다.
- 단위 시험을 더했습니다. 묻기, 계속하기, 묻는 중에 다시 누른 트레이 종료, 로그오프에서 묻지 않기, 런처의 ESC를 다룹니다.
- 타입 검사와 lint가 통과했습니다. 단위 시험 671개와 e2e 시험 26개도 통과합니다.

## 한계

- Windows에서는 트레이 종료, 런처 ×, Alt+F4, 로그오프를 확인하지 못했습니다. `docs/checklists/windows-m0.md`에 항목을 더했습니다.
- 업데이트 알림의 [다시 시작]은 받은 업데이트가 있어야 보여서 이 Mac에서 누르지 못했습니다.
- ▼ 메뉴가 한 줄 늘어서 작업 영역이 작으면 메뉴 안 스크롤이 조금 더 일찍 생깁니다.
