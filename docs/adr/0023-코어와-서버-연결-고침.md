# 0023 코어와 서버 연결 고침

날짜 2026년 10월 9일

코드 검토에서 나온 렌더러 코어, 부팅, 서버 adapter 문제를 고쳤습니다. 기능 이름은 코어에 들어가지 않습니다. 모듈 계약은 두 군데 늘었고 줄어든 것은 없습니다.

## 정한 것

- Firebase 데이터베이스는 웹소켓만 씁니다(`forceWebSockets`). SDK는 웹소켓이 한 번 실패하면 그 사실을 저장해 두고 다음부터 long polling으로 시작합니다. long polling은 `<script>` 태그를 넣는데 앱 CSP가 `script-src 'self'`라 그 태그를 막아서 다시 시작해도 연결이 오프라인에 머물렀습니다.
- 부팅은 공개 프로필 읽기를 3초만 기다립니다. Firebase 읽기는 오프라인이면 연결될 때까지 끝나지 않아서 인터넷 없이 켜면 실행 화면이 뜨지 않았습니다. 3초가 지나면 프로필 없이 런처와 실행 화면을 띄우고 읽기가 끝나면 이름과 친구 코드를 채웁니다. 그사이 사용자가 이름을 정했으면 그 이름을 둡니다.
- 절전에서 깨어나 같은 방에 다시 들어가지 못하면 실행 화면에 이유를 띄웁니다. 예를 들어 자는 동안 주인이 방을 지우면 `주인이 지운 방입니다.`가 뜹니다. 다시 들어가기는 연결이 돌아올 때까지 기다립니다.
- 방 입장은 입장마다 번호를 받습니다. 들어가는 중에 다른 입장이나 나가기나 절전이 오면 앞의 입장은 멈추고 이미 쓴 멤버 기록을 지웁니다. 그래서 두 방의 구독이 함께 남지 않습니다. 들어가는 중에 잠들면 깨어날 때 그 방에 들어갑니다. 모듈 계약의 `JoinResult` 실패 종류에 `cancelled`를 더했습니다. 코어는 이 종류를 안내하지 않고 모듈은 다른 실패처럼 이유 문장을 그대로 띄워도 됩니다.
- 다른 기기가 이 계정을 가져가면(ACC-12) 이 PC는 계정 접속 상태를 쓰지 않습니다. 연결이 끊길 때의 offline 쓰기 예약을 거두고 다시 연결돼도 쓰지 않으며 모듈이 `ctx.self.setPresence`로 바꾼 값도 이 PC에만 둡니다. 전에는 쓰지 않는 PC가 잠들면 계정 전체가 offline으로 보였고 폰 신호 규칙도 PC가 꺼진 것으로 보고 신호를 막았습니다. `여기서 계속 쓰기`를 누르면 다시 씁니다. 이를 위해 `ServerPort.presence`에 `stop`을 더했습니다.
- 서버 조정값이 배열이면 기간 목록인지 먼저 봅니다. 모든 칸이 `value`가 있는 객체이거나 빈 칸이면 기간 목록이고 아니면 배열 값 하나입니다. 레벨 표 같은 배열 값이 늘 무시되던 문제와 목록 가운데를 지워 생긴 빈 칸에서 예외가 나던 문제를 고쳤습니다. 운영 스크립트의 기간 더하기도 같은 판정을 씁니다.
- 한 좌석에 자리를 떠나는 효과가 둘 이상이면 모두 끝나야 좌석에 돌아옵니다. 효과마다 수를 셉니다.
- 모듈의 정리 목록에서 끝난 것을 뺍니다. `ctx.timers.at` 타이머는 울리면 빠지고 회사원 모드나 그려지지 않은 좌석처럼 바로 끝난 효과는 목록에 들어가지 않습니다. 오래 켜 두면 목록이 계속 늘던 문제입니다.
- 효과 창의 화면 전체 canvas는 효과가 `surface.canvas`를 처음 읽을 때 만듭니다. 4K 화면이면 효과 하나에 수십 MB였고 지금 놀이 효과는 이 canvas를 쓰지 않습니다.
- 외형 파일이 JSON이 아니면 외형 없음으로 봅니다. 서버 파일은 받을 때 내용의 sha256이 해시와 같은지 확인하고 다르거나 base64가 아니면 없는 파일로 봅니다. 누가 해시 자리를 다른 내용으로 먼저 썼으면 올리기가 규칙에 막힙니다. 이때 저장된 값을 읽어 같으면 올린 것으로 보고 다르면 실패로 돌려줍니다.
- 저장된 설정은 키마다 검사합니다. 전에는 키 하나가 맞지 않으면 모듈 설정 전체가 기본값이 되고 다음 저장이 그 기본값을 덮어썼습니다.
- 설정 코드 창은 로그인하는 동안 열려 있고 버튼이 `확인하는 중이에요`로 바뀝니다. 실패하면 adapter가 알려 준 이유(코드 형식, 인터넷 연결, 맞지 않는 코드)를 창 안에 띄웁니다. 전에는 모든 실패가 코드가 맞지 않는다는 안내였습니다. 창을 닫으면 부팅이 멈춘 채로 남던 문제는 창을 다시 여는 것으로 고쳤습니다. 코드를 넣어야 시작할 수 있고 앱 끝내기는 트레이 메뉴에 있습니다.
- 배포 빌드(`--mode e2e`가 아닌 production 빌드)에 Firebase 주소가 없으면 개발 로그인 메모리 서버로 켜지 않고 시작할 때 멈춥니다. 실행 화면에 `시작하지 못했습니다. Firebase 설정 없이 만든 빌드입니다.`가 뜹니다. 개발판과 시험판은 그대로 메모리 서버를 씁니다.
- 패널 창 portal은 스테이지 옆의 `Panels`가 그립니다. 열린 창 목록만 구독해서 좌석이 바뀌어도 패널을 다시 맞추지 않습니다. 좌석 그리기 fps는 `FPS_AWAKE`와 `FPS_ASLEEP` 상수를 씁니다.
- 패널의 ESC와 패널 단축키는 모듈이 이미 처리한 키(`defaultPrevented`)를 건너뜁니다. 그리기 도구를 내려놓는 ESC가 창까지 닫던 문제의 코어 쪽입니다. 모듈은 처리한 키에 `preventDefault`를 부릅니다.

## 오프라인 부팅의 이름 (Codex 검토 2번)

프로필 읽기가 3초를 넘기면 account 모듈이 이 PC에 둔 이름을 `ctx.self.setName`으로 넣었습니다. 이 호출은 서버 프로필에도 쓰므로 다른 PC에서 바꾼 새 이름을 이 PC의 옛 이름이 덮었고 늦게 읽은 프로필은 이미 이름이 있다며 버려졌습니다.

- 모듈 계약에 `ctx.self.fillName(name)`을 더했습니다. 이름이 비어 있을 때만 그 이름을 보이고 서버에는 쓰지 않습니다. 프로필을 이미 읽었는데 이름이 비어 있으면(처음 쓰는 계정) 전처럼 한 번 올립니다. account 모듈은 setup에서 이 PC에 둔 이름을 `fillName`으로 넣고 `ctx.self.onChange`로 이름이 바뀔 때마다 이 PC의 사본을 맞춥니다.
- 코어는 이번 실행에서 사용자가 `ctx.self.setName`으로 정한 이름이 있는지 기억합니다. 늦게 읽은 프로필은 그 이름이 없을 때만 받고 프로필에 이름이 없으면 그동안 보이던 이름을 한 번 올립니다.
- 부팅은 프로필을 아직 읽지 못한 것(`undefined`)과 읽었는데 없는 것(`null`)을 구분해서 코어에 넘깁니다.
- `src/modules/account/account.test.ts`가 실제 account 모듈과 코어 런타임으로 세 경우를 확인합니다. 다른 PC가 바꾼 이름이 이기는 것, 프로필을 읽기 전에 사용자가 정한 이름이 이기는 것, 서버에 이름이 없는 계정이 이 PC의 이름을 올리는 것입니다.

## 알려진 한계

- 웹소켓 고정과 오프라인 부팅은 가짜 Firebase 설정 빌드에서 로그인 응답을 메인이 대신 주고 데이터베이스 연결을 막아 확인했습니다. 실제 Firebase에서 웹소켓이 실패한 뒤 다시 붙는지와 연결된 뒤 이름이 채워지는지는 확인하지 않았습니다.
- 프로필을 읽기 전에 사용자가 이름을 정하면 그 이름이 서버에 올라가 다른 PC에서 바꾼 이름을 덮습니다. 사용자가 직접 정한 이름이라 그대로 둡니다.
- 쓰지 않는 기기의 접속 상태는 메모리 서버와 시험에서만 확인했습니다. 두 PC와 Firebase에서는 확인하지 않았습니다. offline 쓰기 예약을 거두는 요청이 서버에 닿기 전에 연결이 끊기면 서버가 예약대로 offline을 씁니다.
- 들어가는 중에 다른 기기가 계정을 가져가면 그 입장은 취소되고 `여기서 계속 쓰기` 뒤에 그 방으로 돌아가지 않습니다.
- 해시 자리를 다른 내용으로 먼저 쓴 파일은 앱이 고칠 수 없습니다. 그 해시의 그림은 보이지 않고 올리기는 규칙이 거부한 오류 문장을 그대로 보여 줍니다. 낯선 계정의 쓰기를 막는 규칙은 따로 다룹니다.
- 배포 빌드 확인은 빌드가 아니라 실행 때 멈춥니다. 빌드 설정은 이 작업 범위 밖이라 설치 파일은 만들어집니다. 빌드 단계에서 막으려면 빌드 설정에서 같은 조건으로 실패하게 해야 합니다.
- 설정 코드 창은 닫자마자 다시 열립니다. 나중에 넣기 같은 선택지는 두지 않았습니다.
