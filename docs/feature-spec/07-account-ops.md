### ACC-04 계정 식별 코드 (친구 코드)

| 우선순위 |
|---|
| P0 |

- 선물하는 사람이 `npm run account:create -- <이름>`을 실행하면 `scripts/create-account.ts`가 로그인 계정을 만듭니다. 계정마다 바뀌지 않는 내부 ID(uid)가 생기고 이름과 친구 코드는 `users/{uid}/public`에 저장됩니다. 스크립트는 uid와 친구 코드를 화면에 적고 설정 코드 한 줄을 출력합니다.
- 설정 코드는 `TD1-`로 시작하는 한 줄이고 스크립트가 정한 임의 이메일 주소와 24자 비밀번호를 담습니다. 친구는 이메일이나 비밀번호를 직접 정하지 않습니다.
- 처음 켠 PC는 [설정 코드 입력] 창을 띄웁니다. 친구가 코드를 붙여 넣고 [시작하기]를 누르면 로그인하고 런처가 뜹니다. 코드 형식이 틀렸거나 인터넷이 끊겼거나 코드가 맞지 않으면 앱은 그 이유를 창 안에 보여 줍니다. 창을 닫으면 앱이 창을 다시 엽니다. 로그인 상태는 PC에 남아서 다음에 켤 때 앱이 코드를 다시 묻지 않습니다.
- 친구 코드는 숫자 0과 1, 영문 I와 O를 뺀 32자에서 고른 8자입니다. 스크립트는 겹치지 않는 코드를 얻을 때까지 5번까지 시도합니다. 친구 코드는 uid를 가리키는 별칭이고 서버 기록은 모두 uid로 저장합니다. 친구 추가는 이 코드로 합니다(5장 FRD-01).
- 친구 코드는 런처의 내 정보 화면 위쪽, 설정 창 [계정] 탭, 친구 창에 [복사] 버튼과 함께 보입니다. 닉네임은 [계정] 탭에서 1자부터 20자까지 바꿉니다.
- 친구가 설정 코드를 잃으면 선물하는 사람이 `npm run account:create -- --reset <uid>`로 비밀번호를 새로 만듭니다. 기존 로그인이 모두 끊기고 옛 코드는 더 쓸 수 없으며 친구는 새 코드로 같은 계정과 기록을 그대로 씁니다.

### ACC-05 기기 연동과 연동 해제

| 우선순위 |
|---|
| P2 |

- 계정은 한 번에 한 PC에서만 쓰고(ACC-12) 캐릭터 슬롯은 PC 사이에서 맞춥니다(ACC-13).
- 설정 창 [일반] 탭의 시스템 묶음에 [이 PC 연결 해제]가 있습니다. 누르면 이 PC의 기록은 남고 다시 쓰려면 설정 코드를 넣어야 한다는 안내와 [연결 해제] [취소] 버튼이 나옵니다.
- [연결 해제]를 누르면 앱은 모듈에 종료를 알리고 저장한 뒤 로그인만 지우고 처음 단계부터 다시 시작해 [설정 코드 입력] 창을 띄웁니다. 이 PC의 설정과 프로그램별 집중 시간 같은 파일은 지우지 않습니다.
- 설정 창의 설정값은 PC마다 저장되어 다른 PC로 옮겨 가지 않습니다.

### ACC-08 데이터 백업과 수동 복구

| 우선순위 |
|---|
| P1 |

- 선물하는 사람은 자기 PC의 예약 작업으로 `node scripts/backup.ts [폴더]`를 하루 한 번 실행합니다. 폴더를 적지 않으면 저장소 밖의 `~/isshoni-hatarakou-backups`에 저장합니다.
- 스크립트는 그림 파일 경로 `files/`를 뺀 데이터베이스 전체를 `YYYY-MM-DD.json` 파일 하나에 담고 날짜 이름 파일은 최근 7개만 남깁니다. 다 쓴 뒤에 파일 이름을 바꾸므로 중간에 끊긴 파일은 백업으로 세지 않습니다.
- 그림 파일은 내용 해시가 이름이라 바뀌지 않으므로 백업 폴더의 `files/`에 해시마다 한 번만 받습니다(10.7.5). 백업에서 서버로 되돌리는 스크립트는 아직 없습니다.
- 앱은 캐릭터를 저장하거나 다른 PC와 맞추거나 휴지통에서 복원할 때 덮어쓴 모습을 서버 휴지통에 10일 동안 남깁니다. 내 정보 화면의 휴지통 탭에서 [복원]을 누르면 그 모습이 원래 칸으로 돌아가고 그 칸의 지금 모습은 휴지통으로 갑니다. 캐릭터 만들기 창의 [이전 모습] 탭에서는 [불러오기]로 편집 중인 캐릭터에 불러옵니다.
- 휴지통 항목마다 사라질 날짜가 붙고 최근 50개까지 보입니다. 10일 지난 항목은 앱이 서버와 캐릭터를 맞출 때 지웁니다.
- 설정 코드를 잃었을 때는 ACC-04의 `--reset`으로 같은 계정을 되찾습니다. 캐릭터 하나는 캐릭터 파일로 내보내 따로 보관할 수 있습니다(4장 AVT-17).

### ACC-09 우편함

| 우선순위 |
|---|
| P2 |

- 선물하는 사람이 보낸 글은 내 마이홈의 [우편함] 탭과 우편함 창에 보입니다. 친구 마이홈을 보는 동안에는 이 탭에 글을 보여 주지 않습니다.
- 읽지 않은 글이 있을 때만 실행 화면 상태칩 줄에 ✉와 읽지 않은 글 수가 보이고 10개부터는 9+로 줄여 보입니다. ✉를 누르면 우편함 창이 열립니다. 회사원 모드에서는 ✉를 숨깁니다.
- 우편함에는 [전체] [공지] [업데이트] [우편] 탭과 [전체 읽음] 버튼이 있습니다. 고정한 글이 맨 위에 오고 나머지는 새 글부터 놓입니다. 글 머리를 누르면 본문이 펼쳐지고 읽음이 되며 링크가 있는 글에는 [링크 열기]가 있습니다.
- 글은 모두에게 보내는 글과 한 사람에게 보내는 편지 두 가지입니다. 제목은 80자까지이고 본문은 800자까지입니다. 글에는 http나 https 링크 하나를 붙일 수 있습니다. 앱은 모두에게 보낸 글과 내 편지를 각각 최근 30개만 받으므로 고정한 글도 그 밖이면 보이지 않습니다.
- 앱에 함께 넣은 업데이트 소식(OPS-17)도 [업데이트] 탭에 보이고 읽지 않은 글 수에는 들어가지 않습니다. 읽음 표시는 PC마다 따로 저장합니다.
- 글은 선물하는 사람만 `scripts/ops.ts`로 쓰고 지웁니다(OPS-01). 앱은 읽기만 합니다.

### ACC-10 선물함

| 우선순위 |
|---|
| P2 |

- 내 마이홈의 [선물함] 버튼을 누르면 친구가 보낸 말랑이 선물 목록이 열립니다. 받지 않은 선물이 있으면 버튼에 그 수가 보이고 새 선물이 오면 알림을 띄웁니다.
- 항목마다 보낸 사람 이름, 보낸 때, 60자까지의 메시지가 보입니다.
- [받기]를 누르면 그 그림이 내 말랑이(최대 10개)에 들어가고 목록에서 빠집니다. [숨기기]를 누르면 숨긴 선물은 다시 볼 수 없다는 문구와 [숨기기] [취소] 버튼이 나오고 [숨기기]를 다시 누르면 지웁니다.
- 한 사람이 받는 사람에게 쌓아 둘 수 있는 받지 않은 선물은 30개까지입니다. 선물을 보내는 방법은 6장 HOM-14에 있습니다.

### ACC-12 한 계정 한 기기

| 우선순위 |
|---|
| P2 |

- 앱을 켜면 이 PC를 계정을 쓰는 기기로 서버에 적습니다. 같은 계정으로 다른 PC를 켜면 먼저 쓰던 PC는 방에서 나오고 실행 화면에 다른 기기에서 쓰는 중이라는 안내와 [여기서 계속 쓰기] 버튼을 띄웁니다.
- 그동안 먼저 쓰던 PC는 방에 들어가지 못하고 집중 시간을 세지 않습니다. 계정 접속 상태도 서버에 쓰지 않고 오늘 일정 알림도 보내지 않습니다.
- [여기서 계속 쓰기]를 누르면 이 PC가 계정을 다시 가져오고 나왔던 방에 다시 들어가며 캐릭터를 서버와 다시 맞춥니다(ACC-13). 그러면 다른 PC에 같은 안내가 뜹니다.
- 어느 PC의 캐릭터와 기록도 지우지 않습니다.

### ACC-13 캐릭터 자동 동기화와 충돌 선택

| 우선순위 |
|---|
| P2 |

- 캐릭터 슬롯 3개는 서버에 저장합니다. 앱은 켤 때, 30분마다, [여기서 계속 쓰기]로 계정을 다시 가져올 때 슬롯을 서버와 맞추고 저장한 캐릭터는 바로 서버에 올립니다.
- 슬롯마다 마지막으로 서버와 맞춘 시각을 PC에 저장합니다. 그 뒤로 한쪽만 바뀌었으면 바뀐 쪽을 씁니다. 이 PC와 서버가 모두 바뀌었고 내용이 다르면 합치지 않고 [캐릭터 맞추기] 창을 띄웁니다.
- [캐릭터 맞추기] 창은 캐릭터 번호, 이 PC 쪽 미리보기, 다른 PC 쪽 미리보기를 보여 주고 [현재 PC로 맞추기]와 [다른 PC로 맞추기] 가운데 하나를 고르게 합니다. 고르지 않은 쪽은 휴지통에 10일 동안 남습니다(ACC-08).
- 앱은 서버의 수정 시각이 마지막으로 맞춘 시각과 같을 때만 캐릭터를 올립니다. 그래서 다른 PC가 먼저 바꾼 서버 쪽을 덮어쓰지 않고 바로 고르기 창을 띄웁니다.
- 고르지 않고 창을 닫으면 30분 뒤 맞출 때 창이 다시 뜹니다. 그 사이 그 슬롯을 다시 저장해도 고를 때까지 서버에 올리지 않습니다.

| P2 |

- 따로 공지 화면은 없습니다. 앱 안 공지는 우편함(ACC-09), 업데이트 소식 창(OPS-17), 확성기(OPS-18)로 합니다.
- 선물하는 사람은 `node scripts/ops.ts mail <제목> <본문>`으로 모두에게 글을 보냅니다. 태그 기본값은 공지이고 `--tag update`를 붙이면 업데이트 글이 됩니다. `--pin`은 글을 맨 위에 고정하고 `--link <주소>`는 링크 하나를 붙입니다. 본문의 `\n`은 줄바꿈이 됩니다.
- `--to <친구 코드나 uid>`를 붙이면 그 사람에게만 가는 편지가 되고 태그 기본값은 우편입니다.
- `node scripts/ops.ts mails`는 보낸 글 목록과 id를 보여 주고 `node scripts/ops.ts unmail <id>`는 글을 지웁니다. 두 명령 모두 `--to`를 붙이면 그 사람의 편지를 다룹니다.
- 스크립트는 글 형식이 앱이 받는 형식과 같은지 먼저 확인하고 맞지 않으면 보내지 않습니다.

### OPS-12 기간 한정 이벤트

| 우선순위 |
|---|
| P2 |

- 선물하는 사람은 앱을 다시 배포하지 않고 서버 조정값으로 레벨 보상 조건 같은 값을 바꿉니다. `node scripts/ops.ts tunable <모듈>`은 그 모듈의 지금 값을 보여 주고 `<키> <JSON 값>`을 붙이면 값을 바꿉니다. `<키> --clear`는 키를 지워 앱 기본값으로 돌립니다.
- `--from <시각> --until <시각>`을 붙이면 그 기간에만 쓰는 값을 더합니다. 시각은 `2026-10-10T00:00+09:00` 형식이고 끝 시각이 시작 시각보다 늦어야 합니다. 스크립트는 값을 더할 때 이미 끝난 기간 항목을 지웁니다.
- 앱은 값을 읽을 때마다 지금 시각이 든 기간의 값을 고르고 기간이 겹치면 나중에 더한 값을 씁니다. 레벨 보상 같은 잠금 조건은 5초마다 다시 확인하므로 기간이 끝나면 5초 안에 원래 값으로 돌아옵니다.
- 모듈이 정한 형식에 맞지 않는 값은 무시하고 기본값을 씁니다. 지금 바꿀 수 있는 값은 growth의 `secondsPerLevel`(기본 3600초)과 `tierLevels`, wardrobe의 `animalUnlockLevel`(기본 30이고 1부터 999까지), gacha의 `hueUnlockCount`, photo의 `photoDailyCap`, phone의 `pageUrl`입니다.
- 예를 들어 주말 동안 `animalUnlockLevel`을 낮출 수 있습니다. 기간 안에 앱이 동물 캐릭터 해금 조건을 확인하면 해금 기록이 계정에 남으므로 기간이 끝나도 다시 잠기지 않습니다(3장 GRW-03).

### OPS-21 운영자 관리 도구

| 우선순위 |
|---|
| P2 |

- 앱에는 관리 화면이 없고 선물하는 사람이 자기 PC에서 Node로 스크립트를 실행합니다. 모든 스크립트는 서비스 계정 JSON 경로를 담은 `GOOGLE_APPLICATION_CREDENTIALS`와 `FIREBASE_DATABASE_URL` 환경 변수가 있어야 실행됩니다.
- `scripts/create-account.ts`(`npm run account:create`)는 친구 계정을 만들고 설정 코드를 다시 만듭니다(ACC-04).

- `scripts/backup.ts`는 데이터베이스를 날짜별 JSON으로 받아 최근 7개를 남깁니다(ACC-08).
- `npm run rules:deploy`는 `database.rules.json`이 모듈 규칙 조각에서 만든 최신 파일인지 확인한 뒤 `scripts/deploy-rules.ts`로 보안 규칙을 배포합니다. `firebase login` 없이 서비스 계정으로 배포합니다. `scripts/set-min-protocol.ts`는 방 입장 최소 버전을 올립니다(OPS-13).
- 보안 규칙은 우편, 확성기, 서버 조정값을 앱이 쓰지 못하게 막으므로 이 값은 관리 SDK를 쓰는 스크립트로만 바꿉니다. 버그 제보도 본인 말고는 스크립트만 읽습니다.
