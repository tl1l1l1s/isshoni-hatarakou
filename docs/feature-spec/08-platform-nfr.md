## 8. 플랫폼과 비기능 요구사항

이 장은 앱이 지켜야 할 플랫폼, 성능, 서버, 배포 목표와 지금 앱이 그 목표를 지키는 방법을 정리합니다. 프로그램 전체 구조는 10장에 있고 두 장이 다르면 10장을 따릅니다.

### NFR-01 지원 OS와 기준 플랫폼

| 우선순위 |
|---|
| P0 |

앱은 Windows와 macOS에서 실행되는 데스크톱 앱입니다.

- 지금 출시하는 판은 Windows x64 NSIS 설치 파일 하나입니다(NFR-02, NFR-19).
- macOS 빌드 설정은 Intel과 Apple 실리콘에서 모두 켜지는 universal dmg 하나입니다. 출시 절차는 아직 dmg를 만들지 않고 Mac에서는 개발판으로만 실행해 확인합니다.
- OS마다 다른 동작은 활성 창, 그림 앱 목록, 자동 실행, 스테이지 창 옵션을 맡는 platform adapter 뒤에 두고 `src/main/platform/index.ts` 한 파일만 `process.platform`을 읽습니다(10.8.1). Mac adapter는 아직 최소 구현입니다.
- CI는 Windows에서 네이티브 모듈 `get-windows` 빌드와 NSIS 패키징을 확인하고 macOS에서 활성 창 도우미 실행 파일이 받아지는지 확인합니다(10.10.2).
- 휴대폰과 태블릿용 앱은 없고 폰 자동화 앱이 보내는 신호를 받는 연동만 있습니다(3장 FOC-09).

### NFR-02 설치 파일과 첫 실행

| 우선순위 |
|---|
| P0 |

친구는 설치 파일 하나를 실행하고 설정 코드 한 줄을 넣으면 앱을 쓸 수 있습니다.

- Windows 설치 파일은 사용자 계정에 설치하는 one-click NSIS 설치 파일 `isshoni-hatarakou-Setup-버전.exe`이고 공개 저장소의 GitHub Releases에서 받습니다. 설치 파일에는 코드 서명이 없습니다.
- 설치 파일의 NSIS GUID와 데이터 폴더 이름을 고정해서 앱 이름이나 appId를 바꿔도 같은 앱으로 덮어 설치되고 설정과 로그인이 남습니다(ADR 0024).
- 첫 실행 화면은 설정 코드 입력 창입니다. 선물하는 사람이 `scripts/create-account.ts`로 친구 계정을 만들면 설정 코드 한 줄이 나오고 친구는 이 코드를 넣어 로그인합니다. 창을 닫으면 다시 열리고 앱 끝내기는 트레이 메뉴에 있습니다.
- 로그인 상태는 Firebase JS SDK가 데이터 폴더의 IndexedDB에 남기므로 다시 시작하거나 다시 설치해도 유지됩니다.
- 설정 일반 탭의 [컴퓨터 켤 때 자동 실행]은 OS 로그인 항목에 앱을 등록하고 켤 때마다 사용자가 OS에서 끈 값을 읽어 체크 상자를 맞춥니다(2장 SET-01). 앱은 한 PC에서 하나만 실행되고 다시 실행하면 숨긴 캐릭터를 다시 띄웁니다.

### NFR-03 투명 오버레이 창

| 우선순위 |
|---|
| P0 |

캐릭터는 배경 없이 바탕화면과 다른 프로그램 위에 떠 있고 캐릭터 밖의 클릭은 뒤에 있는 프로그램이 받습니다.

- 스테이지 창은 테두리와 그림자가 없는 투명 창이고 `screen-saver` 단계의 항상 위에 있습니다. 키보드 포커스를 받지 않고 Windows에서는 작업 표시줄에 나타나지 않으며 Mac에서는 활성화하지 않는 `panel` 창으로 만들고 Dock 아이콘을 숨깁니다.
- 스테이지 크기는 좌석이 차지하는 영역만큼이고 고른 모니터 작업 영역의 아래 가운데에 놓입니다(NFR-08).
- 렌더러는 `data-interactive` 영역이 바뀔 때만 메인 프로세스에 보내고 메인 프로세스는 50밀리초마다 커서 위치를 읽습니다. 커서가 스테이지에서 40픽셀보다 멀면 바로 클릭을 통과시키고 가까우면 그 영역 위에서만 클릭을 받습니다. 마우스 움직임 전달(`setIgnoreMouseEvents`의 `forward`)은 쓰지 않고 숨긴 스테이지는 커서를 읽지 않습니다(10.8.1).
- 설정이나 채팅 같은 패널은 스테이지가 `window.open`으로 여는 별도 창이고 스테이지와 같은 렌더러 프로세스에서 그립니다. 글을 입력하는 패널만 포커스를 받습니다(10.4). 화면을 가로지르는 연출은 연출 동안만 모니터 전체 크기의 효과 창을 열고 끝나면 닫으며 효과 창은 클릭을 언제나 아래로 넘깁니다(10.8.2).
- 트레이 메뉴에는 [보이기/숨기기], [위치 초기화], [종료]가 있고 Windows에서는 트레이 아이콘을 왼쪽 클릭해도 보이기와 숨기기가 바뀝니다. 두 OS 모두 `Control+Alt+H`로 화면을 숨기거나 다시 띄웁니다.

### NFR-04 화면 공유와 녹화 프로그램 대응

| 우선순위 |
|---|
| P1 |

앱을 켠 채 화면을 공유하거나 녹화해도 공유 영상이 검게 가려지거나 깜빡이지 않아야 합니다.

- 스테이지가 좌석 영역 크기라서 화면 전체를 덮는 창은 연출 동안 잠깐 여는 효과 창뿐입니다(NFR-03).
- 설정 화면 탭의 [영상 겹침 우회]는 기본값이 꺼짐이고 켜면 Windows에서 스테이지 불투명도를 252/255로 낮춥니다. Chromium은 불투명도가 255보다 낮은 창을 아래 창을 가리는 창으로 세지 않습니다. 켜는 즉시 적용되고 GPU 합성이 꺼져 있으면 건너뛰며 Mac에서는 아무것도 바꾸지 않습니다.
- 이 설정 아래에는 화면 공유 영상이 검어지거나 깜빡일 때만 켜라는 안내가 있고 진단 요약의 스테이지 줄에 켜져 있는지 적힙니다(NFR-21).
- 투명 창이 검게 그려지는 PC에서는 데이터 폴더에 `no-gpu` 파일을 두면 앱이 하드웨어 가속을 끄고 켜집니다. 이 항목은 설정 화면에 없습니다.
- 화면 공유에서 캐릭터만 숨기는 설정은 아직 만들지 않았습니다.

### NFR-05 영상과 겹칠 때 깜빡임과 화면 멈춤

| 우선순위 |
|---|
| P0 |

캐릭터를 영상 위에 띄워도 영상이 깜빡이거나 끊기지 않고 앱이 멈춰도 멈춘 창이 화면에 남지 않아야 합니다.

- 스테이지가 응답하지 않거나(`unresponsive`) 렌더러 프로세스가 비정상으로 끝나면(`render-process-gone`) 메인 프로세스가 스테이지를 닫고 새로 만듭니다. 다시 만들기 전에 1초를 기다리고 1분 안에 되풀이되면 대기 시간을 두 배씩 늘려 최대 30초까지 기다립니다.
- 스테이지를 다시 만들면 같은 프로세스를 쓰는 패널도 닫히지만 트레이 메뉴와 `Control+Alt+H`는 메인 프로세스가 처리하므로 계속 동작합니다.
- 그림을 64KB 안으로 줄이는 작업은 Web Worker에서 해서 스테이지를 그리는 스레드를 막지 않습니다.
- 좌석 그리기는 깨어 있을 때 초당 30프레임, 잠들거나 자리비움일 때 초당 5프레임을 넘지 않고 스테이지를 숨기면 그리지 않습니다. 바뀐 것이 없는 프레임은 다시 그리지 않습니다(NFR-10).
- 1080p 60fps 영상을 캐릭터 아래에서 30분 재생하는 시험은 `docs/checklists/windows-m0.md`에 있고 아직 하지 않았습니다.

### NFR-06 고스트 현상과 접속 상태 정리

| 우선순위 |
|---|
| P0 |

방을 나갔거나 연결이 끊긴 사람의 캐릭터가 다른 사람 화면에 남지 않아야 합니다.

- 멤버 기록 키는 `{uid}_{deviceId}`입니다. 방에 들어가면 앱은 연결이 끊길 때 서버가 이 기록을 지우도록 Firebase `onDisconnect`를 등록하고 다시 연결될 때마다 등록과 기록 쓰기를 다시 합니다. 앱이 갑자기 꺼져도 서버가 이 삭제를 실행합니다.
- 앱은 60초마다 멤버 기록의 `seenAt`을 모아 둔 presence 필드와 함께 씁니다. 다른 앱은 서버 시각 기준으로 `seenAt`이 150초 넘게 바뀌지 않은 멤버를 화면에서 빼고 규칙은 그런 기록을 방 멤버 누구나 지울 수 있게 합니다. 두 값은 `src/shared/constants.ts`에 있고 규칙 빌드도 같은 값을 씁니다.
- 연결된 상태인데 내 기록이 지워졌으면 앱이 기록을 다시 쓰고 방이 지워졌으면 방에서 나갑니다.
- PC가 절전에 들어가면 방에서 나가고 깨어나면 연결이 돌아온 뒤 같은 방에 다시 들어갑니다. 다시 들어가지 못하면 실행 화면에 이유를 띄웁니다.
- 20분 동안 입력이 없으면 자동 자리비움이 되고 그 상태가 6시간 이어지면 1분 전에 안내를 띄운 뒤 방에서 나갑니다. 직접 고른 상태가 있거나 그림 앱이 앞에 있거나 방 주인이면 나가지 않습니다(3장 CHR-13, 5장 ROM-14).

### NFR-07 해상도와 화면 배율

| 우선순위 |
|---|
| P0 |

배율이 다른 화면에서도 캐릭터가 비슷한 크기로 또렷하게 보이고 클릭 영역이 캐릭터와 어긋나지 않아야 합니다.

- 창 크기와 위치는 OS 배율을 반영한 논리 픽셀로 계산하고 캐릭터는 `devicePixelRatio`를 곱한 해상도로 그립니다. 그림을 키울 때는 보간하지 않아서 픽셀 경계가 흐려지지 않습니다.
- 모니터 배율이나 해상도가 바뀌거나 모니터를 연결하거나 뽑으면 마지막 변경 뒤 0.4초가 지나서 스테이지를 다시 놓습니다. 앱을 다시 켜지 않아도 됩니다.
- 배율이 다른 모니터로 옮길 때 Windows가 창 크기를 다시 바꾸는 경우가 있어서 위치를 정한 뒤 다시 읽고 다르면 한 번 더 정합니다.
- 설정 화면 탭의 [캐릭터 크기]는 60%부터 160%까지 10%씩 바꿉니다.
- 배율 100%, 125%, 150%에서 확인하는 항목은 `docs/checklists/windows-m0.md`에 있고 아직 하지 않았습니다.

### NFR-08 멀티 모니터

| 우선순위 |
|---|
| P1 |

사용자가 캐릭터를 띄울 모니터를 고를 수 있고 그 모니터를 뽑아도 캐릭터가 보이지 않는 곳에 남지 않아야 합니다.

- 모니터가 둘 이상이면 설정 화면 탭에 [모니터 1 (주)]처럼 번호와 주 모니터 표시가 붙은 버튼이 나타나고 고른 모니터 작업 영역 아래 가운데에 스테이지가 놓입니다(2장 SET-06).
- 고른 모니터는 `device/display.json`에 저장합니다. 앱은 모니터 ID, 해상도와 위치와 회전과 배율로 만든 지문, 같은 해상도, 주 모니터 순서로 그 모니터를 찾습니다(10.8.1).
- 고른 모니터를 뽑으면 스테이지가 주 모니터로 옮겨 가고 다시 꽂으면 고른 모니터로 돌아옵니다. 캐릭터를 끌어서 다른 모니터로 옮기는 기능은 없습니다.
- 패널 창은 기억한 위치가 지금 작업 영역 안에 보일 때만 그 자리에 뜨고 아니면 화면 가운데에 뜹니다. 설정의 [창 위치 초기화]와 트레이의 [위치 초기화]는 기억한 패널 위치를 지우고 스테이지를 다시 놓습니다(2장 SET-16).

### NFR-09 입력 감지와 OS 권한

| 우선순위 |
|---|
| P0 |

앱은 키 내용을 읽지 않고 입력이 있었는지와 앞에 있는 앱만 알아내며 관리자 권한이나 Mac 개인정보 권한을 요구하지 않습니다.

- 입력 여부는 OS 유휴 시간(`powerMonitor.getSystemIdleTime()`, 초 단위 정수)으로만 압니다. 전역 키보드 후킹 모듈을 쓰지 않으므로 어떤 키를 눌렀는지 모르고 키보드와 마우스도 나누지 않습니다.
- 메인 프로세스는 0.5초마다 앞에 있는 앱의 키, 유휴 초, 그림 앱 여부, 앱을 알 수 없는 이유를 담은 활동 샘플을 만듭니다. manifest의 `uses`에 `platform.activity`를 적은 모듈만 이 샘플을 `ctx.activity`로 받습니다(10.8.1).
- 앞에 있는 앱은 `get-windows`로 읽고 Windows는 실행 파일 이름에 `win:`을 붙이고 Mac은 번들 ID에 `mac:`을 붙여 앱 키를 만듭니다. 창 제목은 읽지 않으므로 Mac의 손쉬운 사용과 화면 기록 권한이 필요 없습니다. 입력이 2초 넘게 없으면 앞에 있는 앱은 5초마다만 다시 묻고 Mac에서는 1.5초에 한 번까지만 묻습니다.
- 관리자 권한으로 실행 중인 창처럼 실행 파일 경로를 읽지 못하면 알 수 없는 앱으로 두고 집중 시간을 쌓지 않으며 진단 요약에 이유를 적습니다.
- 유휴 시간이 1초 이하이면 타이핑 자세이고 그림 앱이 앞에 있으면 4초까지 타이핑 자세로 봅니다. 20분 동안 입력이 없으면 자동 자리비움이 됩니다(3장 CHR-05, CHR-13).

### NFR-10 성능과 자원 사용

| 우선순위 |
|---|
| P0 |

하루 종일 켜 두어도 작업 프로그램이나 게임을 느리게 하지 않는 것이 목표입니다.

- CPU 목표는 4코어 노트북의 10좌석 장면에서 깨어 있을 때 5% 이하이고 모두 잠들었을 때 2% 이하입니다. 메모리 목표는 앱 프로세스 합계 400MB 이하이고 8시간 연속 실행 뒤에도 처음의 1.5배 미만입니다.
- CPU와 메모리 측정 순서는 `docs/checklists/windows-m0.md`에 있고 아직 재지 않았습니다.
- 좌석 그리기는 깨어 있을 때 초당 30프레임, 잠들거나 자리비움일 때 초당 5프레임까지만 하고 스테이지를 숨기면 멈춥니다. 그리기는 라이브러리 없는 Canvas 2D이고 그림은 내용 해시로 캐시해 모든 좌석이 함께 씁니다.
- 패널 창은 스테이지와 같은 렌더러 프로세스를 쓰므로 창을 열어도 렌더러 프로세스가 늘지 않습니다(10.4). 효과 창의 화면 전체 canvas는 효과가 처음 쓸 때만 만듭니다.
- 메인 프로세스는 숨긴 스테이지의 커서를 읽지 않고 입력이 없을 때 앞에 있는 앱을 덜 자주 묻습니다(NFR-09). 앞 샘플을 아직 만드는 중이면 다음 샘플은 건너뜁니다.

### NFR-11 3D 캐릭터 렌더링

| 우선순위 |
|---|
| P0 |

3D 렌더링은 아직 만들지 않았고 캐릭터는 2D 그림으로 그립니다.

- 진단 요약 `logs/diagnose.txt`는 앱이 준비될 때와 [진단 기록 폴더 열기]를 누를 때 새로 씁니다. 앱 버전, Electron과 OS 버전, 모니터 배치, 스테이지 위치, 영상 겹침 우회, 업데이트 상태, 자동 실행, 더한 그림 앱 수, 코어 설정, 앞 앱을 알 수 없는 이유, 모듈 켜짐과 꺼짐, 모듈마다 `diagnose()`가 돌려준 줄을 담습니다.
- 설정 일반 탭에는 앱 버전과 [진단 기록 폴더 열기] 버튼이 있습니다. 친구는 이 폴더의 파일을 선물하는 사람에게 보냅니다.
- 마이홈 버그제보 탭에서 보낸 글은 앱 버전과 함께 서버에 저장되고 선물하는 사람이 `scripts/ops.ts reports`로 읽습니다(7장 OPS-03).
- 처리하지 않은 예외, 렌더러와 보조 프로세스 종료, 스테이지 응답 없음, 지난 실행의 비정상 종료는 앱이 자동으로 보고합니다. 메인 프로세스가 앱 버전, OS, 켠 뒤 지난 시간, 오류 내용, 집 폴더와 사용자 이름을 가린 최근 로그 50줄로 보고를 만들어 디스코드 웹훅에 올리고 버그 제보 기록에도 `[자동 오류 보고]` 글로 남깁니다(7장 OPS-03). 같은 오류는 실행마다 한 번, 5분에 하나, 하루 20개까지이고 설정 일반 탭의 [오류가 나면 자동으로 알리기]로 끕니다.

### NFR-22 이모지와 글꼴 표시

| 우선순위 |
|---|
| P1 |

글자와 이모지가 Windows와 Mac에서 빈 네모 없이 보여야 합니다.

- 글꼴은 앱에 넣지 않고 OS 글꼴을 씁니다. 글꼴 순서는 system-ui, Segoe UI, Apple SD Gothic Neo, 맑은 고딕, Noto Sans KR이고 그 뒤에 OS별 컬러 이모지 글꼴(Segoe UI Emoji, Apple Color Emoji, Noto Color Emoji)이 옵니다.
- 채팅 이모티콘은 👍, 👏, 😂 같은 기본 이모지 12개이고 모두 Windows 10 기본 이모지 글꼴에도 있는 이모지입니다.
- 이모지 그림을 앱에 넣지 않으므로 이모지 모양은 OS마다 다릅니다.

### NFR-23 에셋 출처와 이용 조건

| 우선순위 |
|---|
| P0 |

앱에 들어가는 그림과 소리는 모두 직접 만든 것이고 출처를 에셋 목록에 기록합니다.

- 저장소에는 그림 파일과 소리 파일이 없습니다. 기본 몸과 책상은 코드로 그린 자체 제작 그림이고 `src/modules/wardrobe/assets.json`에 id, 출처 파일, `license`를 적습니다.
- 채팅 알림음과 백색소음은 소리 파일 없이 WebAudio로 합성합니다.
- 트레이 아이콘은 코드로 그린 임시 원이고 그림이 정해지면 그 그림으로 바꿉니다(9.1 결정 7).
- 얼굴 그림과 아이템 그림은 사용자가 직접 넣는 그림이라 앱에 들어 있지 않습니다. 음악도 앱에 넣지 않고 YouTube 삽입 플레이어(`youtube-nocookie.com`)로 재생합니다.

### NFR-24 구현 기술과 우리 기술 선택

| 우선순위 |
|---|
| P0 |

앱은 Electron 44.4.5 데스크톱 앱이고 strict TypeScript 5.9.3으로 씁니다.

- 빌드는 electron-vite로 하고 패키징은 electron-builder로 합니다. 의존성은 2주 넘게 지난 안정판의 정확한 버전으로 고정합니다(ADR 0001).
- 화면은 React 19로 만들고 설정과 저장 데이터와 IPC 인자의 형식 검사는 zod로 합니다. 그리기는 라이브러리 없는 Canvas 2D입니다(NFR-11).
- 서버 연결은 Firebase JS SDK로 하고 운영 스크립트는 firebase-admin을 씁니다. 메인 프로세스가 불러오는 패키지는 electron-updater, electron-log, get-windows, zod입니다.
- 시험은 Vitest, Playwright, Firebase 에뮬레이터로 합니다. 모듈 경계는 ESLint `no-restricted-imports`와 `scripts/check-imports.ts`로 확인합니다(10.11).

### NFR-25 그림 앱 사용 중 펜 입력 보호

| 우선순위 |
|---|
| P1 |

그림 앱으로 펜을 쓰는 동안 앱 때문에 펜 선이 끊기거나 직선이 되지 않아야 합니다.

- 클릭 통과에 마우스 움직임 전달(`forward`)을 쓰지 않고 전역 입력 훅도 쓰지 않습니다. 그림 앱이 앞에 있어도 클릭 통과는 같게 동작해서 캐릭터 위에서만 클릭을 받고 투명한 부분의 펜 입력은 그림 앱으로 갑니다(NFR-03).
- Windows 기본 그림 앱 목록은 실행 파일 이름 17개입니다(Clip Studio Paint, Photoshop, Illustrator, SAI, SAI2, Krita, FireAlpaca, MediBang Paint Pro, 그림판, Paint.NET, Aseprite, Sketchbook, ArtRage, Animate, Blender, ZBrush, CorelDRAW). Mac에는 기본 목록이 없습니다.
- 사용자는 설정 일반 탭의 [직전에 쓴 앱을 그림 앱으로 넣기]로 그림 앱을 50개까지 더하고 목록은 `device/pen-apps.json`에 저장됩니다.
- 그림 앱이 앞에 있으면 마지막 입력 뒤 4초까지 타이핑 자세로 보고(평소 1초) 자동 퇴장도 하지 않습니다(3장 CHR-12).
- 펜 태블릿으로 30분 그리는 시험은 `docs/checklists/windows-m0.md`에 있고 아직 하지 않았습니다.
